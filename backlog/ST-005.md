## Story
As a story-time maintainer, I want setup to select automatic synchronization for supported trackers, so that story changes publish without a separate synchronization decision.

## Acceptance Criteria
- [ ] Given a new GitHub, Gitea, or Azure DevOps setup, when the setup skill writes settings without a sync override, then it explicitly writes auto.
- [ ] Given an existing explicit sync policy or a files, Jira, or Linear tracker, when setup runs without an owner-requested change, then it preserves the explicit policy or uses off for a tracker without sync.
- [ ] Given this repository, when the real CLI reads configuration, then it selects GitHub with auto and preserves Rust verification commands and all Ready and Done rules.

## Out of Scope
Convert the existing Node CLI, change omitted-sync runtime compatibility defaults, change branch protections, remove historical GitHub links, or change Cartographer admission.

## Test Plan
- Run the real repository CLI with config --json and assert GitHub/auto.
- Check the setup skill and native Gitea setup reference with a Rust contract test; verify explicit auto settings through the real init/config CLI path.
- Run Rust policy unit and repository contract tests, including preservation of Rust test commands and Ready/Done rules.
- Run npm test and the required PR checks.
- Read the settings from the exact merged default-branch revision.
