## Story
As a maintainer, I want native story stats to read every updated date Node reads, so that the stale list matches Node for hand-written dates.

## Acceptance Criteria
- [x] Given a story whose updated value is 2026/11/14 or Nov 14 2026, when native story stats runs with and without --json, then its stdout and exit code equal the Node CLI output, verified by a case in native/story-push/tests/stats_contract.rs

## Notes
Source: ST-054 (PR #157). Native date_parse handles only the ECMAScript ISO format; forms that only V8's legacy fallback parser accepts read as NaN. Every real `updated` value is YYYY-MM-DD today.

## Evidence
- Red 606cbc9: the unit table failed with 215 differences, each native NaN where Node gave a number; `legacy_date_forms_match_node` failed with native `Stale: none` against Node `Stale: ST-006, ST-007, ST-008, ST-009, ST-010, ST-011`.
- Green d875d75: `stats.rs` ports V8's DateParser (ISO pass, then the legacy fallback with V8's keyword table and day, time, and zone composers). A table of 190 strings holds Node 24 `Date.parse` values under TZ=UTC and Etc/GMT+6.
- `tests/stats_contract.rs::legacy_date_forms_match_node` compares Node and native (PATH=/nonexistent) for `2026/11/14`, `Nov 14 2026`, and 15 other forms, with and without `--json`, at four `--stale-days` values and four time zones.
- A 60,000-string random fuzz against Node in three zones gave 0 differences (harness not committed). `local_offset_ms` now clamps wall times outside chrono's range, which fixed year-275760 local dates.
- Real backlog: stats text and `--json` identical to Node, 2 compared, 0 differing.
- Checks: `cargo fmt --check` ok; `cargo clippy --locked --all-targets -- -D warnings` ok; `cargo test --locked` 300 passed, 0 failed; `npm test` 461/461; `scripts/story-policy.rs` 12 passed; `test/story-policy-contract.rs` 11 passed.
- Review follow-up (Jev concern fuzz_uncommitted): c5f9b18 adds `stats::date_fuzz::seeded_strings_parse_as_node_does`, 20,000 seeded strings compared with one Node process under TZ=UTC and Etc/GMT+6; 0 differ, 0.18 s. Changing `cdt` to Zone(-6) made it fail with `28 of 40000 differ` (reverted).
