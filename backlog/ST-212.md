## Story
As a maintainer, I want every audit-log assertion in tests/mcp_http.rs to hold when the stderr reader thread receives a line after the HTTP answer, so that native-push neither fails at random on a correct server nor passes when a refused request wrongly ran a tool.

## Acceptance Criteria
- [x] Given a delay injected in the test harness's stderr reader thread, when cargo test --locked --test mcp_http runs, then every test that reads the audit log passes, where before the fix the positive checks fail (for example left 0, right 1 at the one-tool-call count, and the missing linker line)
- [x] Given a delayed reader and a tool call that ran before a no-tool-ran check (an injected wrong run), when that check runs, then it fails, where before the fix it passed
- [x] Given no injected delay, when cargo test --locked runs in native/story-push, then all tests pass, with no assertion weakened and no server code changed

## Evidence
- Criterion 1: PR #489 merged to main as a4072170c62b2e83cfd2ea15f3214413fe3b545c, whose tree is identical to the CI-tested head b9e71a4 (all 10 checks green, including native-push). With a temporary 300 ms sleep in the reader thread before `sink.lock().unwrap().push(line)`, the code before the fix failed `a_marked_client_gives_its_token_in_the_path_and_no_other_client_can` at the one-tool-call count (left 0, right 1), and with that count removed it failed the "linker" check ("the audit line names the client"); with the fix all 9 mcp_http tests passed under the same delay.
- Criterion 2: with the same delay, a real tool call injected just before each check: before the fix the 401 test's "no tool ran", the path test's "no refused request ran a tool" (old code given the count wait to reach it) and the -32020 test's "a refused request runs no tool" all passed, missing the run; with `Http::audit_settled` each failed ("no tool ran"; left 2, right 1; left 2, right 1).
- Criterion 3: without the delay, `cargo test --locked` in native/story-push passed 673/673 on the fix, 684/684 after merging #480, and 709/709 on b9e71a4; `cargo test --locked --test mcp_http` 9/9 three runs in a row; fmt and clippy -D warnings clean. The PR diff touches only backlog/ST-212.md and native/story-push/tests/mcp_http.rs: no server code, and every assertion keeps its expected value and message.
- DoD: Stories line on PR #489; test-only change, so no installed CLI or skill path is affected; npm test 457/457 and both story-policy Rust suites passed.

## Steps to Reproduce
1. In `native/story-push/tests/mcp_http.rs`, add a short sleep in the stderr reader thread before it pushes each line into `log`.
2. Run `cargo test --locked --test mcp_http` in `native/story-push`.

## Expected
Every audit assertion waits for the lines it depends on: positive checks pass, and a check that no tool ran would still see a tool that wrongly ran.

## Actual
`a_marked_client_gives_its_token_in_the_path_and_no_other_client_can` fails with left 0, right 1 at the one-tool-call count, and its "linker" log check can fail. The "no tool ran" checks read the log before late lines arrive, so they pass even when a tool ran.

## Out of Scope
- Server code and the audit line format.
- Audit reads already guarded by `audit_when` (ST-159, PR #480).

## Notes
- Source: PR #480 (commit a41ffcf) fixed the baseline in `a_header_that_does_not_match_the_body_gets_minus_32020` and queued the other unguarded reads as a follow-up. Same race as ST-159.
- Unguarded reads at a41ffcf: line ~306 (`no tool ran`), ~347 (one tool call ran), ~380-384 (no refused request ran a tool), ~385-391 (token absent, "linker" named), ~574-578 (a refused request runs no tool).
- Approach: positive checks wait with `audit_when`; "nothing ran" checks send a known-good sentinel call after the refusals and wait for its line. The server writes each line before it answers and the reader keeps stderr's order, so every earlier line has arrived.
