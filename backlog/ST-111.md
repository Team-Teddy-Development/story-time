## Story
As a coding agent operator, I want an MCP client to list, show, lint, and read config for an allowlisted repository, so that agents use story data without shell commands.

## Acceptance Criteria
- [x] Given a fixture repository passed as --root, when a client calls story_list, story_show, story_lint and story_config, then each result matches its outputSchema and agrees with story list --json, story show --json and story lint --json on the same fixture, verified by a native/story-push protocol test
- [x] Given more than 50 stories, when story_list pages with limit and cursor, then every id appears once in CLI order, and a cursor reused with a different filter returns invalid_cursor, verified by a native/story-push protocol test
- [x] Given a client that sends 2026-07-28 _meta and a client that sends initialize 2025-11-25, when each calls tools/list and tools/call, then both succeed, an unknown version returns -32022 with supported, and missing _meta returns -32602, verified by a native/story-push protocol test
- [x] Given a repository key that is not allowlisted, an invalid id, a backlog directory linked outside the root, malformed JSON, or a line over 1 MiB, when a read tool is called, then the response carries the contracted error code and a byte snapshot of the fixture tree is unchanged, verified by a native/story-push protocol test
- [x] Given fake token values in GH_TOKEN, GITEA_TOKEN and .story-time/.*.env and a story body containing a ghp_ value, when any read tool runs, then no output or stderr contains a fake value, the story shows [redacted], and redactions is at least 1, verified by a native/story-push protocol test
- [x] Given the installed story binary, when Claude Code and Codex each register story mcp --root <fixture> over stdio and list the stories, then the output matches the fixture and the protocol version each client used is recorded in the story Evidence

## Evidence
All tests are in `native/story-push/tests/mcp_protocol.rs`.
- Criterion 1: `read_tools_match_their_output_schemas_and_agree_with_the_cli` validates each result against its `tools/list` outputSchema and compares it with `story config/list/show/lint --json` on the same fixture (ids, fields, file sha256, frontmatter and sections, lint findings and counts).
- Criterion 2: `story_list_pages_every_id_once_and_refuses_a_cursor_with_another_filter` pages 120 stories in 3 pages of 50 in CLI order with each id once; a cursor reused with another status filter and a forged cursor return `invalid_cursor`; `limit: 101` returns `invalid_argument` at `/limit`.
- Criterion 3: `modern_and_legacy_clients_both_work_and_version_faults_use_their_codes` covers a 2026-07-28 client (server/discover, tools/list, tools/call) and an initialize 2025-11-25 client; an unknown version returns -32022 with `supported`; missing `_meta` returns -32602.
- Criterion 4: `refused_reads_carry_their_error_codes_and_change_no_file` covers `repository_not_allowed`, `invalid_story_id`, `path_outside_repository` (symlinked backlog and story file), -32700 for malformed JSON, and -32600 for a line over 1 MiB; a byte-and-mode snapshot of the fixture tree is unchanged.
- Criterion 5: `no_output_carries_a_fake_token_and_a_pasted_token_is_redacted` sets fake GH_TOKEN, GITEA_TOKEN and `.story-time/.*.env` values; no fake value appears in any stdout or stderr, the story shows `[redacted]`, and `redactions` is 3.
- Criterion 6: on installed release 2fcb0405, both clients registered `story mcp --root <fixture>` over stdio through a logging wrapper and listed FX-001 Alpha story, FX-002 Beta story and FX-003 Gamma story, matching the fixture.
