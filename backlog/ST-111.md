## Story
As a coding agent operator, I want an MCP client to list, show, lint, and read config for an allowlisted repository, so that agents use story data without shell commands.

## Acceptance Criteria
- [ ] Given a fixture repository passed as --root, when a client calls story_list, story_show, story_lint and story_config, then each result matches its outputSchema and agrees with story list --json, story show --json and story lint --json on the same fixture, verified by a native/story-push protocol test
- [ ] Given more than 50 stories, when story_list pages with limit and cursor, then every id appears once in CLI order, and a cursor reused with a different filter returns invalid_cursor, verified by a native/story-push protocol test
- [ ] Given a client that sends 2026-07-28 _meta and a client that sends initialize 2025-11-25, when each calls tools/list and tools/call, then both succeed, an unknown version returns -32022 with supported, and missing _meta returns -32602, verified by a native/story-push protocol test
- [ ] Given a repository key that is not allowlisted, an invalid id, a backlog directory linked outside the root, malformed JSON, or a line over 1 MiB, when a read tool is called, then the response carries the contracted error code and a byte snapshot of the fixture tree is unchanged, verified by a native/story-push protocol test
- [ ] Given fake token values in GH_TOKEN, GITEA_TOKEN and .story-time/.*.env and a story body containing a ghp_ value, when any read tool runs, then no output or stderr contains a fake value, the story shows [redacted], and redactions is at least 1, verified by a native/story-push protocol test
- [ ] Given the installed story binary, when Claude Code and Codex each register story mcp --root <fixture> over stdio and list the stories, then the output matches the fixture and the protocol version each client used is recorded in the story Evidence
