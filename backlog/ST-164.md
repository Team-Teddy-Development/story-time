## Story
As a maintainer reading a story-sync run, I want the 'no pull request' line to give the number of cards the run mirrored, and a failed git read to fail the run, so that the report matches what the tracker received

## Acceptance Criteria
- [ ] Given a push with no pull request that changes three cards, of which one has no remote, when `story sync-merge` runs, then the report line reads 'no pull request for <sha>; mirrored 2 cards' and the card with no remote is listed as skipped with reason unlinked
- [ ] Given a push with no pull request that changes one linked card, when `story sync-merge` runs, then the report line reads 'mirrored 1 card'
- [ ] Given a push with no pull request for which the git diff of that commit fails, when `story sync-merge --json` runs, then the report lists a retryable failure for that commit and the command exits 1

## Notes
- Source: EGM drift report on `docs/designs/merge-sync-design.md`, run 2026-11-16 as the trial for a design-deviation brief. Finding DR-09. A second code read at `f3a9dbd` confirmed it. No test was run; write the failing test first.
- Design: `docs/designs/merge-sync-design.md` lines 245-248 (CUJ 4, "mirrored 1 card"), 777-778, and 787 ("A failed `git` subprocess is a retryable failure").
- Code: the count is the number of card paths in `git diff <sha>^1 <sha>`, taken before any mirror runs, so cards that are deleted, unlinked, or failed are counted. A failure of that `git diff` becomes 0 through `.unwrap_or(0)` (`native/story-push/src/sync_merge.rs:335-357`).
- If the owner prefers the count of changed cards, amend the design text and close this story with that amendment; the swallowed `git` failure stays a defect.
- Related: ST-151.
