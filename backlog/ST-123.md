## Story
As a story-time operator, I want VictoriaMetrics to keep story_time_ metrics, so that story-time metrics are not dropped at scrape time.

## Acceptance Criteria
- [ ] Given the coffee-apps drip VictoriaMetrics scrape config, when the keep regex at k8s/drip/10-victoriametrics.yaml includes story_time_ and Argo has synced it, then a story_time_ metric sent through the Xanthos gateway is queryable in VictoriaMetrics, verified by a read-only query recorded in the story Evidence

## Notes
Source: ST-122 spike. The change lives in the coffee-apps repository (team-teddy/coffee-apps on Gitea) and reaches the cluster through Argo CD, so it is a deploy: it needs the owner's go-ahead and goes through coffee-cluster-mcp. ST-009's live acceptance depends on it.

## Evidence
- Change: coffee-apps PR #304 (http://192.168.1.56:30003/team-teddy/coffee-apps/pulls/304) adds `story_time_.+` to the `otel-collector` scrape keep regex; merged at e4a8167. Argo CD `drip-observability` reported revision e4a8167 Synced Healthy about 240 s after the merge; the live ConfigMap `victoriametrics-scrape` holds the new regex.
- Gateway path: `telemetry-smoke` job `metrics` (run 43744962959, branch chore/ST-123-metrics-smoke) posted `story_time_smoke` to https://xanthos.teamteddy.net/v1/metrics, HTTP 200. The gateway log shows `POST /v1/metrics 200` for that run, and the collector exporter `:8889/metrics` holds `story_time_smoke{job="story-time",run_id="43744962959",service_name="story-time"} 1`.
- Criterion not met: VictoriaMetrics returns no `story_time_` series. Cause: its `otel-collector` scrape target has been down for 7+ days because the exporter output (56,555,549 bytes, 124,761 series, 106,046 of them `lb0200_duration_milliseconds_bucket`) exceeds the 16 MiB `maxScrapeSize`. No collector metric reaches VictoriaMetrics. Filed as coffee-apps issue #305 (http://192.168.1.56:30003/team-teddy/coffee-apps/issues/305) with the proposed fix (`metrics_expiration` on the `spanmetrics` connector).
- Handoff: after #305 is fixed, run `gh workflow run telemetry-smoke.yml --repo Team-Teddy-Development/story-time --ref main`, then query VictoriaMetrics `story_time_smoke{run_id="<run id>"}` (read-only port-forward to `svc/victoriametrics` in `drip`). A non-empty result meets the criterion.
