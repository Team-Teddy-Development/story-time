## Story
As a story-time maintainer, I want compiled contract tests to use their source checkout, so that running them from another directory cannot test stale repository files.

## Acceptance Criteria
- [x] Given a contract binary compiled in the repair checkout, when it runs from an unrelated directory, then all repository contract assertions still inspect the repair checkout and pass.
- [x] Given a contract binary compiled in the repair checkout, when it runs from the stale shared anchor, then its results match execution from the repair checkout without modifying the anchor.
- [x] Given the seven owner-named error-sentinel fingerprints, when repair evidence is recorded, then each has its actual cause, test or operational evidence, and a truthful fixed, corrected, or filed disposition rather than a session-task-only closure.

## Steps to Reproduce
Compile `test/story-policy-contract.rs` in a current checkout, then run its binary from the stale shared anchor or an unrelated directory. The tests resolve fixtures, Rust source, and retained CLI paths through the caller's current directory.

## Expected
Tests inspect the checkout containing their compiled source regardless of runtime working directory. Disposable story fixtures remain isolated.

## Actual
Repository contract checks read stale or missing files and fail before testing their intended contracts.

## Out of Scope
Change tracker sync policy, weaken assertions or readiness rules, implement Neo4j, widen the Gitea-only Pi Git tool's host allowlist, or rewrite retained Node application logic.
