## Story
As a hosted story MCP client, I want the story MCP to run at storytime.teamteddy.net on the coffee cluster, so that I can read stories of the registered repositories from any machine.

## Acceptance Criteria
- [x] Given the image deployed with cc_deploy and reported Synced and Healthy, when curl requests https://storytime.teamteddy.net/healthz, then it returns 200
- [x] Given the deployed server, when a client with a read token calls story_show VC-109 at https://storytime.teamteddy.net/mcp, then the story returns with sha256, repository, sha, and fetched_at, and the same call without a token returns 401
- [x] Given the deployed server, when story_repos runs, then it lists varsity-core and varsity-web, each with a sha and fetched_at
- [ ] Given an upstream commit to a registered repository, when story_show runs after the TTL, then the response carries the new sha
- [ ] Given the pod, when kubectl exec runs curl -sI https://api.github.com in the story container, then the response status is 200

## Out of Scope
- Server code. ST-130 delivers it.
- The graph, write, and comment checks (ST-137).

## Test Plan
- Affected: Gitea `team-teddy/coffee-apps` (`argocd/story-time.yaml`, `k8s/story-time/`), and `cc_deploy` and `cc_status` of coffee-cluster-mcp. No `story` command changes.
- Build and push the image with `docs/runbooks/story-time-image.md`.
- `cc_deploy(app: "story-time", file: "k8s/story-time/30-deployment.yaml", image: "192.168.1.51:30500/story-time", tag)`, then `cc_status` reports Synced and Healthy.
- Run each criterion's command against `https://storytime.teamteddy.net`.

Deploy (2026-11-16), 1 of 5 criteria met:
- The owner made the GitHub App `story-time-mcp` (App ID 5777016, owner Team-Teddy-Development; the name `storytime` is reserved for an account). It is installed on Varsity-Engine for `varsity-core`, `varsity-web`, and `varsity-mcp`. The registry serves all three (`VM` for `varsity-mcp`).
- The owner ran `scripts/provision-story-time-secrets.sh` (3 Vault entries), merged coffee-apps PR 307 (`0c3da48`), and registered `argocd/story-time.yaml`.
- `cc_deploy(story-time, k8s/story-time/30-deployment.yaml, 192.168.1.51:30500/story-time, 75581d6-amd64)` returned `idempotent: true`, `Synced`, `Healthy`. Pod `story-time-766b5f766f-xh4p8` is 2/2 Ready with 0 restarts; ExternalSecret `story-time-credentials` is `SecretSynced`.
- Criterion 1, not met: `storytime.teamteddy.net` has no DNS record (`curl` exit 6). Through the ingress address (`curl -H "Host: storytime.teamteddy.net" http://192.168.1.200/healthz`) the answer is 200. The tunnel already routes `*.teamteddy.net`; the owner must add the Cloudflare DNS record.
- Criterion 2, not met at the public URL for the same reason. Through the ingress address: `story_show {"id":"VC-109","repository":"varsity-core"}` returned sha256 `376bd72b…46e56`, repository `varsity-core`, sha `1aec156b…`, fetched_at `2026-11-16T01:18:15.960Z`; `/mcp` without a token returned 401. On a server with several repositories the call must name `repository`.
- Criterion 3, met: `story_repos` listed `varsity-core` `1aec156bab`, `varsity-web` `d2d4d7926c`, `varsity-mcp` `487d50321b`, each `ready` with a fetched_at. Each sha equals `gh api repos/Varsity-Engine/<name>/commits/main`.
- Criterion 4, not met: no upstream commit was seen after the deploy.
- Criterion 5, not met: the image has no `curl`, and `story mcp probe --url https://api.github.com` in the pod returned `no answer` 4 of 4 times. Cause: one CoreDNS replica answers SERVFAIL for external names (`Team-Teddy-Development/coffee-cluster-talos` issue 52). The first clone of all three repositories did succeed, so egress to GitHub works when the name resolves. Later fetches fail part of the time with `Could not resolve host: github.com`; the server then serves its last good clone.

Public checks (2026-11-16), 3 of 5 criteria met:

- Criterion 1, met: after `cc_deploy` reported Synced and Healthy, `curl -s -o /dev/null -w '%{http_code}' https://storytime.teamteddy.net/healthz` printed 200 (`/readyz` also 200).
