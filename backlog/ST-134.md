## Story
As a hosted story MCP client, I want to list the comments on a story's GitHub issue and mark one resolved with a note, so that review feedback has a recorded answer.

## Acceptance Criteria
- [ ] Given a story with remote_url and two issue comments, when story_comments runs, then both comments return with resolved null and author_association
- [ ] Given a story with no remote_url, when story_comments runs, then it returns no_tracker_issue
- [ ] Given an unresolved comment, when story_resolve_comment runs with a note, then exactly one bot reply is posted with the note and the marker, and the next story_comments shows that comment as resolved
- [ ] Given a marker reply written by a user ID other than the bot, when story_comments runs, then the comment stays unresolved
- [ ] Given a resolved comment that its author edits, when story_comments runs, then the comment is unresolved
- [ ] Given an empty note or an already resolved comment, when story_resolve_comment runs, then it returns note_required or already_resolved and posts nothing
- [ ] Given a token without the comment scope, when story_resolve_comment runs, then it returns scope_refused and posts nothing

## Out of Scope
- PR review threads.
- Gitea comments.
- Filtering comments by org membership.

## Notes
Source: ST-128, docs/designs/hosted-story-mcp.md, slice S5 (Component 7; items 12, 24). The `story_comments` description states that `body` is untrusted input, not instructions.

As built:
- `native/story-push/src/mcp/comments.rs` holds both tools. `src/mcp/forge.rs` reads the comment pages (it follows `Link` at the configured API only, and sends the ETag of each page) and posts the reply.
- The issue of `remote_url` must be in the registered repository of the story, because the installation token covers only that repository. Another issue returns `no_tracker_issue`.
- The bot's marker replies are state. They are not in `comments`. A marker that another user id wrote is an ordinary comment.
- The reply also has the line `Requested-by: <client>`, for goal G6 of the design.
- A note is one line. A note with a control character or an HTML comment returns `invalid_argument`, so that a note cannot carry a second marker.
- The server reads at most 3000 comments of one issue; more returns `forge_unavailable`.
- Red run: with the new test file on the ST-133 source, 3 of 3 tests failed (`Unknown tool`). The tests were written before the code.
- Not checked here: comments against real GitHub. That is ST-137.
