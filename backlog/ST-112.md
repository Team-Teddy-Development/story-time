## Story
As a coding agent operator, I want approved MCP writes that follow lifecycle rules and return audit evidence, so that agents change stories safely without shell commands.

## Acceptance Criteria
- [ ] Given a server started without --write, when a client lists tools or calls a write tool, then no write tool is listed and the call returns -32602, verified by a native/story-push protocol test
- [ ] Given the current sha256, when story_update sets fields, then the file equals what story set produces apart from the date and the result carries the before and after hashes, the changelog line, and publish.next for the configured sync, verified by a native/story-push protocol test
- [ ] Given a stale sha256, a retry of an applied update, another process holding the repository lock, status=ready with lint errors, or a protected field such as remote, remote_url, id or created, when story_update runs, then the result is conflict, already_applied with no second changelog line, lock_held, lifecycle_refused with findings, or field_not_writable respectively, with no unintended change, verified by a native/story-push protocol test
- [ ] Given story_note with a stale hash, when it runs, then the result is conflict and the file is unchanged, verified by a native/story-push protocol test
- [ ] Given Claude Code and Codex in writes mode, when a write tool is called, then the client prompts before the call and the write succeeds after approval, recorded in the story Evidence
