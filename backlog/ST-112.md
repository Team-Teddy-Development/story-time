## Story
As a coding agent operator, I want approved MCP writes that follow lifecycle rules and return audit evidence, so that agents change stories safely without shell commands.

## Acceptance Criteria
- [x] Given a server started without --write, when a client lists tools or calls a write tool, then no write tool is listed and the call returns -32602, verified by a native/story-push protocol test
- [x] Given the current sha256, when story_update sets fields, then the file equals what story set produces apart from the date and the result carries the before and after hashes, the changelog line, and publish.next for the configured sync, verified by a native/story-push protocol test
- [x] Given a stale sha256, a retry of an applied update, another process holding the repository lock, status=ready with lint errors, or a protected field such as remote, remote_url, id or created, when story_update runs, then the result is conflict, already_applied with no second changelog line, lock_held, lifecycle_refused with findings, or field_not_writable respectively, with no unintended change, verified by a native/story-push protocol test
- [x] Given story_note with a stale hash, when it runs, then the result is conflict and the file is unchanged, verified by a native/story-push protocol test
- [ ] Given Claude Code and Codex in writes mode, when a write tool is called, then the client prompts before the call and the write succeeds after approval, recorded in the story Evidence

## Evidence
All tests are in `native/story-push/tests/mcp_protocol.rs`.
- Criterion 1: `without_write_no_write_tool_is_listed_and_a_write_call_is_an_unknown_tool`. Without `--write`, only the 4 read tools are listed and both write calls return -32602 with the tree unchanged. With `--write`, the write tools carry readOnlyHint false.
- Criterion 2: `story_update_writes_what_story_set_writes_and_returns_audit_evidence` runs for sync ask, auto and off. The file is byte-equal to `story set` with string, number, array and null values. It checks the before and after hashes, the changelog line, the audit fields, `publish.next` (`story push ST-002`, or null when sync is off), and the output schema.
- Criterion 3: `story_update_refusals_carry_their_codes_and_change_nothing_unintended` covers a stale hash (conflict), each of remote, remote_url, id and created (field_not_writable), a draft moved to ready (lifecycle_refused with findings), a held lock (lock_held), and a retry (already_applied with no second changelog line). The snapshot is unchanged in every case.
- Criterion 4: `story_note_appends_what_story_note_appends_and_a_stale_hash_is_a_conflict` is byte-equal to `story note`, and a stale hash returns conflict with the file unchanged.
- Criterion 5: open until acceptance on the installed release with real clients.
- Red (bbef992): 4 new tests failed with "server closed stdout" because `--write` was refused. Green (c80f8fb): `set::apply`, `note::append` and `adoption_apply::lock_repository` are shared with the CLI, and CLI messages are unchanged.
- Checks on the rebased branch: fmt ok; clippy clean; cargo 71 binaries, 363 passed, 0 failed; npm pass 457 fail 0; story-policy 12 passed; contract 11 passed.
- Real data: on scratch copies of this backlog (115 stories), `set` and `note` through Node, native and MCP gave 0 differences in each comparison.
