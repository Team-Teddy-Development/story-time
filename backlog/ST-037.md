## Story
As a story-time maintainer of a Gitea repository, I want gap-sweep to collect open Gitea issues and story-create to take one over, so that the sweep and issue takeover work outside GitHub.

## Acceptance Criteria
- [x] Given tracker gitea in settings, when gap-sweep collects issues, then skills/gap-sweep/SKILL.md names a read-only Gitea issue listing that excludes story remotes, verified by cargo test --test gap_sweep_skill
- [x] Given an open Gitea issue no story names, when story-create files a story from it and story push runs, then the push updates that issue instead of creating one, verified by a native/story-push Gitea gateway test

## Out of Scope
Trackers other than Gitea and GitHub. Any change to how story push chooses create or update.

## Notes
Source: gap-sweep row 3 on 8f65a07. ST-030 Out of Scope names other trackers (reported as skipped) and ST-029 Out of Scope names adoption for trackers other than GitHub. Gitea repositories on this machine use story-time. Affected skills: gap-sweep, story-create; affected command: story push to Gitea.

## Test Plan
Red: gap_sweep_skill asserts the Gitea collector rule; a gateway test asserts update when remote is set on Gitea. Verify with cargo test --locked in native/story-push.

## Evidence
- Criterion 1: skills/gap-sweep/SKILL.md collects Gitea issues with the native, GET-only `story issues --state open --limit 200 --json`, keeps the `story`-label drop, story-remote drop, and truncation rules, and records `skipped (no signed-in Gitea access)` on failure. The skill contains no curl, `GITEA_TOKEN`, or Authorization text. A first version piped `$GITEA_TOKEN` into curl; Jev judged it a violation of the skill's "never read a token" rule (0.71), so it was replaced.
- `gap_sweep_lists_open_gitea_issues_read_only_and_drops_story_remotes` (tests/gap_sweep_skill.rs): red 8511498 "missing instruction: when `tracker` is `gitea`", then red 7a9cea0 "missing instruction: story issues --state open --limit 200 --json"; green 2bccaec.
- `story issues` (tests/open_issues.rs, 3 tests, real binary vs a loopback fake Gitea): two open issues across two pages with the pull request excluded, only GETs with state=open&type=issues&limit=50, the token absent from stdout and stderr; --limit 1 stops after one request; a github tracker exits non-zero naming `gh issue list`. Red 7a9cea0: no `issues` command.
- Criterion 2: `a_story_that_takes_over_an_open_gitea_issue_updates_it_instead_of_creating_one` (tests/gitea_takeover.rs, dbe6420): after `story set ST-001 remote=7`, push reports action `update` for 7, sends no `POST /issues`, PATCHes the story title, body, and state onto issue 7, keeps the issue's own `team:payments` label, and leaves no `pending_create`. No red: push already plans `update` whenever `remote` is set. Removing the `story set` step makes it fail with `left: "create" right: "update"`.
