## Story
As a story-time maintainer, I want changes linked to our own stories, so that feature work follows the process we distribute.

## Acceptance Criteria
- [ ] Given this repository, when story config runs, then it selects GitHub Issues in Team-Teddy-Development/story-time with sync ask.
- [ ] Given a pull request, when story-link runs, then it rejects absent or invalid story references and accepts existing story files or story-labeled issues.
- [ ] Given new story files, when story-ids runs, then it rejects IDs already on main or added by an older open pull request.
- [ ] Given the mandate checks, when Rust tests run, then valid, invalid, incident, and duplicate-ID cases have passing assertions.

## Out of Scope
Convert the existing story CLI or installer to Rust; redesign story readiness; change owner-review requirements; seed unrelated feature stories.

## Test Plan
- Run the configuration and push dry-run commands against this repository.
- Run the Rust unit tests for strict declaration lines, all references, issue labels, incident behavior, API failures, and duplicate IDs.
- Run the Rust integration tests against the compiled checker and disposable Git histories.
- Run the existing Node regression suite and the new GitHub Actions jobs.
- Require the new check contexts without removing the existing owner-review and test requirements.

## Evidence
- RED: the Rust repository contract test failed before the story workflows existed.
- GREEN: 12 Rust unit tests and 7 integration tests pass; expected rejection paths assert exit code 1 and capture their diagnostics.
- Regression suite: npm test reports 408 passed, 0 failed, 0 skipped.
- story config selects the expected GitHub repository; story push created issue #13.
- Default-branch rollout remains pending the PR and its existing owner-review requirement.
