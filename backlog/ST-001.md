## Story
As a story-time maintainer, I want changes linked to our own stories, so that feature work follows the process we distribute.

## Acceptance Criteria
- [x] Given this repository, when story config runs, then it selects GitHub Issues in Team-Teddy-Development/story-time with sync ask.
- [x] Given a pull request, when story-link runs, then it rejects absent or invalid story references and accepts existing story files or story-labeled issues.
- [x] Given new story files, when story-ids runs, then it rejects IDs already on main or added by an older open pull request.
- [x] Given the mandate checks, when Rust tests run, then valid, invalid, incident, and duplicate-ID cases have passing assertions.

## Out of Scope
Convert the existing story CLI or installer to Rust; redesign story readiness; change owner-review requirements; seed unrelated feature stories.
