## Story
As a story-time operator, I want a client token to read only the orgs and repositories that I name for it, so that a client of one org cannot read the backlog of another org.

## Acceptance Criteria
- [ ] Given a client with orgs = ["varsity"], when it calls story_show, story_list, story_lint, story_graph, or story_comments for a repository of another org, then the server returns repository_not_allowed and the audit line records the refusal
- [ ] Given that client, when it calls story_repos, then the result holds only the repositories it can read
- [ ] Given a client with no orgs and no repositories key, when it calls a read tool, then it reads every repository as today
- [ ] Given a clients file that names an org or a repository that the registry does not hold, when the server starts, then it exits non-zero and names the client and the value

## Out of Scope
- Write and comment limits by prefix. They exist today (`prefixes` in the clients file).
- Sign-in of a person. A client is still a token.

## Notes
Source: owner message on 2026-11-16, "we wont see other devs repos will we?", and the request for multi-org support the same day. Today each client token reads every registered repository; `prefixes` limits only the write and comment scopes (`native/story-push/src/mcp/caller.rs`). With one org that is correct. With several orgs (ST-141) it lets a client of one org read another org.
