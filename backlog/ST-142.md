## Story
As a story-time operator, I want a client token to use only the orgs that I name for it, so that a client of one org cannot read or change the backlog of another org.

## Acceptance Criteria
- [x] Given a client with orgs = ["varsity"], when it calls a tool with a repository of another org, then the server returns repository_not_allowed with the message of an unknown repository, and the audit line records the client and the error code
- [x] Given that client, when it calls story_repos, or story_config with no repository, then the result holds only the repositories of its orgs
- [x] Given a client with no orgs key, when it calls a tool, then it uses every repository as today
- [x] Given a clients file that names an org that the registry does not hold, or names an org when the server has no registry, when the server starts, then it exits non-zero and names the client and the org

## Out of Scope
- A limit below one org (single repositories). Links resolve inside one org, so story_show, story_lint, and story_graph return data of the other repositories of the org. Jev chose the limit by org (0.98).
- Limits of the write and comment scopes by prefix. They exist today (`prefixes` in the clients file).
- Sign-in of a person. A client is still a token.

## Notes
Source: owner message on 2026-11-16, "we wont see other devs repos will we?", and the request for multi-org support the same day. Today each client token reads every registered repository; `prefixes` limits only the write and comment scopes (`native/story-push/src/mcp/caller.rs`). With one org that is correct. With several orgs (ST-141) it lets a client of one org read another org.
