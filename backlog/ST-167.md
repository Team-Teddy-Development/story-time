## Story
As the operator of a local coding-agent loop, I need story selection to distinguish a live execution owner, a terminated owner, and unknown legacy ownership, so the loop can recover abandoned work without duplicate implementation. Implement in the native Story Time CLI beside ranking. Existing status, dependency, readiness, admission, and tracker rules remain authoritative. Do not reset legacy in-progress stories or change Cartographer core. Test plan: real CLI tests for atomic claims across worktrees, process-identity checks, stale-owner recovery, expired-but-live and unknown-owner protection, heartbeat fencing, and preserved partial work.

## Acceptance Criteria
- [ ] Given ranked ready stories with completed dependencies and free configured WIP capacity, when concurrent local agents request the next assignment, then only one valid ownership claim can occupy each slot and the highest-ranked eligible story is returned.
- [ ] Given a recorded assignment whose exact local process identity has terminated, when the coordinator reconciles ownership, then it invalidates the old claim and makes that work recoverable without deleting branches, worktrees, PRs, or changing story acceptance status.
- [ ] Given live ownership, uncertain ownership, or an in-progress story without verified ownership, when selection or recovery runs, then it does not automatically release that work or start a conflicting assignment.
- [ ] Given a replaced or released claim, when its former owner attempts a heartbeat or another ownership operation, then the operation fails without changing the current owner; real CLI regression tests and agent instructions demonstrate the full selection and recovery path.
