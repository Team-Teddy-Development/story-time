## Story
As a client of the hosted story-time MCP, I want the server to try a network step again when the name of the forge does not resolve, so that one bad DNS answer does not fail my read or my edit.

## Acceptance Criteria
- [ ] Given a git fetch that fails 2 times with Could not resolve host and then works, when a client calls story_show, then the call returns the story
- [ ] Given a git fetch that always fails with Could not resolve host, when a client calls story_show, then the answer is repository_unavailable with that reason after 4 tries of the fetch, and no more
- [ ] Given a request to the forge API that fails before the connection is made, when the server sends it, then it sends it again up to 4 times in total, and an answer with an HTTP status is not sent again

## Out of Scope
- The repair of the cluster DNS (coffee-cluster-talos issue 52).
- A retry of a request that got an answer, or of a `git` failure with another cause.

## Notes
Source: the owner, 2026-11-16, from a cloud session: "The Story Time server hit the same github.com DNS failure when it tried to push the story". Cause on the cluster: 1 of the 2 CoreDNS pods (`coredns-64ff8d5d54-fsnpw` on `coffee-cluster-7`) answers SERVFAIL; 174 upstream errors in 10 minutes on 2026-11-16, and 0 on the other pod. Each lookup goes to one of the two, so about 1 of 2 lookups fails. The server did one try for each step: `story_repos` showed `last_error` "Could not resolve host: github.com", and a first clone passed on try 6 of the client.

A DNS failure happens before a connection exists, so no request reached the forge and a second try cannot repeat an effect. That holds for the POST that opens a pull request too. With 4 tries and a failure rate of 1 of 2, about 1 of 16 steps still fails; the repair of the cluster stays necessary.

## Test Plan
- Criteria 1 and 2: `tests/mcp_hosted_workspace.rs`, test `a_fetch_is_tried_again_when_the_forge_name_does_not_resolve`, with a `git` on PATH that fails a set number of fetches with the text of the real failure (red first).
- Criterion 3: unit tests of the retry function in `src/mcp/retry.rs`: a transient failure is tried 4 times, another failure 1 time, a success after 2 failures returns the value.
- Regression: `cargo test --locked`.
