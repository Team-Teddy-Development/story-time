## Story
As a project owner whose agents write through MCP, I want story_update to refuse done unless the story carries acceptance evidence, so that only an accepted story reaches done.

## Acceptance Criteria
- [x] Given a story with an unticked acceptance criterion or no non-empty Evidence section, when story_update sets status=done, then the result is lifecycle_refused with a finding naming what is missing and the file is unchanged, verified by a native/story-push protocol test
- [x] Given a story whose acceptance criteria are all ticked and whose Evidence section is not empty, when story_update sets status=done, then the story is done and the result carries the audit evidence, verified by a native/story-push protocol test

## Notes
Source: ST-006 spike open question; Jev decision 2026-11-14 (jev-1.14.0, owner said 'jev decide'): refuse (0.98). The workflow rule is that only story-accept establishes completion. CLI story set keeps its current behavior; this changes only the MCP story_update tool.
