## Story
As a maintainer, I want the legacy-CLI message to list native commands from the dispatch table itself, so that each new native command changes one line and parallel branches stop conflicting on the message.

## Acceptance Criteria
- [x] Given the native dispatch table, when the binary runs a command that is not native without a legacy CLI, then the message names exactly the commands in the dispatch table, verified by a native/story-push test that compares the message with the table

## Evidence
- Red 2cfc6a0: native/story-push/tests/native_command_message.rs did not compile (`cannot find value NATIVE_COMMANDS in crate story_time_native`).
- Green 8c7aa49: native/story-push/src/lib.rs holds `NATIVE_COMMANDS`, one table of (name, handler) for init, push, adopt, plan, config, show, issues, list, secret, machine, and metrics, and `legacy_required_message()` builds the message from it. main.rs dispatches through one table lookup; the separate plan, machine, and adopt branches and the hand-written message are gone. For today's commands, the old and new stderr are byte-identical (cmp, both exit 1).
- df36777: the test triggers the message with an unknown command instead of `stats`, so it stays valid as more commands become native.
- The test runs the binary with env cleared and PATH=/nonexistent, splits stderr into its two command lists, and asserts each equals the table names in order. With `metrics` dropped from the message builder, the test failed (10 names against 11). 1 passed.
- Checks on main 0b8b4d7: cargo fmt --check clean; clippy -D warnings clean; cargo test --locked 204 passed, 0 failed (41 binaries); npm test 456/456; story-policy.rs 12 passed; story-policy-contract.rs 11 passed.
- Follow-up: ST-077 (test the native-command lists in AGENTS.md and story-time SKILL.md against the table).
