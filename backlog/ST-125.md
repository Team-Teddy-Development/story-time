## Story
As a story-time maintainer, I want the one unexplained split_contract failure explained and fixed, so that a red cargo run always means a real defect.

## Acceptance Criteria
- [x] Given the split_contract Node-versus-native comparison tests, when the cause of the 2026-11-14 single failure is found, then a test that fails without the fix and passes with it is committed, verified by cargo test --test split_contract

## Notes
Source: ST-011 checks on 2026-11-14 (worktree 961df8b3c0601a3bd95239f5a818d4cf, commit cba4c1e rebased on main 3237352). Fingerprint: cargo test -q --locked stopped after 67 binaries with passed=354 failed=1; by cumulative test counts the failing binary was tests/split_contract.rs (3 tests, the 67th binary in run order). The test name and message were not captured, because checks.sh keeps only the result lines. Not reproduced: 4 later full cargo runs, 40 serial runs and 72 runs 12-wide in parallel of split_contract all passed. First step: make checks.sh keep the failing test's output so the next occurrence names the test.

## Findings
Cause: the test fixture, not product code. The failing test was `children_skip_ids_reserved_on_other_branches`. Git 2.56 starts `git maintenance run --auto --quiet --detach` after every `git commit`. The detached child creates `.git/objects/maintenance.lock` and deletes it 1 to 3 ms after the commit returns. The test copies the template right after its last commit, once for the Node run and once for the native run, and compares both trees including `.git`. A copy that catches the lock differs from one that does not ("files differ"), and a lock that vanishes mid-copy makes `copy_tree` panic on ENOENT. strace of one normal run: commit pid exited 11:21:21.899144, daemon unlinked the lock 11:21:21.900269, template copy started 11:21:21.914531. Fix: the fixture git helper passes `-c maintenance.auto=false`, so commits start no background writer. Follow-up: ST-127 (same latent race in `new_contract.rs`, and the leaked base directory).

## Evidence
- Forced interleaving: `strace -f -qq -o /dev/null -e trace=dup -e inject=dup:delay_exit=150000:when=2 <split_contract test binary> children_skip --test-threads=1`. Before the fix: `panicked at tests/split_contract.rs:125:13 ... files differ` (Node tree 309 entries with `.git/objects/maintenance.lock`, native 308). After the fix: `test result: ok. 1 passed` at 100, 150 and 200 ms delays.
- Red: commit e9d74dc adds `fixture_commits_start_no_background_maintenance`; re-run by the coordinator on the e9d74dc test file: `test fixture_commits_start_no_background_maintenance ... FAILED`.
- Green: commit 7d29aa0; `cargo test --locked --test split_contract`: 4 passed, 0 failed (coordinator run). Delegate run: `cargo fmt --check` ok; `cargo clippy --locked --all-targets -- -D warnings` clean; `cargo test --locked` 75 binaries, 388 passed, 0 failed; 30 parallel split_contract runs all ok; `npm test` 457 pass, 0 fail.
