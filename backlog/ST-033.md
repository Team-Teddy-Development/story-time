## Story
As a story-time maintainer, I want the push test helper to handle a child that closes stdin early, so that the Node suite does not fail at random with EPIPE.

## Acceptance Criteria
- [x] Given a test that forces the child process to exit before it reads stdin, when the helper at skills/story-time/scripts/test/cli-push.test.mjs writes its input, then the test reports the child's exit result and no unhandled EPIPE error
- [x] Given a child that exits with a non-zero code, when the helper handles the closed pipe, then the test still fails with that exit code

## Out of Scope
Other test helpers. ST-027's empty-JSON symptom in the same helper.

## Notes
Source: gap-sweep dry run row 3. The helper at skills/story-time/scripts/test/cli-push.test.mjs:32 still calls `child.stdin.end(input ?? '')` with no error handler. ST-027 covers a different symptom. Rust rule: if the regression test is a new test file, kickoff decides whether it can be written in Rust. This story adopts #11; its next push replaces the issue's title and body.

Original issue #11 title: Flaky EPIPE from the stdin helper in cli-push.test.mjs

Original issue #11 body:

> An independent verifier saw one run of the suite on main (1b2a3a5) fail with an EPIPE error from the stdin helper at `skills/story-time/scripts/test/cli-push.test.mjs:32`. Two reruns of each tree passed, so the failure is intermittent.
>
> Likely cause (a guess, not confirmed): the helper writes to the child's stdin after the child has already exited or closed stdin, and the write has no error handler.
>
> Done when a test that forces an early child exit reproduces the EPIPE, and the helper then handles the closed pipe without hiding a real failure.
>
> Found during verification of #10: https://github.com/Team-Teddy-Development/story-time/pull/10#issuecomment-6803556041

## Test Plan
Red: a test forces the child to exit before reading stdin and observes the EPIPE. Green: handle the stdin error in the helper so it reports the child's result. Verify with npm test.

## Evidence
- Reproduced: a parent writing 1 MiB to a child that ran `closeSync(0)` and exited 300 ms later crashed with unhandled EPIPE three times out of three.
- Red 65de29f: the helper moved to skills/story-time/scripts/test/run-cli.mjs (cli-push.test.mjs now calls it); native/story-push/tests/push_test_helper.rs failed both tests with `unhandled EPIPE`.
- Green 4965612: the helper ignores EPIPE on stdin and rejects any other stdin error. Both tests pass three runs in a row: exit 0 reports code 0, exit 3 reports code 3. cargo test --locked 79 passed 0 failed; npm test 426/426; story-policy.rs 12/12; story-policy-contract.rs 11/11; fmt and clippy clean.
