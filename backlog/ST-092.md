## Story
As a maintainer, I want story split to skip IDs that another branch already uses, as story new does, so that two branches that split stories never create the same IDs.

## Acceptance Criteria
- [x] Given a repository whose other branch holds ST-200 and a local backlog that ends at ST-090, when story split creates two children, then their IDs are above ST-200, verified by a native/story-push contract test

## Notes
Source: ST-061 (PR #186) real-data run. Node splitStory and the native port allocate child IDs only from local frontmatter IDs and ignore gitReservedIds, unlike story new. With ST-200 on another branch, both gave ST-088. ST-061 kept Node behavior as its Out of Scope required.

## Evidence
- Red af38aa2: `children_skip_ids_reserved_on_other_branches` failed for `split ST-001 --from two.json`; Node and native both allocated ST-091 where ST-201 was expected (branch `other` holds ST-200).
- Green ee4f738: Node `split-story.mjs` and native `split.rs` take the larger of the highest local ID plus one and the repository's next ID (`repo.nextId` with gitReservedIds in Node, `next_id::next_id` natively), the same source `story new` uses. Outside git both reserve nothing, as `story new` does.
- The contract test copies one git template byte for byte for each run, runs Node and native (PATH holds only git), compares stdout, stderr, exit code, and the full tree with modes including .git, in text and `--json` forms, and asserts ST-201 and ST-202 exist and ST-091 does not. The existing split cases still pass.
- Real data: a clone with 154 refs (highest ST-094); `split ST-007 --from kids.json` gave `ST-007 split into ST-095, ST-096.` in Node and native, trees equal.
- Limit: as with `story new`, reserved IDs come only from fetched refs.
- Checks: `cargo fmt --check` ok; `cargo clippy --locked --all-targets -- -D warnings` ok; `cargo test --locked` 316 passed, 0 failed; `npm test` 461/461; `scripts/story-policy.rs` 12 passed; `test/story-policy-contract.rs` 11 passed.
