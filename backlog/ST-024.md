## Story
As a backlog maintainer, I want readiness lint to distinguish terminal split parents from implementation stories, so that preserved aggregate estimates do not make valid child work appear unready.

## Acceptance Criteria
- [ ] Given a split parent with size13 and child stories within the readiness limit, when lint checks the family, then it preserves the parent estimate without a size readiness error while still rejecting an unsplit size13 story.

## Steps to Reproduce
Run `story lint ST-018 ST-019 ST-021 ST-022 ST-023 --json` after ST-021(size13) is split into ST-022(size5) and ST-023(size8). The parent remains size13 as the original aggregate estimate.

## Expected
Terminal split parents retain their original estimate without a readiness-size error. Unsplit implementation stories with size13 remain unready. Child readiness and dependency warnings remain visible.

## Actual
The command exits1 with `size.small` error for ST-021 despite status split: `Size 13 >= 13: too big to finish in a sprint. Split it.` Active implementation leaves have zero errors. Root cause is applying the implementation-size readiness rule to terminal split records without a status distinction.

## Out of Scope
Do not lower historical estimates, skip actual child readiness checks, change the maximum implementation size, or implement unrelated planning/adoption behavior. Future replacement executable lint logic and tests must be Rust.
