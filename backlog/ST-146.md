## Story
As an owner who connects a cloud client that cannot send a request header, I want a client entry that takes its token in the path /mcp/<token>, so that ChatGPT cloud can use the hosted story-time MCP and my other tokens stay header-only.

## Acceptance Criteria
- [ ] Given a client entry with url_token = true, when a request with no Authorization header posts tools/list to /mcp/<token of that client>, then the answer is HTTP 200 with the tools of the scopes of that client
- [ ] Given a client entry without url_token, when its token is in the path, then the answer is HTTP 401 with the same body and headers as for an unknown token
- [ ] Given the path /mcp/ with an unknown token, an empty token, or one more path segment, when a request posts to it, then the answer is 401 or 404, no tool runs, and no line that the server writes holds a path token
- [ ] Given a clients file in which url_token is not true or false, when the server starts, then it refuses the file and names the entry and the key

## Out of Scope
- An OAuth server.
- The ingress and Cloudflare logs. A URL is written to them; the coffee-apps change that goes with the deploy turns off the ingress access log for `/mcp/` paths. Cloudflare keeps its own records.
- Read limits for each client (ST-142).

## Notes
Source: the owner, 2026-11-16: ChatGPT cloud (web) cannot send a request header to a connector, so it needs the token in the URL. Decision: the path token works only for a client entry that is marked `url_token = true`, so a token made for a header never works in a URL. A marked client can also use the header.

Risk the owner accepted with this request: a URL is not kept as a secret by proxies, logs, and client settings. Use a separate client entry for each path client, with the smallest scopes that it needs, so that it can be revoked alone.

Not verified by this story: that ChatGPT cloud completes its MCP handshake with this server. Only the owner can add the connector there.

## Test Plan
- Criteria 1 to 3: `tests/mcp_http.rs`, test `a_marked_client_gives_its_token_in_the_path_and_no_other_client_can` (red first). It reads the answers and the stderr lines of the server.
- Criterion 4: unit test `url_token_must_be_a_boolean` in `src/mcp/caller.rs`.
- Regression: the other tests of `tests/mcp_http.rs` and `cargo test --locked`.
