## Story
As a hosted story MCP client, I want the server to read stories from every registered repository at storytime.teamteddy.net, so that I can list, show, and lint a story without a local checkout.

## Acceptance Criteria
- [ ] Given a registry with two repositories and a fetch TTL, when story_show runs twice within the TTL, then the second call does not fetch and both responses carry repository, sha, and fetched_at
- [ ] Given an upstream commit after the TTL expires, when story_show runs, then the response carries the new sha
- [ ] Given a branch named in ref, when story_show runs with that ref, then the response holds the story content of that branch
- [ ] Given one repository that the server cannot reach, when story_repos and story_show run, then story_repos reports state unavailable with last_error, story_show returns repository_unavailable, and /readyz returns 200
- [ ] Given a registry that names forge gitea or declares one prefix in two repositories, when the server starts, then it exits with an error that names the entry
- [ ] Given a GitHub App key and a stub token endpoint, when the server fetches a private repository, then the installation token appears only in GIT_CONFIG_VALUE_0 of the git child and in no output
- [ ] Given the image deployed with cc_deploy, when a client with a read token calls story_show VC-109 at https://storytime.teamteddy.net/mcp, then the story returns with content_sha256, and the same call without a token returns 401

## Out of Scope
- Cross-repo lint (ST-131), graph (ST-132), writes (ST-133), comments (ST-134).
- Gitea.
- Creating the GitHub App and the Vault values. They are an owner handoff, and the cluster criterion waits for them.

## Test Plan
- Affected commands: `story mcp --http --registry`, tools `story_repos`, `story_show`, `story_list`, `story_lint`, `story_config`.
- `cargo test --locked --manifest-path native/story-push/Cargo.toml --test mcp_hosted_workspace` covers the TTL, sha, ref, unavailable-repository, and registry criteria against `file://` bare repositories and a local GitHub stub (`--github-api-url`).
- `cargo test --locked --manifest-path native/story-push/Cargo.toml forge_auth` covers the token criterion.
- `docker build -f native/story-push/Dockerfile .` succeeds in CI.
- Cluster: after `cc_deploy` reports Synced and Healthy, `curl -s https://storytime.teamteddy.net/healthz` returns 200 and the `story_show VC-109` calls behave as the last criterion states.
- `cargo clippy --manifest-path native/story-push/Cargo.toml --locked --all-targets -- -D warnings` and `cargo fmt --manifest-path native/story-push/Cargo.toml --check` pass.
- The existing contract tests pass unchanged.
