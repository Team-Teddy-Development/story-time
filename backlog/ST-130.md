## Story
As a hosted story MCP client, I want the server to read stories from every registered repository at storytime.teamteddy.net, so that I can list, show, and lint a story without a local checkout.

## Acceptance Criteria
- [x] Given a registry with two repositories and a fetch TTL, when story_show runs twice within the TTL, then the second call does not fetch and both responses carry repository, sha, and fetched_at
- [x] Given an upstream commit after the TTL expires, when story_show runs, then the response carries the new sha
- [x] Given a branch named in ref, when story_show runs with that ref, then the response holds the story content of that branch
- [x] Given one repository that the server cannot reach, when story_repos and story_show run, then story_repos reports state unavailable with last_error, story_show returns repository_unavailable, and /readyz returns 200
- [x] Given a registry that names forge gitea or declares one prefix in two repositories, when the server starts, then it exits with an error that names the entry
- [x] Given a GitHub App key and a stub token endpoint, when the server fetches a private repository, then the installation token appears only in GIT_CONFIG_VALUE_0 of the git child and in no output

## Out of Scope
- Cross-repo lint (ST-131), graph (ST-132), writes (ST-133), comments (ST-134).
- Gitea.
- The cluster deploy, the coffee-apps manifests, and the GitHub App and Vault handoff (ST-136).

## Notes
Source: ST-128, docs/designs/hosted-story-mcp.md, slice S1 (Components 2, 3, 8; items 8, 9, 11, 18, 19, 21, 26 to 28). The manifests land in Gitea `team-teddy/coffee-apps`; deploy only through coffee-cluster-mcp. Owner handoff: GitHub App `storytime` (Contents: read, Metadata: read) installed on both Varsity repositories, and Vault keys `global/infra.story-time.*`.

From ST-131 (2026-11-15): the lint rule `links.undeclared_prefix` (an error for a backlog file whose prefix its repository does not declare) needs the registry, so it belongs to this story. `Redactor.values` also becomes a `RwLock` here, when installation tokens refresh (from ST-129).

Deviations from the design (2026-11-15):
- A read writes `.story-time`, the backlog directory, and `model` of one commit into a directory under `--data` through a temporary git index. The design named `git worktree add` with a sparse checkout. The server keeps the directories of the last 4 commits of each repository; it has no cache of parsed backlogs.
- `forge_auth.rs` holds its own base64 code. No `base64` dependency was added.
- `--data DIR` names the data directory (default `/data`). `--registry` refuses `--root` and `--write`.
- `story_config` takes no `ref`. `story_list`, `story_show`, and `story_lint` take it.
- A repository accepts a story id of each prefix that the registry declares for it, found with the real Varsity repositories (`ST-001` in varsity-core).
- `story mcp probe --url URL` is in this story (design item 27 names it for the probes).
- The tests were written before the code but first ran after it. One case (`ST-001` with the declared prefixes `VC` and `ST`) ran red before its fix.

## Evidence
Source commits `2dca9cc` and `d1f145d`, merged to `main` in PR #304 as merge commit `95df795`. CI on PR #304 passed every check, including the `image` job that builds the container. Each criterion is verified by a test in `native/story-push/tests/mcp_hosted_workspace.rs`, which runs the real `story` binary against `file://` repositories and a local GitHub stub.

| Criterion | Test |
|---|---|
| 1: a second read within the TTL does not fetch; responses carry `repository`, `sha`, `fetched_at` | `a_read_within_the_ttl_does_not_fetch_and_a_read_after_it_sees_the_new_commit` |
| 2: a read after the TTL carries the new `sha` | `a_read_within_the_ttl_does_not_fetch_and_a_read_after_it_sees_the_new_commit` |
| 3: `ref` reads the story content of that branch | `a_named_ref_reads_the_story_of_that_branch` |
| 4: an unreachable repository is `unavailable`, `story_show` returns `repository_unavailable`, `/readyz` returns 200 | `a_repository_that_cannot_be_reached_is_unavailable_and_the_rest_keep_working` |
| 5: forge `gitea` or a repeated prefix stops the server with an error that names the entry | `a_registry_that_names_gitea_or_repeats_a_prefix_is_refused_at_start` |
| 6: the installation token is only in `GIT_CONFIG_VALUE_0` and in no output | `a_private_repository_is_fetched_with_an_installation_token_that_no_output_shows`, and unit test `the_token_is_only_in_the_value_variable_of_the_git_environment` |
