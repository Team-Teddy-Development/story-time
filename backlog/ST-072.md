## Story
As a story-time maintainer, I want native story push to accept every story file the Node CLI accepts, so that a valid story is never refused by push alone.

## Acceptance Criteria
- [x] Given story files with a colon-space in a frontmatter value, a duplicate frontmatter key, and prose before the first section, when story show and story push --dry-run run on each, then push either plans the story or reports the same error as show, verified by a native/story-push contract test

## Out of Scope
Changing what Node accepts. Rewriting a story file that push did not change.

## Notes
Source: ST-047 implementation report. native/story-push/src/story.rs `parse` (used by push) rejects duplicate keys, preamble text, and `: ` in values, which Node's parseStory accepts; ST-047 added a lenient port in src/show.rs. ST-044 already added `parse_legacy` for adoption. Decide one parser for read paths and keep push's lossless write guard. Epic EP-001.

## Evidence
- Red 06a51af: 4 new tests in native/story-push/tests/push_lenient_contract.rs failed; the dry run stopped with `Unsupported frontmatter value: Fix: login fails` and `Duplicate frontmatter key: title` (exit 1), and push's error text differed from show's for bad quoting.
- Green b0258a7: push reads stories with lenient_story (the parser show and list use) through `parse_noting_drops` and `Js::to_value`, so its errors and exit codes equal show's. A write guard refuses, before any tracker call or file write, a real push whose rewrite would lose text (duplicate keys or sections, prose before the first section, a `sections` or `__proto__` key, or a serialize round trip that changes data). A colon-space title pushes and is written back quoted; a duplicate key or leading prose plans in a dry run and is refused on a real push with the file byte-identical and no tracker call.
- push_lenient_contract compares Node and native show, the dry-run plan, the error cases, and a real push to a stub `gh`, including written bytes. 4 passed. All existing push tests pass.
- Real data: Node and native `push --all --dry-run --json` on this backlog match; a real native push of all 76 stories to the stub `gh` refused none and changed only remote, remote_url, updated, and changelog lines.
- Checks after rebase on main f468c6e: cargo fmt --check clean; clippy -D warnings clean; cargo test --locked 209 passed, 0 failed (42 binaries); npm test 456/456; story-policy.rs 12 passed; story-policy-contract.rs 11 passed.
- Limits: frontmatter comments are still dropped on write-back, as before. Native writes a null key as `key: null` where Node omits it, as before.
- Follow-up: ST-081 (plan and metrics still use the strict parser).
