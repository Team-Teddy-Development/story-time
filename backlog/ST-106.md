## Story
As a maintainer setting up a machine or a repository, I want a Rust installer that copies the skills, so that installing story-time needs no Node, as Constitution Article VIII requires.

## Acceptance Criteria
- [x] Given a temporary HOME and a project directory, when the Rust installer runs with --agent codex, claude and all, with --scope user and --scope project --project DIR, with --codex-home DIR, and with --dry-run, then it prints the same output, writes the same files without the skills' test folders, and exits with the same code as node scripts/install.mjs, verified by a native/story-push contract test
- [x] Given skills already installed, when the Rust installer runs without --force and then with --force, then it refuses and writes nothing, then replaces them, matching node scripts/install.mjs output and exit codes, verified by a native/story-push contract test

## Evidence
- Red 15bcb9e: `tests/install_skills_contract.rs` with an empty `story-install-skills` main; all 5 tests failed on output (`stdout differs for ["--agent", "codex"]`, `stderr differs for ["--agent", "all"]` in the clash case).
- Green 3fe41d8: new binary `story-install-skills` (`src/bin/story_install_skills.rs`) on a shared library module `src/skill_install.rs` (`Agent`, `Target::{User, Project}`, `plan`, `skill_names`, `install`, and `normalize`, a port of Node's lexical path join). `story-install` now uses the same module for its skill copy, so there is one copy routine. Copied folders keep the source folder's mode, as Node's `fs.cp` does.
- AC1: the contract test runs Node `scripts/install.mjs` and the Rust binary (env_clear, PATH=/nonexistent, HOME=temp) on identical fixtures and compares stdout, stderr, exit code, and every file and folder with mode and bytes, for `--agent codex|claude|all` at user scope; `--scope project` with an absolute, a `./project/../project/`, and the current-folder project; `--codex-home` absolute with `..` and a trailing slash, and relative with `--agent all`; and `--dry-run` at user scope, project scope, and with `--codex-home`. Both read the real `skills/` tree (27 skills); 18 runs matched.
- AC2: with skills already installed at user and project scope, both refuse without `--force` (exit 1, nothing written, also with `--dry-run`), and both replace them with `--force`; `--force --dry-run` writes nothing.
- Jev concerns on PR #227 (`home_unset` 0.48, `skills_dir_compile_time` 0.44), fixed in red b82dbd0 / green 0da383a. Home now comes from `std::env::home_dir()` (HOME, then the passwd entry), as Node's `os.homedir()` does. With HOME unset, the output, exit code and tree match Node for codex, claude and all with `--dry-run`, and no relative folder appears. With HOME set but empty, Rust uses the account home; Node plans relative folders in the cwd. That difference is deliberate and tested natively. A new `--source DIR` flag (default: the build checkout) selects the skills. If `<source>/skills` is missing, the binary exits 1 with `No story-time skills folder at <path>.` and writes nothing; this is tested with absolute and relative paths, with and without `--dry-run`. `story-install` copies skills from its release export, never from the build checkout.
- Limits: `--uninstall` and `--help` are rejected as unknown flags until ST-107. The test-folder exclusion is `<skill>/scripts/test`; Node matches that substring anywhere, and no current path differs.
- Checks on main cf2170f: `cargo fmt --check` ok; clippy `-D warnings` ok; `cargo test --locked` 336 passed, 0 failed; `npm test` 467/467; `scripts/story-policy.rs` 12 passed; `test/story-policy-contract.rs` 11 passed.
