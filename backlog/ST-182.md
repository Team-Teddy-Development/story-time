## Story
## Story

As a backlog owner turning a task list into stories, I want story-create to check whether the requested behavior already exists before it files a story, so that the backlog does not fill with stories for finished work.

## Source task

Asked by Eric on 2026-11-25 in a Claude Code session. A 2026-11-24 sweep of a Microsoft To Do list filed ess-monorepo stories for work that had already shipped, including ESS-382. A reviewer then closed their issues by hand, and the next `story push` would reopen them because the stories stayed `draft`.

## To plan

- What counts as evidence: merged PRs and done stories with similar titles, plus a search of the code for the named route, screen or command.
- When evidence turns up, offer three choices: skip filing, file the story as already delivered (archived, with the evidence), or file it anyway with a note.
- Should `story new` warn on a near-duplicate of a done or archived story, as well as an exact title match?

## Acceptance Criteria
- [ ] Given a request for behavior a merged PR already delivered, when story-create runs, then it reports the evidence and does not file a draft story without confirmation
