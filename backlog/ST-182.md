## Story
As a backlog owner turning a task list into stories, I want story-create to check whether the requested behavior already exists before it files a story, so that the backlog does not fill with stories for finished work.

## Source task
Asked by Eric on 2026-11-25 in a Claude Code session. A 2026-11-24 sweep of a Microsoft To Do list filed ess-monorepo stories for work that had already shipped, including ESS-382. A reviewer then closed their issues by hand, and the next `story push` would reopen them because the stories stayed `draft`.

## Acceptance Criteria
- [ ] Given `skills/story-create/SKILL.md`, when an agent reads its duplicate check, then it must search merged pull requests of the configured tracker repository by the request's keywords (`gh pr list --state merged --search`) before running `story new`, verified by a native/story-push test that reads the skill text
- [ ] Given `skills/story-create/SKILL.md`, when an agent reads its duplicate check, then it must also compare the request with `done` and `archived` stories from `story list --json` and search the code for the route, screen, or command the request names, verified by a native/story-push test that reads the skill text
- [ ] Given a search that finds evidence the behavior shipped, when story-create reports it, then it offers exactly three outcomes: skip filing, file as `archived` with the evidence in Notes, or file as `draft` with a note, verified by a native/story-push test that reads the skill text
- [ ] Given evidence and no outcome chosen by the person, when story-create proposes one, then it recommends `archived` with the evidence, verified by a native/story-push test that reads the skill text
- [ ] Given a story filed as `archived` with no `remote`, when `story push <id> --dry-run` runs, then the plan skips that story and creates no issue, recorded with the command output in the story Evidence
- [ ] Given several stories from one source (a gap-sweep table or a task-list sweep), when story-create shows the list for approval, then each row shows its evidence links and proposed outcome, verified by a native/story-push test that reads the skill text
- [ ] Given a merged pull request search that cannot run (tracker is not GitHub, or `gh` is not signed in), when story-create reports, then it names that search as not run instead of reporting no evidence, verified by a native/story-push test that reads the skill text
- [ ] Given the 2026-11-24 request "Applicant details open as a full page, not a side panel" against ess-monorepo, when an agent follows the updated skill, then it reports merged PR #2107 as evidence and files no `draft` story, recorded with the transcript excerpt in the story Evidence

## Out of Scope
- A near-duplicate title warning in the CLI `story new` command or the MCP `story_create` tool. It would not have stopped ESS-382 (see Notes). File it as its own story if a later case needs it.
- Archiving or closing stories already filed for shipped work. That is the weekly audit ESS-391 in ess-monorepo.
- Reopen behavior of `story push` for issues closed by hand.
- The GitHub request form that feeds grooming (ESS-394 in ess-monorepo).
- Changes to the gap-sweep skill. It hands approved rows to story-create, so the check runs there.

## Notes
Decisions made in grooming on 2026-11-25, replacing the `## To plan` list.

- **What counts as evidence.** Merged pull requests found by keyword search, `done` and `archived` stories with a similar title or statement, and a code search for the route, screen, or command the request names. The merged pull request search is the part that stops ESS-382: `gh pr list --state merged --search "applicant full page"` in ess-monorepo returns PR #2107 "feat(ats): open applicant details as a full page" as its first result, merged 2026-11-19, five days before the story was filed. Story-title evidence alone would have missed it. PR #2107's body says `Stories: none`, and no `done` or `archived` ess-monorepo story has a close title (checked 2026-11-25 against 121 done and 13 archived cards on main; the nearest, ESS-206, moved import paths).
- **The skill owns the whole check; the CLI does not change.** The check needs keyword search and code reading, which only the agent can do. Today `story new` refuses no title at all: two `story new --title "Same thing"` runs in a scratch backlog wrote T-001 and T-002. Only the MCP `story_create` tool refuses an exact, case-folded title match (`native/story-push/src/mcp.rs`). Jev `decide` chose skill-only over skill plus a CLI near-title warning at confidence 0.6 (0.8 vs 0.2). That is below 0.7, so grooming took the smaller, reversible option: skill only, with the CLI warning out of scope.
- **Three outcomes, `archived` recommended.** When evidence turns up, the person picks skip, file as `archived` with the evidence, or file as `draft` with a note. Jev `decide` chose `archived` as the default recommendation at confidence 1.0. An `archived` card with no `remote` is skipped by `story push` (`native/story-push/src/lib.rs`, the `closed` and `skip` branch), so no issue is created or reopened. The card stays in `backlog/`, so the next sweep's duplicate check finds it and does not propose the work again. Skipping leaves no such record.
- **Why story-create.** gap-sweep hands approved rows to story-create, and story-create is the skill that files stories from any request, so one check there covers both paths. Which skill the 2026-11-24 sweep agent followed is not recorded in its commit (e1d167bf4 in ess-monorepo).
- **Verification commands.** Skill-text criteria: a Rust test in `native/story-push` that reads `skills/story-create/SKILL.md`, as ST-097 did, run with `/home/ejernigan/.claude/bin/heavy cargo test -p story-time-native`. Push criterion: `story push <id> --dry-run` on a scratch `archived` card. Replay criterion: a transcript of an agent following the skill against ess-monorepo.
- **Estimate.** Planning poker 2/3/3 (Builder high, Tester med, Operator med), median 3. Anchors: ST-097 (1, skill text verified by a native test), ST-121 (2), ST-113 (3, MCP create refuses duplicate titles). Drivers: a rewrite of story-create section 2 into an evidence check with outcomes and a batch row format, one Rust skill-text test file covering six criteria, and two evidence runs (a push dry run and the ess-monorepo replay). Risks: string-match tests force skill wording and test needles to be designed together, and the replay needs a live `gh` login to ess-monorepo and may take a rerun.
- **Value scores are PROPOSED by agent**, not confirmed by the owner. value 5: every story-create run in every repo using story-time, and the 2026-11-24 sweep filed at least two shipped-work stories (ESS-382 and one more, per ESS-391). time_criticality 3: task-list sweeps recur, and ess-monorepo already holds 107 draft stories. risk_reduction 3: new filings stop feeding the close-by-hand and reopen-on-push loop, and fewer stories reach the ESS-391 audit.
- Affected skill: `skills/story-create/SKILL.md`. Expected result: before `story new`, the agent reports evidence and an outcome choice instead of filing a draft for shipped work.
