## Story
As an agent, I want the story-map skill to describe exactly which backlog files each command reads as stories, so that I do not rely on a rule the CLI does not follow.

## Acceptance Criteria
- [x] Given skills/story-map/SKILL.md, when it describes map files in the backlog directory, then it names the rule list, planning, and adopt actually use, verified by a native/story-push test that reads the skill text

## Notes
Source: ST-093 (PR #192) report. skills/story-map/SKILL.md lines 71-72 say "The CLI ignores files that aren't story files". `list` reads `<ID>.md` names; planning and adopt skip `*.map.md` and treat other Markdown as stories.

## Evidence
- Red 25dd937: `tests/story_map_skill.rs` failed with `overbroad claim is still present: The CLI ignores files that aren't story files.`
- Green 64d0ca7: skills/story-map/SKILL.md step 6 now says no command reads a `.map.md` file as a story; `story list`, `lint`, and `stats` read only files named for a story ID; `story plan` and `story adopt` read every other `.md` file as a story and stop with an error on one that is not; keep other notes out of the backlog directory.
- The same test runs the native binary (env_clear, PATH=/nonexistent) on a scratch backlog: with ST-001.md and EP-001.map.md, `list --json` is `["ST-001"]`, `stats --json` total is 1, lint does not mention the map, and `plan --snapshot` and `adopt preview` succeed; after adding notes.md, list still skips it, `plan --snapshot` exits 2 with `malformed_story: backlog/notes.md`, and `adopt preview` exits 2 with `unsupported_story` on `backlog/notes.md`.
- Observed sources: `list.rs` `story_id` filter (`<PREFIX>-<digits>.md`); `planning.rs` skips `*.map.md` and parses other `.md`; `adoption.rs` keeps `*.map.md` as `epic_map`.
- Limit: an `.md` file with story-like frontmatter is read as a story by plan and adopt rather than reported.
