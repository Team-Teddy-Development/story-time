## Story
As a story-time user working through an agent, I want to ask "what's our velocity", "show the burndown" or "when will this epic be done" and get the real figures, so that planning conversations use data rather than guesses.

## Source task
2026-11-25, velocity and burndown design (PR #444). Depends on ST-195 (burndown) and ST-196 (forecast), which depend on ST-194.

## Acceptance Criteria
- [ ] Given the ST-195 fixture repository, when a local stdio client calls `story_burndown` with `{"sprint": "2026-S01", "today": "2026-11-06"}`, then `structuredContent` equals the JSON of `story burndown --sprint 2026-S01 --today 2026-11-06 --json` on that repository (`native/story-push/tests/mcp_protocol.rs`)
- [ ] Given the ST-196 fixture repository, when a local stdio client calls `story_forecast` with `{"ids": ["A", "B"], "today": "2026-11-15", "seed": 7}`, then `structuredContent` equals the JSON of `story forecast --ids A,B --today 2026-11-15 --seed 7 --json` (`native/story-push/tests/mcp_protocol.rs`)
- [ ] Given a repository with three closed sprints, when a local stdio client calls `story_velocity` with `{"from": "2026-09-07", "to": "2026-11-15"}`, then `structuredContent` equals the `velocity` figure of `story metrics --from 2026-09-07 --to 2026-11-15 --json` (`native/story-push/tests/mcp_protocol.rs`)
- [ ] Given a registry server whose repository has the branch `story-time/ST-001` with a sprint that differs from the default branch, when `story_burndown` is called with `ref` `story-time/ST-001`, then the result's `sha` is that branch's head and its `rows` are the burndown at that commit (`native/story-push/tests/mcp_hosted_workspace.rs`)

- [ ] Given the skills folder, when the skills test reads it, then each file holds its required text:

## Notes
Decisions:
- **Where the hosted server lives.** It is this repository's own binary. `story mcp --http --registry` serves the same tool table over HTTP from bare clones of the registered repositories (ADR 0007, `docs/adr/0007-hosted-story-mcp.md`). The files are `native/story-push/src/mcp.rs` (the tool table at `:1905-2248`; `at_commit` at `:2253-2255` gives a tool the `ref` argument; `scope` at `:2258-2261` grants read-only tools to the `read` scope; `story_graph` is registry-only at `:2294`), `mcp/http.rs` (routes at `:150-160`), `mcp/registry.rs`, `mcp/workspace.rs` (the bare clones) and `mcp/propose.rs` (writes). It is deployed twice from the image built by `native/story-push/Dockerfile`: the Team Teddy coffee cluster (`docs/designs/hosted-story-mcp.md:416-425`) and an ESS Fargate stack. So one change to `mcp.rs` serves local and hosted, as the design requires.
- **Three read-only tools.** `story_velocity`, `story_burndown` and `story_forecast` are added to the tool table with `read_only: true`, and to `at_commit`, so a hosted call can read a proposal branch. Each calls the same function as its CLI command and returns its JSON unchanged. `story_velocity` returns the `velocity` figure of `story metrics` (ST-194), so no separate `story velocity` command is needed.
- **Already covered elsewhere.** `story_list` filtering by `sprint` and `story_update` setting `sprint` are in ST-194's scope, so they are not repeated here.
- **No dashboard in the hosted server.** The server answers only `/mcp`, `/healthz` and `/readyz` (`mcp/http.rs:152-156`), and both hosted roots return 404. The delivery dashboard is a separate claude.ai dashboard that computes its own velocity, burndown and forecast from an hourly export. Jev, 2026-11-25 (1.00): the dashboard panels are a separate story, ST-203. This story stays MCP and skills.
- **SVG split out.** `story burndown --svg` moved to ST-202. The chart is a CLI output format that shares no code with the MCP tools or the skills, and without it poker sized this story 5/5/5.
- **Ship obligations.** The new tools keep `mcp_registration_docs` and the hosted tool table in step, and the skill text passes `test/expected-skills.mjs` and `agile_metrics_skill.rs`. The hosted image redeploys for both deployments; no infrastructure changes.

Estimate: see the changelog line for the poker votes and anchors.
