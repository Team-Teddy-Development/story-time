## Story
As a developer who sets up story-time, I want the installer to check that my agents and my repository can use the hosted story-time MCP, and to add what is missing, so that I do not register the server and the repository by hand.

## Acceptance Criteria
- [ ] Given an agent (Claude Code, Codex, or Pi) with no story-time MCP entry, when the install check runs with a server URL and a token file, then it reports the missing entry, adds it with the token read from the file at connect time, and a second run reports no change
- [ ] Given a repository whose origin is not in the answer of story_repos, when the install check runs in it, then it reports that the server does not serve the repository and prints the registry entry to add
- [ ] Given the server is not reachable or refuses the token, when the install check runs, then it exits non-zero, names the cause, and changes no agent configuration

## Notes
Source: owner message on 2026-11-16, "we may need a story about an install checker to add it to your repo", sent while ST-138 added the hosted MCP to Claude Code and Pi by hand. What the hand setup needed: a helper that reads the token from `~/.config/story-time/client-token`, one `claude mcp add-json --scope user` call, one entry in `~/.pi/agent/mcp.json`, and for a new repository one `[[repo]]` table in `k8s/story-time/25-configmap.yaml` of coffee-apps plus the GitHub App installation on that repository.

Open question for refinement (assistant's reading, not confirmed by the owner): "add it to your repo" can mean (a) add the MCP entry to the agent configuration, (b) add the repository to the server registry, or both. The criteria cover (a) as a change and (b) as a report. The registry is in another repository and a change to it is a deploy, so the check only prints that entry.
