## Story
As a coding agent, I want story_comments and story_resolve_comment to work on a story with a Gitea issue, so that review comments on Gitea are answered and marked as on GitHub.

## Acceptance Criteria
- [ ] Given a story with a Gitea issue, when story_comments runs, then it returns each comment with its author, its time, and its resolved state
- [ ] Given a comment that is not resolved, when story_resolve_comment runs, then the bot posts one reply that carries the story-time marker with the forge gitea, and story_comments then shows the comment as resolved
- [ ] Given a comment that is already resolved, when story_resolve_comment runs again, then the server posts no second reply
- [ ] Given a story whose issue URL is not on the Gitea host of its registry entry, when a comment tool runs, then the server refuses and sends the token to no host

## Out of Scope
- Writes and pull requests (ST-149).
- Comments of a pull request review. The tools read issue comments only.
- A change to the GitHub path.

## Notes
Source: split of ST-140 on 2026-11-16 (Jev: three stories, 0.63).

`mcp/comments.rs` reads the issue from `remote_url`, takes only an `https://` URL (`issue_of`), and writes the marker `<!-- story-time:v1:resolves=github:...`. A Gitea issue URL can be plain HTTP under the `allow_http` rule of ST-140, and the marker must name the forge `gitea`. The bot identity that marks a comment resolved is the user of the token (`GET /api/v1/user`), not an App.

Owner handoff: the bot user needs write access to post the reply.
