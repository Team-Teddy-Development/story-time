## Story
As a story-time maintainer, I want one native config validator, so that story config, push, and init cannot disagree about whether a settings file is valid.

## Acceptance Criteria
- [x] Given a settings file that only one of validate_config and config::parse rejects today, when story config, story push --dry-run, and story init --config run on it, then all three accept it or all three reject it naming the same field, verified by a native/story-push contract test

## Out of Scope
Changing which settings are valid beyond making the three commands agree. Other EP-001 commands.

## Notes
Source: ST-046 implementation report. native/story-push/src/config.rs `parse` is a faithful port of Node parseConfig; push and init still use `validate_config` in src/lib.rs, which is stricter about Gitea URLs with credentials. Decide whether the credential check stays (it likely should, since it protects secrets) and apply it in one place. Epic EP-001; depends on ST-046.
