## Story
As a backlog coordinator, I want to add or replace the dedicated Test Plan and Out of Scope sections through a reviewed hosted proposal so that I can prepare stories for kickoff without bypassing hosted write policy. This addresses the section-edit blocker recorded in ST-174 (#409). Support only existing editable GitHub-backed stories, with the current story content SHA-256, the open proposal as the base when present, existing caller authorization, and the existing reviewed proposal path and branch lease. Out of scope: Gitea, arbitrary Markdown or criteria edits, acceptance and evidence, status and estimates, assignment and WIP, and direct or automatic merge. Leave tracker sync unchanged.

## Acceptance Criteria
- [ ] Given an authorized editor and the current content SHA-256 of an editable GitHub-backed story, when the editor submits valid text for one or both supported sections, then hosted Story Time opens or updates one reviewed pull request with only the requested section changes and one appended changelog entry, and leaves main and the tracker unchanged before merge. Cover adding missing sections and replacing existing sections.
- [ ] Given a stale content SHA-256, an unauthorized caller, a terminal story, an unsupported section, or empty text, when the caller submits an edit, then the service returns a typed conflict or refusal without changing the card, branch, pull request, or tracker. Cover a stale SHA-256 with a newer open proposal and verify that its pending edits remain intact.
