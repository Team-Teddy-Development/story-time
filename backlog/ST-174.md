## Story
As a backlog coordinator, I want to submit an acceptance-criteria section edit through hosted Story Time so that reviewers can refine a story without bypassing the hosted write policy. ST-173 (#403) is the first observed case: a reviewed section patch exists, but hosted update and note can change only fields and the changelog. Reuse the reviewed GitHub PR path tracked by ST-133. This draft does not change ST-173, its criteria, or implementation admission. Out of scope: Gitea writes, editing other sections, estimate or status changes, tracker writes before merge, and assignment or WIP changes.

## Acceptance Criteria
- [ ] Given a refined story in a registered GitHub repository and its current SHA-256, when an authorized editor submits valid replacement acceptance criteria, then the existing story PR workflow exposes a diff limited to the Acceptance Criteria section and one appended changelog entry. Main stays unchanged before merge, and the diff preserves the other sections, metadata, and earlier history.
- [ ] Given a stale story SHA-256, when an authorized editor submits a replacement, then the hosted operation reports a conflict without changing the story, branch, PR, or tracker issue.
- [ ] Given a current SHA-256, when the editor submits malformed criteria or targets a story marked done, split, or archived, then the hosted operation reports the refusal reason without changing the story, branch, PR, or tracker issue.
