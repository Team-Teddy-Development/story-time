## Story
As a maintainer, I want native settings errors to echo numbers as Node does, so that native and Node give the same message for the same settings file.

## Acceptance Criteria
- [x] Given settings.json whose tracker is 9007199254740993 or 1e400, when native story config runs, then its stderr and exit code equal the Node CLI output, verified by a case in native/story-push/tests/config_contract.rs

## Notes
Source: ST-082 (PR #159). serde_json stores settings integers as u64/i64 and prints them exactly where JavaScript rounds above 2^53, and it rejects `1e400` where JSON.parse returns Infinity.

## Evidence
- Red 84a4967: for `{"tracker":1e400}` native printed `invalid JSON configuration.` where Node printed `Unknown tracker "Infinity". ...`; the success and init cases also differed.
- Green 46299d2: `js_number::parse` reads settings as JSON.parse does (each number literal becomes `number(f64)`, 1e400 becomes Infinity). One Infinity mark (`u64::MAX`/`i64::MIN`) replaces the old 5e-324 mark; `model_string` is deleted and its callers use `config::js_string`.
- `tests/config_contract.rs::settings_numbers_echo_as_node_prints_them` adds 11 error cases including tracker 9007199254740993 and 1e400; `settings_numbers_print_as_node_prints_them` and `init_contract::settings_numbers_are_written_as_node_writes_them` compare success output and file bytes with Node.
- Real settings: `story config` and `--json` identical to Node, 2 compared, 0 differing.
- Limit: planning artifacts print sprint_days with serde, not Node formatting (no Node counterpart).
- Checks: `cargo fmt --check` ok; `cargo clippy --locked --all-targets -- -D warnings` ok; `cargo test --locked` 305 passed, 0 failed (rebased on 171b612); `npm test` 461/461; `scripts/story-policy.rs` 12 passed; `test/story-policy-contract.rs` 11 passed.
