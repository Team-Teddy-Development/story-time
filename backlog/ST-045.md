## Story
As a story-time maintainer, I want the adoption contract tests to pass on every run, so that a flaky ETXTBSY failure does not block CI or hide a real defect.

## Acceptance Criteria
- [ ] Given the adoption_contract test binary run 100 times in a row, when setup_routes_use_the_native_contract_and_init_is_unchanged runs in parallel with the other tests, then every run passes with no Text file busy error, verified by a loop over the built test binary

## Out of Scope
Changing the single-test install files planning_install.rs and adoption_preview_install.rs, which have no parallel test to race with.

## Notes
Source: found while verifying ST-044 (run 19 of a 40-run loop). tests/adoption_contract.rs:621 copies CARGO_BIN_EXE_story with fs::copy, and :629 executes the copy. Another test thread forks while the copy's write handle is open, so the forked child holds it until exec and exec fails with ETXTBSY (os error 26). The product does not read its own path, so the test can run CARGO_BIN_EXE_story directly.

## Test Plan
Red: loop the built adoption_contract binary until the ETXTBSY failure appears. Green: run CARGO_BIN_EXE_story directly; loop 100 runs with no failure.
