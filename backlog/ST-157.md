## Story
As a maintainer of a Gitea repository (cartographer-core, xanthos), I want story sync-merge and story check-pr to work with the Gitea tracker, so that merges close and comment on story issues there as they do on GitHub

## Acceptance Criteria
- [ ] Given a repository whose settings name tracker gitea and a merged pull request that names stories, when story sync-merge --from <push before> runs in Gitea Actions after the push to the default branch, then each named issue matches its card and gets one merge comment, and a rerun adds none
- [ ] Given --from is the zero commit or is not an ancestor of HEAD, when story sync-merge runs with tracker gitea, then it takes the --all path, mirrors every linked card, and posts no comment
- [ ] Given an issue comment that carries the marker but was written by a user other than the token's user, when story sync-merge runs with tracker gitea, then it still posts its own merge comment
- [ ] Given .gitea/workflows/story-sync.yml from the playbook in cartographer-core and xanthos, when a push to main runs it, then the run succeeds and its report lists 0 failed

## Test Plan
- AC1: `sync_merge_gitea_contract::ac1_named_issues_match_their_cards_and_get_one_merge_comment` (fake Gitea server; second run finds the token user's marker and posts nothing).
- AC2: `sync_merge_gitea_contract::ac2_a_zero_or_foreign_from_takes_the_all_path`.
- AC3: `sync_merge_gitea_contract::ac3_a_marker_from_another_user_does_not_count`.
- Extras: `a_server_error_exits_1`, `pulls_are_read_once_per_run`, `a_feature_branch_ref_is_refused`.
- AC4: live runs on main in cartographer-core and xanthos after merge.

## Notes
- Scope change (2026-11-16, owner request "build the same story close yml for gitea"): this story covers sync-merge and its Gitea workflow only; the check-pr half moved to ST-161. Estimate kept.
- Gitea is 1.21.11: no Actions run-history API and no commit-to-pull endpoint (`/commits/{sha}/pull` returns 404). The range starts at the push event's `before` commit (`--from`), and merged pulls come from the closed-pull list matched by `merge_commit_sha`.
- Probe runs (throwaway branch `probe/st-157-actions-token`; cartographer-core runs 1143-1144, xanthos runs 404-405): the Actions token is user `gitea-actions` (id -2), reads issues, pulls and the repository, and PATCH on a missing issue answers 404 (not 403). `cartographer-heavy` has cargo 1.96; `xanthos-lightweight` has no cargo but keeps a toolchain under `/data/rust`.
- Source: the owner asked on 2026-11-16 to install story-sync in cartographer and xanthos. Both use `tracker: gitea` (cartographer/cartographer-core, team-teddy/xanthos), and `story sync-merge` (ST-151) reports `skipped (unsupported tracker)` there. `story check-pr` (ST-152) calls `gh`. Not installed in those repositories until this story is done.
- The gateway already has Gitea issue writes; the new parts are Gitea's merged-PR-for-commit lookup, the comment list with the bot user, the last-successful-run anchor in Gitea Actions, and the `.gitea/workflows` templates.
