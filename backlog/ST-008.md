## Story
As a story-time operator, I want structured story-time logs in Loki and Grafana, so that I can locate failed operations and inspect their context.

## Acceptance Criteria
- [ ] Given configured logging, when successful and failing operations run, then Loki contains structured events with timestamp, severity, operation, outcome, duration, and correlation identifier, verified on the live stack from a GitHub Actions run that exports through the Xanthos gateway, recorded in the story Evidence
- [ ] Given collected logs, when the operator uses Grafana filters for operation, outcome, and time range, then matching Loki events appear, verified on the live stack from a GitHub Actions run that exports through the Xanthos gateway, recorded in the story Evidence
- [x] Given secrets and story content in inputs, when events are emitted, then credentials and story bodies are excluded and indexed labels follow a documented bounded set, verified by a native/story-push test that exports to a local OTLP/HTTP receiver
- [x] Given disabled telemetry or an unavailable telemetry backend, when a story command runs, then its result remains correct and telemetry export uses bounded buffering and timeouts, verified by a native/story-push test that exports to a local OTLP/HTTP receiver
