## Story
As a team lead, I want story metrics to read split into changelog lines as a split status event, so that split stories are not reported as history gaps.

## Acceptance Criteria
- [x] Given a story whose changelog has a split into line and whose status is split, when story metrics runs over a window that includes that date, then the story has no history gap and is not listed as unknown, verified by a case in native/story-push/tests/agile_metrics_contract.rs

## Evidence
- Red 4b3001c: the new case `a_split_into_line_is_the_status_event_of_a_split_story` in native/story-push/tests/agile_metrics_contract.rs failed; throughput listed ST-001 as unknown with "status split has no matching changelog event".
- Green e7d30f9: native/story-push/src/metrics.rs reads a `- DATE split into ...` changelog line (the text Node's split-story.mjs writes) as a `split` status event; `set ... status=` parsing is unchanged. The figure source text and skills/agile-metrics/SKILL.md now name `split into` lines too. agile_metrics_contract 5 passed, agile_metrics_skill 5 passed.
- Real data, `story metrics --from 2026-11-01 --to 2026-11-14` on this backlog: before, ST-021 was unknown in throughput, WIP, and cycle time; after, ST-021 is unknown in none. ST-004 and ST-017 stay unknown in cycle time (done with no earlier in-progress event).
- Checks after rebase on main ae14faf: cargo fmt --check clean; clippy -D warnings clean; cargo test --locked 210 passed, 0 failed (42 binaries); npm test 456/456; story-policy.rs 12 passed; story-policy-contract.rs 11 passed.
- Limit: only lines that start with `split into ` count.
