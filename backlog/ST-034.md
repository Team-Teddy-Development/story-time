## Story
As a maintainer working in a story-time checkout, I want native story to use the checkout's own Node CLI, so that commands run the code under test instead of an installed release.

## Acceptance Criteria
- [ ] Given a story-time checkout with skills/story-time/scripts/story.mjs and STORY_TIME_LEGACY_CLI unset, when native story runs a non-native command from inside that checkout, then it dispatches to that checkout's story.mjs, verified by a native/story-push integration test
- [ ] Given STORY_TIME_LEGACY_CLI is set, when native story runs a non-native command anywhere, then it dispatches to that path as before
- [ ] Given a directory that is not a story-time checkout, when native story runs a non-native command, then it uses runtime.json legacyCli as before

## Out of Scope
Changing runtime.json or the installer. Native init, push, adopt, and plan, which do not dispatch.

## Notes
Source: gap-sweep dry run row 6 (feature). Evidence: AGENTS.md:7-8 asks every contributor to set STORY_TIME_LEGACY_CLI by hand; native/story-push/src/main.rs:53-62 falls back only to ~/.config/story-time/runtime.json. During ST-030 the runtime file pointed at a stale release (cb9f9ee). Affected command: native `story` dispatch.

## Test Plan
Red: native/story-push integration tests run the binary in a temporary checkout with and without STORY_TIME_LEGACY_CLI and outside a checkout. Verify with `cargo test --locked` in native/story-push.
