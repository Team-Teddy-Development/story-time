## Story
As a team reading delivery metrics, I want the hosted story_accept tool to write the same `set status=done` changelog event that `story set` and story_update write, so that every hosted-accepted story counts as done on its acceptance date in story metrics, estimates and burndown. Today story_accept appends `<date> accepted with evidence for every criterion`, which no metrics reader parses, so each accepted story is reported as a gap (status done has no matching changelog event). Affected: ST-150, ST-176, ST-191, ST-194, ST-196, ST-211 and about 240 Varsity cards.

## Acceptance Criteria
- [ ] Given an in-progress story with a `set status=in-progress` changelog event, when story_accept accepts it, then its changelog gains `<today> set status=done — accepted with evidence for every criterion` and `story metrics --json` for today lists it in throughput with no unknown gap (cargo test --locked --test mcp_protocol story_accept_records_evidence_and_preserves_criterion_wording)
- [ ] Given the ST backlog on main, when the fix merges, then no done card carries a bare `<date> accepted with evidence for every criterion` line; each is rewritten to `<date> set status=done — accepted with evidence for every criterion` with the same date (grep -rn '^- [0-9-]* accepted with evidence' backlog returns nothing)
- [ ] Given the merged fix, when the hosted MCP is redeployed with the merged main image, then the pod runs the new tag, /healthz returns 200, POST /mcp without a token returns 401, and story_repos reports story-time ready
