## Story
As a maintainer, I want plan output to print settings numbers as JSON.stringify does, so that a large sprintDays or limit value prints the same way in every artifact.

## Acceptance Criteria
- [x] Given settings whose sprintDays is 9007199254740993, when native story plan writes its JSON artifact, then sprint_days prints as 9007199254740992 and not 9007199254740992.0, verified by a native/story-push test

## Notes
Source: ST-084 (PR #180) limits. Planning artifacts (sprint_days, limit_per_person) print through serde_json::to_string_pretty, not js_number::stringify.

## Evidence
- Red 8f98514: `settings_numbers_print_in_plan_artifacts_as_javascript_prints_them` failed with `"sprint_days": 9007199254740992.0,` (also `limit_per_person` and `selected_points: 3.0`).
- Green a6fa297: every JSON print in planning.rs (stdout, `--output` JSON and Markdown, `--snapshot`) goes through `js_number::stringify`, which keeps serde's pretty and compact layouts. The 16 earlier planning contract tests pass unchanged.
- The test asserts `"sprint_days": 9007199254740992,`, `"limit_per_person": 9007199254740992,`, `"selected_points": 3,`, stdout equal to the file, and no `9007199254740992.0` in either artifact. sprintDays 1e400 is rejected first with `malformed_config: team.sprintDays must be a positive integer.`
- Real backlog: `plan --snapshot` then `plan --from` exit 0 with `"sprint_days": 10`; plan has no Node implementation to compare.
- Checks: `cargo fmt --check` ok; `cargo clippy --locked --all-targets -- -D warnings` ok; `cargo test --locked` 316 passed, 0 failed; `npm test` 461/461; `scripts/story-policy.rs` 12 passed; `test/story-policy-contract.rs` 11 passed.
