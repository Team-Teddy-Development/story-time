## Story
As a team lead reading the delivery dashboard, I want its velocity, burndown and forecast panels, and a new estimated-against-shipped panel, drawn from story-time's own figures, so that the dashboard and the CLI give one answer and the forecast shows a 50% and an 85% date instead of a single date at an average pace.

## To plan
- **The dashboard found.** The delivery dashboard ("ESS Delivery Tracker") is a claude.ai dashboard artifact, not part of this repository or of the hosted server, which answers only `/mcp`, `/healthz` and `/readyz` (`native/story-push/src/mcp/http.rs:152-156`). It has two datasets, `items` and `releases`, each a JSON file that a scheduled job rebuilds from the story-time backlogs of three repositories, their merged pull requests and their deploy runs. Each `items` row carries `size`, `points`, `started`, `merged_at`, `finished_on`, `live_at`, `stage`, `value`, `time_criticality` and `risk_reduction`.
- **What it computes today.** Velocity, forecast and burndown are calculations in the page over `items`: weekly finished points; one forecast date per epic and feature from a 14-day pace in priority order; the points left per day since 2026-11-10. Unsized items count as 3 points. These are what this story replaces with story-time's figures, so the CLI, the MCP and the dashboard give one answer.
- **Open questions.** Where the scheduled job that builds the export lives (not found in the local repositories), and whether it should run `story burndown`, `story forecast` and `story estimates` per repository and upload their JSON as three more datasets. Whether the dashboard keeps weekly velocity for repositories without sprints, next to ST-194's sprint velocity. How three repositories' estimate rows are pooled for the size-by-builder level of ST-193's groups.

## Acceptance Criteria
- [ ] Given the JSON of story burndown, story forecast and story estimates for a repository, when the dashboard loads them as datasets, then its forecast panel shows the 50% and 85% dates from story forecast for that repository
