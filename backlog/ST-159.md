## Story
As a maintainer, I want the mcp_http audit assertions to wait for the server's audit line, so that native-push does not fail at random on a correct server

## Acceptance Criteria
- [x] Given the mcp_http tests that assert the latest audit line, when the stderr reader thread receives the line after the HTTP response returns, then the test waits for that line (up to 5 seconds) and passes

## Evidence
- Fix: commit bed76b5 (`native/story-push/tests/mcp_http.rs`): `Http::audit_when` waits up to 5 seconds for the expected audit line; `a_read_only_token_cannot_see_or_run_write_tools` waits for the `story_update` line and `the_same_tool_answers_over_http_and_stdio` style check waits for its first line.
- Before: PR #360's first `native-push` run failed at tests/mcp_http.rs:430 (left `story_show`, right `story_update`) while the same server code passed on `main` at 1b713a8.
- After: `cargo test -q --locked --test mcp_http` passed 15 of 15 consecutive local runs; PR #360 `native-push` passed (run 43929306322); the PR #365 stack ran the full native suite, 538 passed 0 failed.
- DoD: Stories line on PR #360; test-only change, no installed path affected.

## Notes
- Source: PR #360 `native-push` failed in `mcp_http::a_read_only_token_cannot_see_or_run_write_tools` (tests/mcp_http.rs:430: left `story_show`, right `story_update`). The same code passed on `main` at 1b713a8. Cause: the server prints the audit line to stderr, and a test thread reads stderr into `log`. The test read `audit.last()` right after the HTTP answer, before the reader thread had received the new line.
