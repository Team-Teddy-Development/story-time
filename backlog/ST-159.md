## Story
As a maintainer, I want the mcp_http audit assertions to wait for the server's audit line, so that native-push does not fail at random on a correct server

## Acceptance Criteria
- [ ] Given the mcp_http tests that assert the latest audit line, when the stderr reader thread receives the line after the HTTP response returns, then the test waits for that line (up to 5 seconds) and passes

## Notes
- Source: PR #360 `native-push` failed in `mcp_http::a_read_only_token_cannot_see_or_run_write_tools` (tests/mcp_http.rs:430: left `story_show`, right `story_update`). The same code passed on `main` at 1b713a8. Cause: the server prints the audit line to stderr, and a test thread reads stderr into `log`. The test read `audit.last()` right after the HTTP answer, before the reader thread had received the new line.
