## Story
As a story author, I want to name a story in another repository of the same registry org in depends_on or relates_to, so that lint checks the link and tools can follow it.

## Acceptance Criteria
- [x] Given story mcp --root A --root B where B owns VC, when story_lint runs on a VE story with depends_on [VC-109], then no independent.deps error is reported
- [x] Given the same roots, when a VE story names VC-999 which does not exist, then story_lint reports an independent.deps error
- [x] Given a third root that also declares VE, when story_lint runs on a story that names a VE ID, then it reports links.ambiguous
- [x] Given a story body that mentions VC-109 with no frontmatter link, when org-aware story_lint runs, then it reports the warning links.prose_mention
- [x] Given the VE repository alone, when story lint runs on a story with depends_on [VC-109], then it reports the warning independent.foreign_unresolved and exits 0
- [x] Given a VE story whose VC dependency is done, when story_update sets status=ready through an org-aware server, then the update succeeds
- [x] Given a story with relates_to [VC-110], when story set changes another field, then the saved file keeps relates_to directly after depends_on

## Out of Scope
- The hosted registry as an index source. This story builds the index from local `--root`s; ST-130 adds the registry source.
- Neo4j edges (ST-132).
- Automatic rewriting of prose mentions.

## Test Plan

- The existing contract tests pass unchanged.

## Evidence
Red commit `d9c32b8`: `cargo test --locked --test lint_org` failed 8 of 8. Green commit `c04dbb8`. Each criterion is verified by a test in `native/story-push/tests/lint_org.rs`, which runs the real `story` binary.

| Criterion | Test |
|---|---|
| 1: a link to a story in another root raises no `independent.deps` error | `a_link_to_a_story_in_another_root_resolves` |
| 2: a link to a story that no root has is an error | `a_link_to_a_story_that_no_root_has_is_an_error` |
| 3: a prefix that two roots declare gives `links.ambiguous` | `a_prefix_that_two_roots_declare_is_ambiguous` |
| 4: a mention with no link gives `links.prose_mention` | `a_mention_in_the_text_without_a_link_is_a_warning` |
| 5: `story lint` alone warns `independent.foreign_unresolved` and exits 0 | `story_lint_in_one_repository_warns_about_a_link_it_cannot_check` |
| 6: `story_update` moves a story to ready through an org-aware server | `story_update_moves_a_story_to_ready_when_its_dependency_in_another_root_is_done` |
| 7: `relates_to` is saved directly after `depends_on` | `relates_to_is_a_list_field_saved_directly_after_depends_on` |

- `cargo test --locked --manifest-path native/story-push/Cargo.toml --test lint_org`: 8 passed, 0 failed. The eighth test covers a spike that a story in another root waits on.
- `cargo test --locked` (all binaries): 415 passed, 0 failed. This includes `lint_contract` unchanged, which compares the native lint with the Node lint, and 5 unit tests in `src/org_index.rs`.
- `cargo clippy --locked --all-targets -- -D warnings`: clean. `cargo fmt --check`: clean. `npm test`: 457 pass, 0 fail.
- Real data, read-only: `story mcp --root ~/source/varsity/varsity-core --root ~/source/varsity/varsity-web` with `story_lint` on each repository. varsity-core: 362 stories, 132 `links.prose_mention` warnings on 73 stories, no `independent.deps` error. varsity-web: 40 stories, no link finding. The first run flagged `ST-002` in varsity-core for naming `VC-001` of its own repository; the rule now asks whether the id belongs to another repository, and the legacy-prefix case is in the test for criterion 4.
- Language audit: the new implementation and tests are Rust (`src/org_index.rs`, `src/lint.rs`, `tests/lint_org.rs`). The two Node files gain `relates_to` in their key lists only, as the design names; the Node lint has no new rule.
- Deviations from the design: `links.undeclared_prefix` is not in this story; it needs the registry and moves to ST-130. `links.prose_mention` skips the Changelog section and names only stories of another repository. A root declares the one `prefix` of its settings; an id of an undeclared prefix still resolves when exactly one root holds it. The installed `story` binary and the installed skills were not updated.
