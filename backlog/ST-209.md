## Story
As a backlog maintainer, I want sync-merge to name a card remote that points at a pull request as a wrong link, so that one stale card is reported once and does not fail every story-sync run on main.

Source: varsity-web VE-1879 (2026-11-26). Card VE-1689 had remote 1689, which is a pull request. gateway.rs github_update read the /pull/ URL as "Issue 1689 was transferred out" (permanent). The merge comment on #1689 then failed under a pull-requests: read token and was classified retryable, so sync-merge exited 1 (varsity-web run 45877597247). varsity-web corrected the card link in PR #2160; this story covers the tool side.

## Acceptance Criteria
- [ ] Given a card whose remote number is a pull request, when sync-merge or story push reads it, then the failure is permanent and its message says the remote names a pull request, not an issue, and a test covers that case.
- [ ] Given a pull request whose Stories line names an issue number that is a pull request, when sync-merge posts merge comments, then it reports one permanent failure for that reference, posts no comment, and exits 0 when no retryable failure exists, and a contract test covers that case.
- [ ] Given a real retryable tracker failure (for example HTTP 503), when sync-merge runs, then it still exits 1.
