## Story
As a team lead, I want a burndown for the current sprint (remaining points per day, scope steps, the ideal line, today) and a burnup for an epic or any set of stories, so that I can see during the sprint whether we will finish.

## Source task
2026-11-25, velocity and burndown design (`docs/designs/velocity-burndown.md`, PR #444). Depends on ST-194 (sprint attribute).

## To plan
- `story burndown [--sprint ID] [--json|--text]`, built from the ST-194 derivations.
  - Each calendar day carries remaining points, scope, ideal and a weekend flag.
  - A scope add or drop shows as a step in scope.
- `story burnup (--epic ID | --ids ...) [--from DATE --to DATE]`: cumulative done points against total scope.
- The JSON keeps the `metrics.rs` figure contract (source, window, units, `unknown` with a reason).
- Read-only MCP tool `story_burndown` (local `story mcp` and hosted), returning the same JSON.

## Acceptance Criteria
- [ ] Given a sprint with 10 committed points, 3 done on day 2 and 2 added on day 4, when story burndown --json runs on day 5, then day 2 shows 7 remaining, day 4 shows scope 12 and remaining 9, and day 5 is flagged as today
