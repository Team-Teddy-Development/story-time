## Story
As a hosted story MCP client, I want story_graph to answer dependents and dependencies across repositories from Neo4j, so that I can find which stories wait on a story in another repository.

## Acceptance Criteria
- [x] Given two registered repositories where VE-046 depends on VC-109, when story_graph runs for VC-109 with direction dependents, then the result includes VE-046 with its repository
- [x] Given the same graph, when story_graph runs for VE-046 with direction dependencies, then the result includes VC-109 and excludes dependents of VE-046
- [x] Given a story with relates_to [VC-110], when story_graph runs for it, then VC-110 returns as a RELATES_TO neighbor at depth 1
- [x] Given any story_graph result, when the client reads it, then it lists the repository and sha pairs that the graph was synced from
- [x] Given a link to an ambiguous prefix, when the sync runs, then the edge is skipped and the sync result counts it in skipped_ambiguous
- [x] Given Neo4j is stopped, when story_graph and story_lint run, then story_graph returns graph_unavailable and story_lint succeeds
- [x] Given a Neo4j started with NEO4J_AUTH=none, when story mcp runs with --graph and no Neo4j credentials, then the sync succeeds

## Out of Scope
- Cypher or other Neo4j concepts in tool contracts.
- `MENTIONS` edges.
- Sharing taskgraph's Neo4j.

## Notes
Source: ST-128, docs/designs/hosted-story-mcp.md, slice S3 (Component 6; items 13, 23, 27). Owner constraint: Neo4j is the core graph store. The sidecar is added to `k8s/story-time/30-deployment.yaml` in coffee-apps.

Deviations from the design (2026-11-15):
- A registry server syncs before a `story_graph` read when the commits in Neo4j differ from the commits it reads. It does not sync at start. The commits and the count of skipped links are stored on the `StoryRepository` nodes, so a Neo4j that lost its data is synced again.
- A registry server has no `story_graph_sync` tool. The sync result (`sync.repositories` with each `sha`, and `sync.skipped_ambiguous`) is in every `story_graph` result.
- A local `story_graph_sync` keeps its behavior: one repository, and a link to a story that the repository does not hold gets a `missing` node. Its result adds `relates_to` and `skipped_ambiguous` (0 for a local sync). Links between repositories exist only on a registry server.
- A registry server leaves a repository that it cannot read out of the sync, and `sync.repositories` does not list it.
