## Story
As a hosted story MCP client, I want story_graph to answer dependents and dependencies across repositories from Neo4j, so that I can find which stories wait on a story in another repository.

## Acceptance Criteria
- [ ] Given two registered repositories where VE-046 depends on VC-109, when story_graph runs for VC-109 with direction dependents, then the result includes VE-046 with its repository
- [ ] Given the same graph, when story_graph runs for VE-046 with direction dependencies, then the result includes VC-109 and excludes dependents of VE-046
- [ ] Given a story with relates_to [VC-110], when story_graph runs for it, then VC-110 returns as a RELATES_TO neighbor at depth 1
- [ ] Given any story_graph result, when the client reads it, then it lists the repository and sha pairs that the graph was synced from
- [ ] Given a link to an ambiguous prefix, when the sync runs, then the edge is skipped and the sync result counts it in skipped_ambiguous
- [ ] Given Neo4j is stopped, when story_graph and story_lint run, then story_graph returns graph_unavailable and story_lint succeeds
- [ ] Given a Neo4j started with NEO4J_AUTH=none, when story mcp runs with --graph and no Neo4j credentials, then the sync succeeds

## Out of Scope
- Cypher or other Neo4j concepts in tool contracts.
- `MENTIONS` edges.
- Sharing taskgraph's Neo4j.

## Test Plan
- Affected commands: `story mcp --graph`, tools `story_graph` and `story_graph_sync`.
- `cargo test --locked --manifest-path native/story-push/Cargo.toml --test mcp_graph` covers every criterion on the Docker-backed Neo4j harness, with `Neo4j::stop()` for the outage criterion.
- The cluster check of this slice is ST-137.
- `cargo clippy --manifest-path native/story-push/Cargo.toml --locked --all-targets -- -D warnings` and `cargo fmt --manifest-path native/story-push/Cargo.toml --check` pass.
- The existing contract tests pass unchanged.
