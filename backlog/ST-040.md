## Story
As a maintainer setting up a machine, I want one command to install a story-time release, so that the binary, skills, and runtime path come from one commit and the old install is kept for rollback.

## Acceptance Criteria
- [x] Given a story-time checkout at commit C, when the install command runs, then the native story binary, the skills for the chosen agents, and runtime.json legacyCli all come from commit C, verified by a Rust integration test in a temporary HOME
- [x] Given an existing install, when the install command runs, then the previous binary and runtime.json are saved and a rollback command restores them
- [x] Given --dry-run, when the install command runs, then it prints the plan and writes nothing

## Out of Scope
Publishing releases. Changing the skill content. Package managers other than cargo.

## Notes
Source: gap-sweep feature row 6 on 8f65a07. docs/native-story-push.md:26-34 describes manual steps to back up the binary and runtime.json before replacing them; README.md:97-98 says the installer does not install the native executable. On 2026-11-13 an install took five manual steps (git archive, cargo install, scripts/install.mjs, a runtime.json edit, a backup). The new installer must be Rust. Affected: scripts/install.mjs, native story.

## Test Plan
Red: Rust integration tests run the install command against a temporary HOME and check binary, skills, runtime.json, backup, rollback, and dry-run. Verify with cargo test --locked in native/story-push.
