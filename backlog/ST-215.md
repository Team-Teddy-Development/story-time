## Story
As a backlog owner, I want story-time to invent new epic and feature names when stories fit nothing in the taxonomy, and keep only the names Jev confirms, so that a daily run keeps the grouping fine-grained without a human writing every name and without the epics sprawling.

## Acceptance Criteria
- [ ] Given open stories that story group leaves unresolved, when story taxonomy propose runs with an Anthropic key, then one Messages API request with a JSON-schema output returns at most --max (default 3) proposals, each a new feature under an existing or new epic with a description and the stories it covers; the request carries titles, statements and criteria only, never ids, and refuses a payload the egress scan flags (cargo test --locked --lib group::namer)
- [ ] Given proposals from the Claude namer or a --names-from file, when they are verified, then a proposal is accepted only if Jev places at least --min-cards (default 2) of its stories into exactly that epic and feature at or above 0.7, moves no story already placed in the taxonomy to it, and keeps the taxonomy within 15 epics and 15 features; each rejection names its reason (cargo test --locked --lib group::propose)
- [ ] Given accepted proposals, when story taxonomy propose --write runs, then .story-time/taxonomy.json gains exactly those names and nothing is renamed or removed; without --write no file changes; fewer than --min-gaps (default 5) unresolved stories ends with nothing to propose and no model call (cargo test --locked --lib group::tests::taxonomy)
- [ ] Given the hosted MCP server, when story_taxonomy_propose is called without proposals, then it returns the repository's taxonomy and its unresolved stories; with proposals, it returns each verdict as story taxonomy propose would and writes nothing (cargo test --locked --test mcp_protocol taxonomy_propose)
- [ ] Given docs/designs/taxonomy-propose.workflow.yml, when a repository copies it, then a daily schedule runs story taxonomy propose --write and opens a pull request only when taxonomy.json changed (inspection of the template and story help)

## Out of Scope
- Renaming, merging or deleting taxonomy names automatically
- A local Llama/Ollama namer adapter (the Namer port allows it later)
- Opening the pull request from story-time itself; the workflow does that

## Test Plan
1. AC1 namer: group::namer unit tests against a fake Messages API server: request shape (model, anthropic-version, x-api-key, output_config.format json_schema), no ids in the payload, egress refusal, refusal and max_tokens stop reasons, proposal parsing; FileNamer parsing.
2. AC2 verification: group::propose unit tests with a scripted classifier: accepted, too few cards, steals a kept story, cap exceeded, duplicate name.
3. AC3 command: group::tests::taxonomy_* runs story taxonomy propose with --names-from and the fake Jev server: dry run, --write, min-gaps short circuit.
4. AC4 MCP: tests/mcp_protocol.rs taxonomy_propose gaps and verdict calls.
5. AC5: inspect the workflow template; story help lists the command.
