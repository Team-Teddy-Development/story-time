## Story
As a backlog owner, I want each open story placed in a named epic and feature chosen by Jev from a team taxonomy, and shown as Epic and Feature fields on its GitHub issue, so that a board grouped by epic tells me whether work is infrastructure, the Core cutover, or the recruit portal instead of one 'behind the scenes' bucket.

## Acceptance Criteria
- [ ] Given .story-time/taxonomy.json with named epics and features, when story group runs without --apply, then it prints a placement per open story (epic name, feature name, confidences, source jev or code) and writes no file (cargo test --locked --lib group::tests::dry_run_writes_nothing)
- [ ] Given a TypeSafe key, when story group runs, then each story costs one batched Jev request of choice questions (one epic question plus one feature question per epic, at most 16, each with a none_fit option) and the feature is read only from the chosen epic's question (cargo test --locked group::questions)
- [ ] Given a placement below --min-confidence (default 0.7) or a none_fit answer, when story group --apply runs, then the story is reported unresolved and left unchanged; a story already in a taxonomy epic is kept unless --reassign (cargo test --locked --lib group::placement group::tests)
- [ ] Given story group --apply, when it writes, then each placed story gains epic=<name>, feature=<name> and the changelog line set epic=..., feature=... — grouped by <engine> (epic p, feature p); if any write fails every written file is restored byte for byte (cargo test --locked group::saga)
- [ ] Given a GitHub tracker whose organization has Epic and Feature issue fields, when story push mirrors a story with epic and feature, then the issue gets labels epic:<name> and feature:<name> and the Epic and Feature field values, other field values are untouched, a cleared feature deletes its value, a missing option refuses naming story group --sync-fields, and an organization without the fields gets labels only (cargo test --locked --lib github_fields gateway::tests::github_push_mirrors gateway::tests::a_missing_epic_option gateway::tests::an_owner_without_issue_fields)
- [ ] Given an org admin token, when story group --sync-fields runs, then the organization gains single_select Epic and Feature fields whose options include every taxonomy name, existing options are kept by id and never deleted, and a second run makes no change (cargo test --locked --lib github_fields::tests::sync group::tests::sync_fields)
- [ ] Given an invalid taxonomy (duplicate names, over 15 epics, empty or over-50-character names), when story group runs, then it refuses naming the problem and writes nothing (cargo test --locked group::taxonomy)

## Out of Scope
- MCP story_group tool and a feature filter on story_list
- ADO Tags and Gitea mirroring of features
- User-owned repositories and deleting options for removed epics

## Test Plan
1. AC6 taxonomy: unit tests in group::taxonomy for valid parse and each refusal.
2. AC2 questions: unit tests in group::questions for count <= 16, none_fit, feature from chosen epic.
3. AC3 interpretation: unit tests for threshold, none_fit, kept vs --reassign.
4. AC4 saga: group::saga test injects a failing second write and asserts the first file is restored byte for byte.
5. AC1/AC3 CLI: src/group/tests.rs runs story group against the fake Jev server shared with judge: dry run writes nothing; --apply writes fields and changelog.
6. AC5/AC7 GitHub: github_fields unit tests with a recording GithubApi fake, and gateway tests with the compiled gh stub.
7. Real exercise: story group on this backlog and ask_jev on sampled varsity-core cards.
