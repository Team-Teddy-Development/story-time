## Story
As a maintainer, I want the native binary to answer an unknown command, --help, and -h exactly as the Node CLI does, so that story-time runs with no Node at all.

## Acceptance Criteria
- [x] Given no Node and no STORY_TIME_LEGACY_CLI, when the native binary runs an unknown command, --help, or -h, then its stdout, stderr, and exit code equal the Node CLI output for the same arguments, and main.rs no longer starts the Node CLI, verified by a native/story-push contract test

## Notes
Source: ST-060 (PR #197) report; confirmed on installed cea08eb: Node `story --help` prints `Unknown command "--help".` with usage on stderr and exit 2, native prints the legacy-required message. Every Node command is now native (the legacy-required message lists them all), so the Node fallback in main.rs serves only unknown commands. This story ends EP-001.

## Evidence
- Red 92d37b5: `unknown_commands_and_help_flags_match_node_without_node` got the legacy-required message with exit 1 where Node prints `Unknown command "no-such-command".`, a blank line, and the usage, exit 2; `the_native_binary_never_starts_a_node_cli` showed a fake `STORY_TIME_LEGACY_CLI` was spawned and printed `legacy`.
- Green fc2f3eb: `main.rs` prints `help::unknown_command(cmd)` (built from the embedded `usage.txt`) to stderr and exits 2 when no native command matches. The `STORY_TIME_LEGACY_CLI` / `runtime.json legacyCli` lookup and the `node` spawn are deleted, and so is `legacy_required_message()`. Node's unknown-command branch runs before flag parsing and config loading, so with an invalid config the unknown-command error wins in both.
- `unknown_command_contract.rs` compares Node and native (env_clear, PATH=/nonexistent) on stdout, stderr, and exit code for an unknown command, an unknown command with flags, `--help`, `-h`, and an invalid config; a second test sets `STORY_TIME_LEGACY_CLI` and `runtime.json legacyCli` to a fake CLI with node on PATH and requires Node-identical output. `legacy_dispatch.rs` and `native_command_message.rs`, which pinned the fallback, are deleted.
- Docs that had become false now say native `story` runs every command and needs no Node (AGENTS.md, README.md, skills/story-time/SKILL.md, references/planning.md, docs/native-story-push.md).
- Real repository: 6 argument sets (unknown, `--help`, `-h`, `frobnicate --json`, `help`, none) compared with Node, 0 differing.
- Limits: `story new --help` keeps its native create-help (Node exits 2); the installer still writes an unused `runtime.json legacyCli`.
- Checks on main 646ed0e: `cargo fmt --check` ok; clippy `-D warnings` ok; `cargo test --locked` 319 passed, 0 failed; `npm test` 464/464; `scripts/story-policy.rs` 12 passed; `test/story-policy-contract.rs` 11 passed.
