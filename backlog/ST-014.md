## Story
As a story-time maintainer, I want setup to save validated settings to my explicit config path, so that I can configure an isolated project without creating directories by hand.

## Acceptance Criteria
- [ ] Given a fresh directory and valid GitHub setup JSON, when init writes to an explicit config outside .story-time, then it exits zero, saves normalized settings, creates secret-ignore metadata, and config reads the same tracker coordinates.
- [ ] Given a canonical config path, defaults, or an existing settings file, when native init runs with the supported flags, then defaults and force/refusal behavior preserve the documented setup contract without Node.
- [ ] Given invalid JSON or settings, when native init runs, then it returns a diagnostic and creates or modifies no settings or metadata.
- [ ] Given the approved init execution chain, when the installed command is exercised, then init executes Rust implementation and regressions without a retained Node dispatch, while other commands retain their existing behavior.

## Steps to Reproduce
In a fresh scratch directory, run installed `story init --from answers.json --config settings.json --json` with valid GitHub answers and no runtime override. It exits 1 opening `.story-time/.gitignore` because that directory was not created. The same answers with `.story-time/settings.json` succeed.

## Expected
Setup validates answers before any write, creates required directories, writes the requested settings and preserves the secret-ignore rules. Init works without Node.

## Actual
Non-help init dispatches to retained Node. Its handler creates only the config parent before writing a different metadata directory.

## Out of Scope
Native conversion of config, new, set, lint, or other retained commands; changing tracker sync policy; changing native push behavior; generalized filesystem transactions; evaluator changes; unrelated legacy defects.
