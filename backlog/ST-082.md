## Story
As a maintainer, I want story machine and story table to print large integers the way Node does, so that model output matches on every input.

## Acceptance Criteria
- [x] Given a model file with an integer of 2^53 or more, when native story machine and story table print it, then the text equals the Node CLI output, verified by cases in machine_contract and table_contract

## Evidence
- Red 8755108: machine_contract printed `9007199254740992.0: OK ...` where Node prints `9007199254740992: OK ...`; table_contract printed `-9007199254740992.0: 1 defect` where Node reports OK.
- Green 1e441f3: new native/story-push/src/js_number.rs makes a parsed TOML integer the Number JavaScript holds (`number`), prints it as `String(n)` does (`to_string`), and serializes as `JSON.stringify` does (`stringify`, non-finite as null). toml_subset, config::js_string and js_value, models::out, table::stringify, and the machine ambiguity key use it. Machine ambiguous-group names round-trip through JSON like Node's `JSON.parse(key)`.
- New contract cases compare stdout, stderr, exit code, and fixture snapshot with Node for every action, with and without --json: table_contract::large_integers_match_node (9 cases: 2^53+1, 1e20, 1e21, +/-400-digit literals, 1.23e26, the 2^53 and 2^53+1 duplicate) and machine_contract::large_integers_match_node (10 cases including +/-Infinity transitions). Unit test js_number::tests::numbers_print_as_javascript_prints_them.
- Real data: the repository has no model/**/*.toml files, so there is nothing to compare (compared=0).
- Checks after rebase on main be22e10: cargo fmt --check clean; clippy -D warnings clean; cargo test --locked 235 passed, 0 failed (46 binaries); npm test 456/456; story-policy.rs 12 passed; story-policy-contract.rs 11 passed.
- Limits: +/-Infinity is stored as +/-5e-324 inside serde_json::Value because Value cannot hold a non-finite number; a settings value of exactly 5e-324 would print as Infinity. Settings integers above 2^53 and `1e400` still differ from Node (follow-up).
