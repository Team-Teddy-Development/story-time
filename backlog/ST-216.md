## Story
As a team whose network re-signs TLS with its own CA, I want native story's HTTPS client to trust the system certificate store as well as its bundled roots, so that story judge, story group and the Gitea gateway reach Jev and the tracker instead of failing with transport_error. Today reqwest uses rustls-tls (bundled webpki roots only), so in a proxied cloud session story judge falls back to code while curl to the same host returns 200.

## Acceptance Criteria
- [ ] Given a proxied session whose CA is in the system store and a TypeSafe credential, when TYPESAFE_API_KEY=proxy-injected story judge ST-214 runs, then the engine line reads jev and the story is not marked [fallback] (real CLI evidence)
- [ ] Given the change, when cargo test --locked runs, then every existing test passes, including the judge tests against the local fake Jev server (cargo test --locked --no-fail-fast)
