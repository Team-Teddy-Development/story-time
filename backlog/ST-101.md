## Story
As a maintainer, I want story init --config settings.json to work in Node as it does natively, so that both runtimes accept the same settings paths.

## Acceptance Criteria
- [x] Given an empty directory, when Node and native story init --config settings.json run on the same fixture, then both exit 0 and write the same files, verified by a native/story-push contract test

## Notes
Source: ST-095 (PR #205) report; confirmed on release 3f1d198: Node `story init --config settings.json` exits 1 with `ENOENT ... .story-time/.gitignore` (ensureGitignore writes into `<root>/.story-time` without creating it), while native creates the directory and succeeds (pinned by `explicit_path_beats_environment_and_custom_roots_are_relative_to_cwd`).

## Evidence
- Red 7478211: `a_config_outside_story_time_creates_the_metadata_directory_as_node_does` failed at its first case: Node exited 1 with `ENOENT: no such file or directory, open '.../.story-time/.gitignore'` while native exited 0.
- Green e205c3f: Node `init` runs `mkdir(join(ctx.root, CONFIG_DIR), { recursive: true })` before `ensureGitignore`, as native does. For `--config settings.json` both write `./settings.json` and `./.story-time/.gitignore`.
- `init_contract.rs` covers `settings.json`, `sub/dir/settings.json`, `custom/../settings.json`, and an absolute path, each with and without `--json`, comparing exit, stdout, stderr, and the file tree with modes; native runs with env_clear and PATH=/nonexistent.
- Checks on main 51efc76: `cargo fmt --check` ok; clippy `-D warnings` ok; `cargo test --locked` 323 passed, 0 failed; `npm test` 465/465; `scripts/story-policy.rs` 12 passed; `test/story-policy-contract.rs` 11 passed.
