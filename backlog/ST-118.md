## Story
As a maintainer merging pull requests, I want the MCP protocol tests to pass on every run, so that a timing race in a test never blocks a merge.

## Acceptance Criteria
- [x] Given the server stops reading after a request line passes 1 MiB, when the protocol test sends a line over 1 MiB, then the test still receives the -32600 Request exceeds input limit response and the exit code 0, with no panic from a broken pipe on the write, verified by running native/story-push tests/mcp_protocol.rs refused_reads_carry_their_error_codes_and_change_no_file 50 times with no failure

## Notes
Source: CI native-push on PR #257 (runs 43610123179 and its first attempt) failed twice with BrokenPipe at tests/mcp_protocol.rs:166 in refused_reads_carry_their_error_codes_and_change_no_file. Cause: the server stops reading once a line passes the 1 MiB input limit, as its contract allows, while the test is still writing the rest of the 1 MiB line. The write then fails with EPIPE, depending on timing. The server behavior is correct; the test must accept a closed pipe on that one write.

## Evidence
- Red: on main (e3f99a2), 40 parallel runs of `refused_reads_carry_their_error_codes_and_change_no_file` gave 11 failures, each panicking with BrokenPipe at `tests/mcp_protocol.rs:166`. That matches CI native-push on PR #257, which failed twice the same way.
- Fix (131ca09): a new `Server::oversized` test helper sends the >1 MiB line. It accepts only a BrokenPipe error on that write, then still asserts that the -32600 "Request exceeds input limit" response arrives, along with the existing exit code 0 and no-read-after-limit checks. Server code is unchanged.
- Criterion 1: after the fix, 0 of 50 sequential runs and 0 of 120 runs under the same parallel load failed.
- Checks on the rebased branch: fmt ok; cargo 71 binaries, 363 passed, 0 failed; npm pass 457 fail 0; story-policy 12 passed; contract 11 passed.
