## Story
As a Story Time reviewer, I want pull requests to use the same description structure, so that I can find the linked story, what changed, and verification evidence in a consistent place.

Out of scope: Changing merge rules or relying on the work item template decision.

## Acceptance Criteria
- [ ] Given a manually opened or Story Time-generated pull request in the Story Time repository, when the description is prepared, then it has exactly one leading `Stories:` line and consistent sections for the change and its verification.
