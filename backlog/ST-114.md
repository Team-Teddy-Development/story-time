## Story
As an agent filing stories in parallel, I want story new to never overwrite a story another process just created, so that no story is silently lost.

## Acceptance Criteria
- [ ] Given two story new processes that allocate the same id, when both save, then both stories survive under distinct ids, or the second fails with an error and the first file is unchanged, verified by a native/story-push test that races two creates

## Notes
Source: ST-006 spike (docs/spikes/ST-006-mcp-server.md), found by reading native/story-push/src/new_story.rs: it takes next_id and then list::save renames a temp file over <id>.md, so two concurrent creates can get the same id and the second replaces the first. Not reproduced yet; the criterion's race test reproduces it first. Prerequisite for ST-113.
