## Story
As an agent filing stories in parallel, I want story new to never overwrite a story another process just created, so that no story is silently lost.

## Acceptance Criteria
- [x] Given two story new processes that allocate the same id, when both save, then both stories survive under distinct ids, or the second fails with an error and the first file is unchanged, verified by a native/story-push test that races two creates

## Notes
Source: ST-006 spike (docs/spikes/ST-006-mcp-server.md), found by reading native/story-push/src/new_story.rs: it takes next_id and then list::save renames a temp file over <id>.md, so two concurrent creates can get the same id and the second replaces the first. Reproduced by the coordinator on 2026-11-14 with the installed story (release 6468a12-era): 50 pairs of concurrent story new runs in a files-tracker temp repo left 99 story files and 99 distinct titles out of 100 creates, so one story was silently replaced. Prerequisite for ST-113.

## Evidence
- Criterion 1: `native/story-push/tests/create_race.rs`. `concurrent_creates_never_replace_a_story` runs 10 rounds of 12 concurrent `story new` processes (PATH=/nonexistent) and asserts all 120 titles survive under distinct ids. `a_split_racing_creates_never_replaces_a_story` races one `split` against 12 `new` per round and asserts no story is replaced and a failed split leaves no child files.
- Red (a91bab7): on the old code the new-race test kept 55 of 120 titles ("every concurrent story new kept its own story file").
- Green (071c1a5): `list::create` publishes with `fs::hard_link`, which fails with AlreadyExists instead of replacing; `story new` retries with the next id; `split` children use `list::create` and roll back on a taken id. `save` keeps rename-over for updates. adopt already used create_new plus hard_link.
- 4b65f5c: the race test removes its temp folders through a Drop guard, so a failed assertion leaves nothing in /tmp.
- Checks on the rebased branch: cargo fmt ok; clippy -D warnings clean; cargo test 70 binaries, 350 passed, 0 failed; npm test pass 457 fail 0; story-policy 12 passed; story-policy-contract 11 passed.
- Real data: Node and native `new` and `split` on scratch copies of this backlog gave identical stdout and byte-identical backlog trees (2 commands, 0 differences). Deliberate difference: only during a race, where Node replaces the other story and native keeps it.
