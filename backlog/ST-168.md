## Story
As the operator of a local coding-agent loop, I need verified execution ownership so that terminated agents do not block progress and live agents do not receive duplicate assignments. Supersedes archived preparation ST-167, whose statement-format failure remains recorded. Scope: native story assignment next, heartbeat, reconcile and release commands plus story-pick instructions. Reuse ranking and configured WIP. Verify real CLI concurrency across linked worktrees, exact process identity, stale-token rejection and partial-work preservation with cargo test --test assignment_contract. Non-goals: modifying Cartographer core or its admission rules, automatically releasing unknown legacy owners, hosted scheduling, deployment, or deleting work.

## Acceptance Criteria
- [ ] Given ready ranked stories, completed dependencies and free WIP capacity, when local agents concurrently claim the next story, then each slot has one valid owner and selection follows existing ranking.
- [ ] Given a recorded owner whose exact local process has terminated, when assignment reconciliation runs, then the old token is invalidated and its story is recoverable without deleting work or changing acceptance status.
- [ ] Given live or uncertain ownership, or legacy in-progress work with no verified owner, when selection runs, then it preserves that work and reports why assignment is blocked.
- [ ] Given a replaced or released token, when its former owner sends a heartbeat or release, then the command fails without changing the current owner; CLI tests and story-pick instructions verify the full recovery path.
