## Story
As a maintainer, I want adopt preview to skip or classify epic map files, so that a backlog that holds EP-xxx.map.md files can be adopted without a false conflict.

## Acceptance Criteria
- [x] Given a backlog directory that holds stories and an EP-001.map.md epic map, when native story adopt preview runs, then the map file is not reported as unsupported_story and the preview status is not conflict because of it, verified by a native/story-push contract test

## Notes
Source: ST-085 (PR #182) real-backlog run. `adopt preview` on this repository reports `unsupported_story` for backlog/EP-001.map.md and backlog/EP-002.map.md, so status is conflict. Node parseStory also refuses these files. Deciding whether maps move out of backlogDir or adoption skips them is part of this story.

## Evidence
- Red e5d5323: `epic_map_files_are_retained_non_story_files_not_conflicts` failed with exit 2 and `unsupported_story` for `work/EP-001.map.md`.
- Green dbb3c3b: `Inventory::files` records a `*.map.md` file as `{kind: epic_map, sha256, bytes}` after recording its preimage, and does not parse it as a story. This is the rule planning already uses (`planning.rs`, `!path.ends_with(".map.md")`) and that `references/planning.md` documents ("Map files do not become stories").
- The test also checks the map's preimage sha256 and byte count, and that a malformed `PAY-002.md` beside it is still `unsupported_story`. `allowed_writes` still holds only the two lifecycle creates, so the map bytes are never written.
- Real backlog (read-only, PATH=/nonexistent): before, exit 2 `conflict` with `unsupported_story` for EP-001.map.md and EP-002.map.md; after, exit 0 `preview`, 96 files, 0 diagnostics.
- Limit: the rule is the filename suffix only, as in planning.
- Checks: `cargo fmt --check` ok; `cargo clippy --locked --all-targets -- -D warnings` ok; `cargo test --locked` 316 passed, 0 failed (main 75b1212); `npm test` 461/461; `scripts/story-policy.rs` 12 passed; `test/story-policy-contract.rs` 11 passed.
