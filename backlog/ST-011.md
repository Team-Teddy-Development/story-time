## Story
As a story-time maintainer, I want to inspect a graph of stories and their links, so that I can see dependencies and connected work.

## Acceptance Criteria
- [ ] Given an authorized repository with story dependencies and epic membership, when its graph is synchronized to Neo4j, then each story has a repository-scoped identity and its declared links appear as typed, directed edges.
- [ ] Given an existing graph and changed or removed story links, when synchronization runs again, then the graph matches the current backlog without duplicate nodes or stale edges.
- [ ] Given a story identifier, when an MCP client requests its graph, then it receives labeled nodes and typed edges with story IDs, titles, status, and available issue URLs for displaying the links.
- [ ] Given an empty backlog or a story with no links, when an MCP client requests its graph, then it receives an empty graph or an isolated node respectively.
- [ ] Given unauthorized repository access or an unavailable Neo4j service, when a graph tool runs, then it returns a typed failure without exposing credentials or changing story files.

## Notes
Requested intake: add Neo4j graph capabilities to the story-time MCP so stories and their links can be inspected. Extend the MCP boundary selected by ST-006 and delivered through ST-007; do not create a competing server.

Markdown stories and their configured frontmatter remain the source of truth. Neo4j is a rebuildable projection. Begin with declared `depends_on` and epic membership; show directed, labeled links, not inferred relationships. Scope identities by repository so identical story IDs in separate repositories cannot collide.

Before readiness, define the graph tool names and bounded query contracts, projection refresh behavior, missing-reference handling, relationship direction, and the client used to display the returned nodes and edges. A graph payload for an MCP client is in scope; a separate dashboard is not. Confirm the Neo4j instance, database, and approved secret binding without storing credentials in stories.

Size and value scores remain unset. This is a draft feature request, not implementation or deployment authorization. ST-007 is the direct prerequisite; ST-006 is its existing design dependency. The existing repository sync setting is preserved; every story change is explicitly published with `story push`.

## Out of Scope
Implement the graph during intake, build a standalone graph UI, infer undeclared links with AI, make Neo4j authoritative for story edits, change tracker synchronization policy, provision production Neo4j, or convert unrelated CLI paths.

## Verification plan
Use native Rust unit and MCP protocol tests for repository-scoped identities, directed dependency and epic edges, repeat synchronization, changed and removed links, empty and isolated graphs, invalid references, authorization, bounded queries, and sanitized Neo4j failures. Exercise a real MCP client against an authorized test Neo4j database, compare the graph with fixture story files, follow returned issue links, and record the source revision and observed graph output.

## Rust conversion gate
At implementation, audit the approved MCP graph execution chain and record each implementation's language, role, and conversion status. Keep the gate UNMET until active in-scope MCP tools, Neo4j adapters, projection logic, and tests are native Rust. Preserve historical non-Rust evidence and name unrelated conversion targets as out of scope. This intake adds documentation only.
