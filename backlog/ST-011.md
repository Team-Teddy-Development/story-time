## Story
As a story-time maintainer, I want to inspect a graph of stories and their links, so that I can see dependencies and connected work.

## Acceptance Criteria
- [x] Given an authorized repository with story dependencies and epic membership, when its graph is synchronized to Neo4j, then each story has a repository-scoped identity and its declared links appear as typed, directed edges, verified by a native/story-push test against a disposable local Neo4j container
- [x] Given an existing graph and changed or removed story links, when synchronization runs again, then the graph matches the current backlog without duplicate nodes or stale edges, verified by a native/story-push test against a disposable local Neo4j container
- [x] Given a story identifier, when an MCP client requests its graph, then it receives labeled nodes and typed edges with story IDs, titles, status, and available issue URLs for displaying the links, verified by a native/story-push protocol test against a disposable local Neo4j container
- [x] Given an empty backlog or a story with no links, when an MCP client requests its graph, then it receives an empty graph or an isolated node respectively, verified by a native/story-push protocol test against a disposable local Neo4j container
- [x] Given unauthorized repository access or an unavailable Neo4j service, when a graph tool runs, then it returns a typed failure without exposing credentials or changing story files, verified by a native/story-push protocol test with a stopped container and a repository key that is not allowlisted, where no stderr or result contains the configured password

## Notes
ST-006 spike input (docs/spikes/ST-006-mcp-server.md): repository identity from the story_config tracker target, else a hash of the root path; opt-in launch flag adding story_graph_sync and story_graph, depth limit 3, node limit 200; missing dependency becomes a node with missing:true; edges DEPENDS_ON and IN_EPIC; each sync replaces one repository's projection in one transaction. Open: Bolt or HTTP query API, a neo4j secret provider, and the instance and database (owner input). Consider splitting a Markdown-only graph payload ahead of the Neo4j inputs.
Requested intake: add Neo4j graph capabilities to the story-time MCP so stories and their links can be inspected. Extend the MCP boundary selected by ST-006 and delivered through ST-007; do not create a competing server.

Markdown stories and their configured frontmatter remain the source of truth. Neo4j is a rebuildable projection. Begin with declared `depends_on` and epic membership; show directed, labeled links, not inferred relationships. Scope identities by repository so identical story IDs in separate repositories cannot collide.

Before readiness, define the graph tool names and bounded query contracts, projection refresh behavior, missing-reference handling, relationship direction, and the client used to display the returned nodes and edges. A graph payload for an MCP client is in scope; a separate dashboard is not. Confirm the Neo4j instance, database, and approved secret binding without storing credentials in stories.

Size and value scores remain unset. This is a draft feature request, not implementation or deployment authorization. ST-007 is the direct prerequisite; ST-006 is its existing design dependency. The existing repository sync setting is preserved; every story change is explicitly published with `story push`.

## Out of Scope

## Evidence
- All criteria run against a disposable `neo4j:5.26.30-community` container that each test starts with a unique name and removes with `docker rm -f -v` (tests skip with `SKIP:` when docker is unavailable).
- Criterion 1: `tests/mcp_graph.rs` `sync_projects_repository_scoped_stories_and_typed_directed_edges`. Three roots (github, gitea, path hash) hold the same ST-001 and ST-002. Each gets its own identity (`github:example/one`, `gitea:gitea.test:3000/team/two`, `path:<sha256>`), exact nodes and directed `DEPENDS_ON`/`IN_EPIC` edges, a `missing: true` node for an absent dependency, and three separate ST-001 nodes.
- Criterion 2: `resync_after_changed_and_removed_links_matches_the_backlog` changes, removes and duplicates links, moves an epic and deletes a story, then syncs twice. The full Neo4j dump equals the expected set both times.
- Criterion 3: `story_graph_returns_labeled_nodes_and_typed_edges_within_bounds` checks labels, ids, titles, status and `remote_url`, depth 2 excluding distance-3 nodes, missing nodes, `limit` truncation, `invalid_argument` for depth 4 or limit 201, and `story_not_found`.
- Criterion 4: `story_graph_of_an_empty_backlog_or_unlinked_story`.
- Criterion 5: `graph_failures_are_typed_and_never_expose_the_password`. A repository key that is not allowlisted gives `repository_not_allowed` for both tools, a wrong password gives `graph_auth_failed`, and a stopped container gives `graph_unavailable` (retryable). The password is absent from results, stdout and stderr, and the fixture byte snapshot is unchanged.
- Also: `graph_tools_appear_only_with_the_graph_flag` (and, after the Jev review, that only the graph tools report `openWorldHint: true`, commits 6506f83 red and 81ebb6d green); `graph_launch_refuses_an_unset_password_variable_without_echoing_values`.
- Real data: a scratch copy of this backlog synced into a disposable container with `PATH=/nonexistent` gave 122 stories, 2 epics, 67 `DEPENDS_ON` and 56 `IN_EPIC` edges, equal to `story list --json`; a second sync gave the same counts.
- Checks on the rebased branch (main f4953ba): fmt ok; clippy clean; cargo 75 binaries, 386 passed, 0 failed; npm pass 457 fail 0; story-policy 12 passed; contract 11 passed.
- Installed release cdb3a1d (`story-install`, fresh target directory), driven over MCP stdio with `env -i PATH=/nonexistent` against a disposable Neo4j container on a copy of this backlog: `story_graph_sync` twice gave 125 stories, 70 `DEPENDS_ON`, 56 `IN_EPIC`, 2 epics, 0 missing, equal to `story list --json`; `story_graph {id: ST-011, depth: 2}` returned ST-011, ST-111, ST-006 and ST-112 with 3 `DEPENDS_ON` edges; the password appeared 0 times in stdout and stderr; story file hashes were unchanged.
