## Story
As a maintainer of an existing project, I want a versioned read-only adoption preview, so that I can review preservation rules and conflicts before changing my backlog.

## Acceptance Criteria
- [ ] Given current or legacy settings and an existing flat-file backlog, when adoption preview runs, then it reports source version, target metadata version1, config and backlog identities, exact preimages and ordered allowed writes without changing project or tracker state.
- [ ] Given custom fields, closed records and missing sprint data, when preview inventories the backlog, then it retains each original identity and reports preservation rules and unknown history without inventing goals, capacity, epic links or events.
- [ ] Given duplicate IDs, unsupported nested formats, unknown versions, unsafe paths, source conflicts or tracker-only input without an import contract, when preview runs, then it reports each conflict and its recovery or export/import action without offering successful apply.
- [ ] Given story-setup and the native preview command, when the disposable installation and Rust process tests run, then new/adopt/upgrade detection reaches one preview owner and existing init behavior remains unchanged.
