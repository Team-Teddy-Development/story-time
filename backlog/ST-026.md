## Story
As a story-time maintainer, I want a chore with exactly one acceptance criterion to reach ready without an estimate, so that the documented rule that a one-criterion chore needs no estimate holds when story set marks it ready.

## Acceptance Criteria
- [ ] Given a chore with exactly one acceptance criterion and no size, when story lint checks it, then size.estimated reports no finding and the story is ready when no other rule reports an error.
- [ ] Given a chore with two acceptance criteria and no size, when story lint checks it, then size.estimated reports the error "Not estimated. Run story-estimate."
- [ ] Given a story of type story with one acceptance criterion and no size, when story lint checks it, then size.estimated reports the error "Not estimated. Run story-estimate."

## Steps to Reproduce
In a scratch backlog, run `story new --type chore --title "Bump a pinned tool" --ac "Given the pinned version, when CI runs, then it uses version 2."`, then `story set X-001 status=ready`.

## Expected
The one-criterion chore becomes ready without a size. A chore with two or more criteria, and every other non-spike type, still needs a size.

## Actual
`story set` exits 1 with `size.estimated: Not estimated. Run story-estimate.` The `size.estimated` rule in `skills/story-time/scripts/src/domain/invest.mjs` exempts only spikes. Downstream, essentials-core CLAUDE.md states "a one-criterion chore needs no estimate", and essentials-core EC-218 hit this refusal.

## Out of Scope
- `value.scored` and WSJF ranking. An unsized chore stays unranked by `story rank`.
- Size rules for split parents (ST-024).
- Converting the lint to Rust.

## Notes
Docs that state the rule (story-ready, story-estimate, backlog-groom) are updated to match.
