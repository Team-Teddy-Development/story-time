## Story
As a team maintainer who uses Bitbucket Cloud, I want to keep my Story Time backlog in the repository and review story changes in pull requests, so that my team can use its existing review process without moving the backlog.

Out of scope: Bitbucket Data Center, Jira issue synchronization, and automatic pull request merges.

## Acceptance Criteria
- [ ] Given a registered Bitbucket Cloud repository with a Story Time backlog on its default branch, when a reader calls `story_list` or `story_show`, then Story Time returns the requested backlog data from that branch.
- [ ] Given a registered Bitbucket Cloud repository and a caller with write access, when the caller uses `story_create`, `story_update`, or `story_note`, then Story Time returns a Bitbucket pull request URL for the proposed change and leaves the default branch unchanged.
- [ ] Given an open Bitbucket pull request for a story edit, when a reader calls `story_show` for that story, then Story Time shows the proposed change separately from the default-branch version.
- [ ] Given a caller without write access, when the caller attempts to change a story in a registered Bitbucket Cloud repository, then Story Time refuses the write without creating a branch or pull request.
