## Story
As a maintainer, I want native push to read a flag value that starts with -- the way Node parseArgs does, so that push and every other command parse arguments the same way.

## Acceptance Criteria
- [x] Given push --dir --x and the same arguments to the Node CLI, when each parses them, then both read --x as the dir value and give the same stdout, stderr, and exit code, verified by a native/story-push contract test

## Notes
Source: ST-086 (PR #185) agent report. Push has its own argument parser in native/story-push/src/lib.rs `parse`, which rejects `--dir --x` with "Flag --dir needs a value." Node parseArgs takes any next argument as the value.

## Evidence
- Red 8659047: `push_flag_contract` failed with native `Flag --dir needs a value.` exit 2 where Node read `--x` as the dir and printed a plan with exit 0.
- Green ccc803a: push's own `Args`/`parse` is deleted; push, issues, context, and plans use `config::Flags`, which matches Node parseArgs.
- The contract test compares Node and native (env_clear, PATH=/nonexistent) on stdout, stderr, and exit code for 7 argument lists, including `--dir --x`, `--dir=x`, an unknown flag, `--all` with IDs, a missing value, and no IDs.
- Behavior now matching Node: an unknown push flag takes the next argument; `--all` with IDs pushes all. Kept on purpose: an empty `push --all` exits 0 (the documented es_9c55035c0ff8 fix). The `push --all ST-001` exit-2 row in tests/cli.rs was native-only and was removed.
- Real backlog copy: 98 push dry-runs compared with Node, 0 differing.
- Checks: `cargo fmt --check` ok; `cargo clippy --locked --all-targets -- -D warnings` ok; `cargo test --locked` all suites ok, 0 failed; `npm test` 461/461; `scripts/story-policy.rs` 12 passed; `test/story-policy-contract.rs` 11 passed.
- Review follow-up (Jev concern lost_guards 0.98): red 7bdead6 / green e4753fd restore two push refusals in BOTH Node and native, with the same text and exit 2, before any tracker call: `Unknown push flag --NAME.` and `Use --all or explicit story IDs, not both.` Native keeps `config::Flags` (new `names()` keeps first-seen order). `push_flag_contract` asserts the exact stderr; `cli-push.test.mjs` adds 3 Node tests with the fake tracker asserting no tracker call. npm test 464/464; cargo test 316 passed. Real backlog copy: 6 command lines, 5 equal; the one difference is the documented empty `push --all` exit-0 fix (es_9c55035c0ff8).
