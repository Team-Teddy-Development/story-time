## Story
As a story-time maintainer on Azure DevOps, I want two pushes that change different tags on one work item at the same time to keep both changes, so that neither push overwrites the other's tags.

## Acceptance Criteria
- [x] Given two story push runs that change different story-time tags on one Azure DevOps work item at the same time, when both finish, then the work item carries both changes and any tag story-time does not manage, verified by a native/story-push test with a stub az CLI

## Out of Scope
GitHub and Gitea labels (ST-039). Two pushes that change the same tag in opposite directions.

## Notes
Source: ST-039 implementation report. native/story-push/src/gateway.rs sends `--fields System.Tags=...` for ADO, which replaces the whole tag set, so a concurrent tag edit can be lost. A fix needs read, merge, and a write guarded by the work item revision (System.Rev). Affected command: story push with tracker ado.

## Evidence
- Cause: the ADO update sent `--fields System.Tags=...`, which replaces the whole tag set.
- Red 56d8550: `two_pushes_that_change_different_ado_tags_at_once_both_keep_their_change` (tests/concurrent_ado_tags.rs) runs two real `story push` binaries against a rustc-compiled stub `az` that keeps rev and tags in a state file, enforces the JSON Patch `test` on `/rev`, and holds both `work-item show` reads until both arrive. Start tags: story-time; ST-001; epic:EP-1; team. Final tags were {ST-001, epic:EP-2, story-time}: `chore` and the foreign `team` tag were lost.
- Green 6bd6883: the field update no longer carries System.Tags. `merge_ado_tags` reads rev and tags, computes this push's adds and stale story-time drops once from that read, and writes `[test /rev, add /fields/System.Tags]` through `az devops invoke ... --media-type application/json-patch+json`. On a failed write with a changed rev it reapplies the same change to the fresh tags, up to 5 attempts; with an unchanged rev it returns the error. Final tags {story-time, ST-001, epic:EP-2, chore, team}, with at least one revision conflict observed.
- Checks after rebase on main d37db21: cargo fmt --check clean; clippy -D warnings clean; cargo test --locked 119 passed, 0 failed (25 binaries); npm test 431/431; story-policy.rs 12 passed; story-policy-contract.rs 11 passed.
- Limit: verified only against the stub az. The `az devops invoke` argument names, the non-zero exit on a failed `/rev` test, and `rev` in `show --fields` output are not checked against live Azure DevOps (az is not installed here).
- Found while verifying: the Node tests leak temp directories; filed as ST-070.
