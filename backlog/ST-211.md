## Story
As a maintainer, I want every audit-log assertion in tests/mcp_http.rs to hold when the stderr reader thread receives a line after the HTTP answer, so that native-push neither fails at random on a correct server nor passes when a refused request wrongly ran a tool.

## Acceptance Criteria
- [ ] Given a delay injected in the test harness's stderr reader thread, when cargo test --locked --test mcp_http runs, then every test that reads the audit log passes, where before the fix the positive checks fail (for example left 0, right 1 at the one-tool-call count, and the missing linker line)
- [ ] Given a delayed reader and a tool call that ran before a no-tool-ran check (an injected wrong run), when that check runs, then it fails, where before the fix it passed
- [ ] Given no injected delay, when cargo test --locked runs in native/story-push, then all tests pass, with no assertion weakened and no server code changed

## Steps to Reproduce
1. In `native/story-push/tests/mcp_http.rs`, add a short sleep in the stderr reader thread before it pushes each line into `log`.
2. Run `cargo test --locked --test mcp_http` in `native/story-push`.

## Expected
Every audit assertion waits for the lines it depends on: positive checks pass, and a check that no tool ran would still see a tool that wrongly ran.

## Actual
`a_marked_client_gives_its_token_in_the_path_and_no_other_client_can` fails with left 0, right 1 at the one-tool-call count, and its "linker" log check can fail. The "no tool ran" checks read the log before late lines arrive, so they pass even when a tool ran.

## Out of Scope
- Server code and the audit line format.
- Audit reads already guarded by `audit_when` (ST-159, PR #480).

## Notes
- Source: PR #480 (commit a41ffcf) fixed the baseline in `a_header_that_does_not_match_the_body_gets_minus_32020` and queued the other unguarded reads as a follow-up. Same race as ST-159.
- Unguarded reads at a41ffcf: line ~306 (`no tool ran`), ~347 (one tool call ran), ~380-384 (no refused request ran a tool), ~385-391 (token absent, "linker" named), ~574-578 (a refused request runs no tool).
- Approach: positive checks wait with `audit_when`; "nothing ran" checks send a known-good sentinel call after the refusals and wait for its line. The server writes each line before it answers and the reader keeps stderr's order, so every earlier line has arrived.
