## Story
As a team lead, I want refined stories surfaced as a review queue and flagged when they wait too long, so that a story that failed its readiness check gets reviewed again instead of stranding.

## Acceptance Criteria
- [x] Given refined stories that entered refined on different dates, when `story rank` runs without flags, then it lists them in a refined review queue, oldest first, with the days each has spent in refined, and the JSON output carries the same queue.
- [x] Given a refined story whose last `set status=refined` is older than the configured limit (default 7 days), when `story lint` runs, then it reports a `refined.stale` warning naming the age; and a story inside the limit, or not refined, gets no such warning.
- [x] Given the story-ready, refinement and story-time skills, when an agent reads them, then story-ready and refinement backlog mode take the refined queue first and either promote each story to ready or name its remaining gap, and the story-time lifecycle section names the refined queue.

## Out of Scope
- The ess-ai-control-plane story-groom skill, which is patched separately.
- Changing the Node legacy CLI. Rank parity tests keep comparing the ranked and excluded output with Node and exclude only the new native queue.

## Test Plan
1. AC1: new Rust integration test `refined_queue` runs the built `story rank` and `story rank --json` over refined stories whose `set status=refined` lines are 30, 10 and 2 days old, one refined story with no event, and a ready story. It asserts the literal queue order and ages in both forms. `rank_contract` still passes against Node for the ranked and excluded output.
2. AC2: `refined_queue` runs the built `story lint --json`. The 10-day and 30-day stories carry a `refined.stale` warning with the literal message; the 2-day refined story and the ready story carry none. `team.refinedStaleDays: 20` in settings removes the 10-day warning and keeps the 30-day one. A non-positive `team.refinedStaleDays` fails config validation.
3. AC3: `refined_queue` reads the story-ready, refinement and story-time SKILL.md files and asserts each names the refined review queue, and that story-ready and refinement take it before other work.

Run Cargo from `native/story-push` with `--locked` through `heavy`, then `npm test` and the story-policy Rust tests.
