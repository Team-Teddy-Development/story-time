## Story
As a maintainer, I want settings validation to reject a prefix that is not a string, so that native commands that read the prefix as text do not fail later.

## Acceptance Criteria
- [x] Given settings whose prefix is a list such as ["ST"], when the native binary runs story config, then it exits 1 and names prefix, verified by a case in native/story-push/tests/config_agreement.rs

## Evidence
- Red 497c695: config_agreement failed `config accepts prefix is a list` (exit 0, expected 1): native read `["ST"]` through `String(value)` as "ST" and accepted it.
- Green 03ad151: config::parse reads prefix through the shared `text` helper, so a non-string prefix fails with an error that names `prefix` in config, push, plan, and init. Cases added to config_agreement.rs and config_contract.rs.
- Checks after rebase on main be22e10: cargo fmt --check clean; clippy -D warnings clean; cargo test --locked 232 passed, 0 failed (46 binaries); npm test 456/456; story-policy.rs 12 passed; story-policy-contract.rs 11 passed.
- Real data: this repository's prefix is the string "ST"; the change rejects only non-string values.
