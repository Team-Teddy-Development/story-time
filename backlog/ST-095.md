## Story
As a maintainer, I want native story init to read flag values the way Node parseArgs does, so that init and every other command parse arguments the same way.

## Acceptance Criteria
- [x] Given init --from --x where --x is a settings file, when native and Node story init run on the same fixture, then both read --x as the --from value and give the same stdout, stderr, exit code, and written files, verified by a native/story-push contract test

## Notes
Source: ST-091 (PR #195) report; confirmed on installed cea08eb: `story init --from --x` gives native rc 2 `Flag --from needs a value.` while Node rc 0. `init.rs` `Init::parse` filters values starting with `--` and rejects unknown flags; migrate it to `config::Flags` and keep the help handling in docs/setup-help-verification.md.

## Evidence
- Red 5678be5: `a_flag_value_that_starts_with_dashes_is_read_as_node_reads_it` failed for `init --from --x --json` (Node exit 0, native exit 2 `Flag --from needs a value.`); `unknown_flags_and_positionals_are_ignored_as_node_ignores_them` failed for `--zzz value --json` (native `Unknown init argument --zzz.`).
- Green 50ae1a6: `init.rs` deletes `Init`/`Init::parse` and reads `config::Flags`. Help prints only for the exact forms `init --help` and `init -h` (docs/setup-help-verification.md; setup_contract 3/3), as Node does; elsewhere `--help` is a value flag and `-h` a positional, as in Node.
- `init_contract.rs` `same_as_node` runs Node, rebuilds the fixture at the same path, runs native (env_clear, PATH=/nonexistent), and compares exit code, stdout, stderr, and the written tree with modes for `--from --x`, `--from --x --json`, `--config --y/.story-time/settings.json --from --x`, `--zzz value`, `extra`, `-h --json`, `--help value`, `--from answers.json --help`, and missing values. The old native-only test that let `--from missing.json --help` succeed was replaced, because Node exits 2 there.
- Limit: Node `init --config X` fails when X is not under a `.story-time/` folder (ENOENT on `.story-time/.gitignore`), where native succeeds; the test uses a `.story-time` path.
