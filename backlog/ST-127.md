## Story
As a story-time maintainer, I want the new_contract git fixture to start no background git maintenance, so that its template copy cannot panic on a vanishing lock file.

## Acceptance Criteria
- [x] Given the new_contract git fixture helper, when a fixture commit runs with GIT_TRACE2 set, then the trace names the commit and no git maintenance process, verified by cargo test --test new_contract

## Notes
Source: ST-125 (cause found 2026-11-15). Git 2.56 starts `git maintenance run --auto --detach` after each commit; the detached child holds `.git/objects/maintenance.lock` for 1 to 3 ms after the commit returns. `native/story-push/tests/new_contract.rs` builds a git template with its own `git` helper and copies it with `copy_tree` (lines 67 to 92 and 195). Its comparison skips `.git`, but `copy_tree` can still panic on ENOENT if the lock vanishes mid-copy. Same fix as ST-125: pass `-c maintenance.auto=false` in the fixture helper. Also in scope: give the `split_contract.rs` `children_skip_ids_reserved_on_other_branches` base directory a Drop guard, because a failing run leaks it (`/tmp/story-split-git-2836640-1` survived the 2026-11-14 failure).

## Evidence
- Red: commit b4618cd adds `fixture_commits_start_no_background_maintenance` to `native/story-push/tests/new_contract.rs`; `cargo test --locked --test new_contract fixture_commits` failed at the `!log.contains("git maintenance")` assertion (line 217).
- Green: commit 32826a7 passes `-c maintenance.auto=false` in the fixture helper; `cargo test --locked --test new_contract`: 6 passed, 0 failed.
- Full checks: `cargo fmt --check` ok; `cargo clippy --locked --all-targets -- -D warnings` clean; `cargo test --locked` 75 binaries, 389 passed, 0 failed; `npm test` 457 pass, 0 fail.
- The leaked-directory note does not apply here: `Sandbox` already removes its root in `Drop`. The leak in `split_contract.rs` `children_skip_ids_reserved_on_other_branches` is outside this story's criterion and is left as is: the ST-125 fix removes the race that made it fail.
