## Story
As a story-time maintainer, I want the hosted story-time MCP to serve Team-Teddy-Development/story-time in its own org, so that agents read and edit the story-time backlog through the server and its ST stories stay apart from the ST stories of varsity-core.

## Acceptance Criteria
- [ ] Given the deployed server with the new registry, when a client calls story_repos, then it lists story-time with the org team-teddy and the state ready, and the three varsity repositories with the org varsity
- [ ] Given the deployed server, when a client calls story_show for ST-141 in story-time, then it returns the story with the title of the multi-org story

## Notes
Source: the owner installed the GitHub App `story-time-mcp` on `Team-Teddy-Development` (all repositories) and on `jejernig` on 2026-11-16. ST-141 made several orgs possible.

Scope: one image of `main` with ST-141, one registry entry in coffee-apps (`k8s/story-time/25-configmap.yaml`), one `cc_deploy`. The org name is `team-teddy`.

Not in this story: `xanthos` (its tracker is Gitea; ST-140), and repositories of `jejernig` (none has story-time settings on 2026-11-16). Each client token still reads every registered repository (ST-142); the only token is the owner's.
