## Story
As a maintainer of an existing project, I want reviewed adoption with verified backup and recovery, so that I can upgrade local lifecycle metadata without losing existing work.

## Acceptance Criteria
- [ ] Given a reviewed version1 preview and matching source preimages, when adoption applies under the repository lock, then it verifies a mode600 non-secret byte backup before mutation and preserves story IDs, links, custom fields, dependencies, estimates, statuses, closed records, criteria, evidence and settings unless the plan names an explicit reviewed mapping.
- [ ] Given successful adoption, when apply and verify run again with the same migration version, then every file and receipt identity remains unchanged and no tracker issues or labels are written.
- [ ] Given an interruption before or after any journaled write, when recovery resumes, then preimage/postimage checks identify completed and pending steps without losing the backup or unrelated edits.
- [ ] Given stale inputs, unsafe paths, a concurrent writer, unsupported capabilities or diverged rollback bytes, when apply or reverse rollback runs, then it stops with the exact conflict and recovery action while preserving recoverable data and unrelated changes.
- [ ] Given legacy stories with missing goals, capacity, epic links or history, when adoption verifies, then missing data remains explicit and terminal stories remain unchanged without new readiness or acceptance gates.
- [ ] Given new-project, adopt-existing and upgrade-existing routes, when the actual Rust command and disposable skill installation run, then all use the reviewed contract and existing init behavior remains unchanged with no non-Rust migration implementation.
