## Story
As a maintainer, I want native push to send ADO descriptions with the same HTML as Node, so that work items do not gain stray newlines.

## Acceptance Criteria
- [x] Given a story with several paragraphs and tracker ado, when native push builds the work item description, then the HTML equals Node's toHtml output with paragraphs joined by an empty string, verified by a native/story-push test against story::to_html

## Evidence
- Red 83fd2b1: `gateway::tests::ado_description_matches_node_gateway_content` failed. Native joined paragraphs with a newline (`<p>First line<br>second</p>\n<p>Next &lt;p&gt;</p>...`) where Node's AdoBoardsGateway.content() joins them with an empty string. Expected values were taken from running Node's gateway.
- Green ad2b64a: gateway.rs deletes its own `html`/`to_html` copy and uses `story::to_html`, which already matched Node's toHtml. It also sends `--description <p></p>` for an empty description, as Node does (`toHtml("")` is truthy). The test asserts the description argument equals `story::to_html(description)` and Node's output, including the empty case.
- Real data (scratch copies with an ADO config): `export --format ado` with and without --command for all 82 stories, compared=164 differing=0. `push --all` against a stub `az` with a fake PAT: 28 calls each; they differ only in the `ST-xxx:` title prefix that ST-015 added on purpose, and with that prefix removed differing=0.
- Checks after rebase on main b26c247: cargo fmt --check clean; clippy -D warnings clean; cargo test --locked 279 passed, 0 failed (50 binaries); npm test 461/461; story-policy.rs 12 passed; story-policy-contract.rs 11 passed.
- Limit: no real story has an empty description, so only the unit test covers it; only creates were compared, because native updates merge ADO tags by design.
