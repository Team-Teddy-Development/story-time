## Story
As a story-time maintainer, I want story judge to run in the native Rust binary, so that the judgement checks works without Node and the retained Node CLI shrinks.

## Acceptance Criteria
- [x] Given a fixture backlog and no Node or STORY_TIME_LEGACY_CLI, when the native binary runs story judge with the arguments its Node version accepts, then its stdout, exit code, and file changes match the Node CLI on the same fixture, verified by a native/story-push contract test

## Out of Scope
Changing the command's behavior or output. Converting other commands.

## Notes
Source: ST-036 (Rust conversion plan, epic EP-001, map backlog/EP-001.map.md). Slice: Rest. Constitution Article VIII requires Rust for replacement implementations. Today native/story-push/src/main.rs runs init, push, adopt, and plan natively and passes every other command to skills/story-time/scripts/story.mjs.

## Evidence
- Red 428dcc0: all 3 judge_contract tests failed; native stdout was empty (judge not in the dispatch table) where Node printed `engine: code (no TypeSafe key; ...)` and the judgements.
- Green 9e9d5c0: native/story-push/src/judge.rs ports CodeDecisionEngine, engine selection (STORY_TIME_JEV kill switch, then TYPESAFE_API_KEY, then the stored .jev.env key), the Jev questions and state, and the Jev client (egress scan, contradiction canary, retries with server hints, auth latch, strict decoding, refused redirects, fallback to the code engine), plus text and --json output. `judge` is one NATIVE_COMMANDS entry; secret::jev_key reuses the secure loader. f1415c8 marks its table row Native Rust for the ST-077 doc test.
- judge_contract (no key; native with env_clear and PATH=/nonexistent) compares stdout, stderr, exit code, and a byte and mode snapshot with Node: no ids, several ids, each of 14 ids, missing, invalid, and empty ids, a bad --dir, an empty backlog, five kill-switch spellings, a stored 0600 key with the kill switch, a 0644 key file (exit 1), and a key file without the variable. 3 passed.
- Jev path: 8 unit tests against a local fake HTTP server (fake key only). Two run Node with a fetch stub against the same server and require identical stdout for success and HTTP 503, 401, 422, 429, and 404, human and --json. Six check the request (canary first, Bearer header, key order, no frontmatter sent) and egress refusal, failed canary, malformed answer, retry-after-ms, and a 302 as transport_error.
- Real data (no key present): no args, --json, and each of 82 ids plain and --json, native against Node: compared=166 differing=0.
- Checks after rebase on main 4bcf72b: cargo fmt --check clean; clippy -D warnings clean; cargo test --locked 292 passed, 0 failed (52 binaries); npm test 461/461; story-policy.rs 12 passed; story-policy-contract.rs 11 passed.
- Limits: the binary always calls the vendor endpoint, so the Jev path is tested in-crate, not through the binary. Jev-path unit tests landed in the green commit. Warnings print `Jev: <message>` where Node prints `(node:PID) Jev: <message>`; stdout is identical.
