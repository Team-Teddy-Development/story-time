## Story
As a Varsity teammate, I want Claude Code Web to handle Story Time, so that I can request a change without looking up issue numbers or configuring a connector.

## Acceptance Criteria
- [x] Given a Varsity Web request with a ready or in-progress story that covers the outcome and an issue that belongs to it, when the session runs Story Time intake before coding and prepares the PR, then it reuses that story and emits the canonical verified link without requesting IDs; verify with the fresh Cloud reuse transcript and `cargo test --locked --manifest-path native/story-push/Cargo.toml --test check_pr_contract cloud_link_`.
- [x] Given a supported small change with no matching story, when the session runs intake before coding, then it creates one scoped story, meets readiness and kickoff requirements, mirrors it to GitHub, and links the PR; a replay does not create another story or issue. Verify with the live publisher replay and `cargo test --locked --manifest-path native/story-push/Cargo.toml --test cloud_intake_publish publish_new_story_once -- --exact`.
- [x] Given ambiguity, insufficient readiness, or missing tracker access, when intake cannot establish a valid link, then it does not pick an unrelated story, invent an issue, or bypass CI, and it requests only product clarification or sends a maintainer a recovery action. Verify with fresh Cloud ambiguity and technical refusal, plus the native `check_pr_contract` suite.
- [x] Given a fresh Claude Code Web session attached to Varsity-Engine/varsity-web with no personal Story Time connector, when reuse and new-intake fixture requests go through the repository-managed path, then each test PR contains exactly one verified `Stories: VE-### (#issue)` line and the unchanged `story-link` gate passes; record exact test PRs and head SHAs. Do not change merge permissions or retrofit Varsity Web PR #1543.
