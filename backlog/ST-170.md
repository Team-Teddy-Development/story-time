## Story
As a Varsity teammate requesting a change in Claude Code Web, I want Story Time to find or file the right story and link the pull request, so I can describe the change without managing story IDs, issues, or a connector. First target: Varsity-Engine/varsity-web. Source: PR #1543 passed after a story line was added, but VE-086 is a Core cutover story and its criteria do not cover the mobile table wrap fix. Keep the existing readiness and merge gates. Do not retrofit #1543, change merge permissions, or require a personal MCP connection. Exercise the actual Claude Code Web path with a test PR.

## Acceptance Criteria
- [ ] Given a Varsity Web change request with a ready story that covers the requested outcome, when Claude Code Web starts the task and prepares the PR, then Story Time uses that story and writes its verified `Stories: VE-### (#issue)` line without prompting the requester for a story ID or issue number.
- [ ] Given a supported small change with no matching story, when Claude Code Web starts the task, then Story Time files one scope-specific story, applies the configured readiness and kickoff rules before implementation, mirrors it to GitHub, and links the PR to that issue; retrying the same intake does not create a duplicate.
- [ ] Given ambiguous scope, an unmet readiness rule, or unavailable tracker access, when Story Time cannot produce a valid link, then it does not guess, create a placeholder, or bypass CI; it asks only for missing product scope or sends an actionable failure to the maintainer.
- [ ] Given a fresh Claude Code Web session without a personal Story Time MCP connection, when a test change runs through the Varsity Web workflow, then the requester provides only the change and any necessary product clarification, and the existing story-link check passes with the verified story and issue pair.
