## Story
As a maintainer, I want story-install to stop writing runtime.json legacyCli now that the native binary never starts Node, so that the install does not record a setting nothing reads.

## Acceptance Criteria
- [x] Given a fresh install with story-install --agent all, when it finishes, then it writes no runtime.json legacyCli, and story-install --rollback still restores a runtime.json that an earlier install wrote, verified by a native/story-push test

## Notes
Source: ST-096 (PR #206) report. native/story-push/src/bin/story_install.rs still writes ~/.config/story-time/runtime.json legacyCli, and tests/release_install.rs pins it; since ST-096 nothing reads it. Confirmed: the 3f1d198 install wrote it.

## Evidence
- Red ff9e5e9: `release_install` ran 5 tests, 3 failed. The install and rollback tests failed on `assertion failed: !runtime(&home).exists()`, and the fresh-machine test failed because the plan printed `write .../runtime.json with legacyCli .../story.mjs`.
- Green 2c93e79: `story_install.rs` replaces `Step::Runtime { legacy_cli }` with `Step::RemoveRuntime`, planned only when `runtime.json` exists and always after `Step::Backup`. A fresh install writes no `runtime.json`; an earlier one is saved to the backup and then removed.
- `tests/release_install.rs`: a fresh machine gets no `runtime.json` and no `legacyCli` in the plan, and `--rollback` leaves none; after an earlier install wrote `{"legacyCli":"/old/story.mjs"}\n`, `--rollback` restores those exact bytes; a failed build leaves `runtime.json` unchanged.
- README now says the installer removes `runtime.json`, which no command reads.
- Limits: the installer still exports `skills/story-time/scripts` (the Node CLI) as a retained artifact. ADR 0003 line 17 still describes the Node fallback that ST-096 removed; filed as a follow-up.
- Checks on main 51efc76: `cargo fmt --check` ok; clippy `-D warnings` ok; `cargo test --locked` 323 passed, 0 failed; `npm test` 465/465; `scripts/story-policy.rs` 12 passed; `test/story-policy-contract.rs` 11 passed.
