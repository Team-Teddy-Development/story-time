## Story
As a backlog maintainer, I want refinement and sprint-planning skills, so that I can organize open stories into epics and realistic sprint plans.

## Acceptance Criteria
- [x] Given open stories and missing epic definitions, when refinement runs, then every open story has a disposition and evidence-based epic mapping or an explicit unresolved question.
- [x] Given ready stories and team capacity, when sprint planning runs, then the plan records a sprint goal, capacity arithmetic, dependency order, and deferred work without treating future forecasts as commitments.
- [x] Given missing capacity or unsupported tracker sprint fields, when planning runs, then it records a provisional plan and publication limits without inventing dates, metrics, or CLI commands.
- [x] Given the skill package, when its validation and installation paths run, then both new skills and their router entries are discoverable with valid metadata.
- [x] Given malformed planning input, duplicate IDs, a dependency cycle, unsupported versions, or changed source preimages, when native planning runs, then it reports the cause without replacing a plan or changing backlog, configuration, or tracker state.
- [x] Given the old backlog-groom entry point or either refinement mode, when refinement starts, then it uses one refinement orchestration path and preserves existing estimates unless re-estimation is requested.
- [x] Given the scoped planning implementation and installed skill package, when Rust contracts and existing regressions run, then all new executable planning logic and tests use Rust and both skill entry points pass their real installation checks.
