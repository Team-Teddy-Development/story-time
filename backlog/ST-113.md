## Story
As a coding agent operator, I want story_create to allocate a new id without replacing or duplicating a story, so that parallel agents can file work safely.

## Acceptance Criteria
- [x] Given a new title, when story_create runs, then it returns a new id and the file equals what story new produces apart from the date, verified by a native/story-push protocol test
- [x] Given an existing title, when story_create runs without allow_duplicate_title, then the result is duplicate_title and nothing is written, verified by a native/story-push protocol test
- [x] Given a racing creator that takes the same id, when story_create saves, then no story is replaced and a second collision returns id_taken, verified by a native/story-push protocol test
- [ ] Given a real MCP client, when it creates a story, then the story appears in story list, recorded in the story Evidence

## Evidence
All tests are in `native/story-push/tests/mcp_protocol.rs`.
- Criterion 1: `story_create_writes_what_story_new_writes_and_returns_audit_evidence` runs for sync ask and off. It compares the file byte for byte with `story new` after replacing the date, checks the output schema, checks that `story_list` shows the new id, and checks that the stderr audit holds the id and no title text.
- Criterion 2: `story_create_refuses_a_duplicate_title_unless_it_is_allowed` covers a title matched after case-folding and trimming, an explicit `allow_duplicate_title: false`, a blank title, and a held lock. Each refusal leaves the snapshot unchanged. With `allow_duplicate_title: true` the story is created.
- Criterion 3: `story_create_never_replaces_a_racing_story_and_a_second_collision_is_id_taken` forces the race deterministically. A FIFO at the server's staging path holds the write until a racer has written `<id>.md`. One collision gives the next id with the racer's file unchanged; a second collision gives `id_taken` (retryable) with no file and no temp file left. It passed 25 repeated runs.
- Criterion 4: open until acceptance with a real client on the installed release.
- Red (22f95be): the new tests failed with -32602 "Unknown tool". Green (e3d45f6): `story_create` turns its input into `story new` flags and calls `new_story::create` under the repository lock with `attempts = 2`. The CLI passes `usize::MAX` and is unchanged.
- Rebased onto ST-116, where `new_story::run` takes the lock outside `create`, so the MCP path does not lock twice. Checks on the rebased branch: fmt ok; cargo 73 binaries, 370 passed, 0 failed; npm pass 457 fail 0; story-policy 12 passed; contract 11 passed.
- Real data: on a scratch copy of this backlog, Node `story new` and MCP `story_create` with the same input both allocated ST-119 with identical backlogs. An upper-cased, padded copy of ST-112's title returned `duplicate_title` with ids ["ST-112"].
