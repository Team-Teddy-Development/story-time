## Story
As a team lead, I want to assign stories to a sprint, so that I can see what the team committed to and how many points it completed.

## Source task
2026-11-25, Eric: build velocity and burndown into Story Time, with sprint membership stored on each story. Design: [Velocity, burndown, and forecast](../docs/designs/velocity-burndown.md) (PR #444).

## Acceptance Criteria
- [x] Given a story, when `story set` or local MCP `story_update` sets or clears its sprint, then the frontmatter and changelog record the change. Both reject an invalid ID without writing. `story lint` reports an invalid hand-edited ID as `sprint.format`. `story list --sprint` and local MCP `story_list` return only stories in the selected sprint.
- [x] Given a weekday anchor with a valid time zone and a ten-working-day sprint length, when the calendar resolves sprints from 2026-01-05, then S01 ends 2026-01-16 and S02 runs 2026-01-19 through 2026-01-30. An override changes only the named sprint and can set its goal. Invalid anchor, time zone, override ID, or date order, and duplicate override IDs fail config validation.
- [x] Given dated sprint, size, and completion events, when the system derives a sprint, then it separates initial commitments from later adds and drops. It uses the last size known at commitment or addition, ignores later resizing, and uses the recorded completion date.
- [x] Given closed sprints with known completed points, when `story metrics` runs, then it reports per-sprint points and the mean, minimum, and maximum for the last three and six where enough history exists. Short windows report `unknown` with a reason. Sprints with unknown completed points appear as unknown and do not enter the statistics.
- [x] Given a sprint ID, when `story sprint show` runs in text or JSON mode, then it reports dates, goal, commitments with points, dated adds and drops, and completions with points without changing any file.

## Out of Scope
- Burndown (ST-195), forecast (ST-196), and hosted MCP and skills integration (ST-197).
- Tracker sprint fields and automatic holiday calendars. Use explicit sprint date overrides for holidays.
