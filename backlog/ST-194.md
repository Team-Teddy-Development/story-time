## Story
As a team lead, I want to put a story in a sprint by setting its `sprint` attribute, so that every surface (CLI, local and hosted MCP, tracker sync) knows what a sprint committed to and `story metrics` reports real velocity instead of "unknown".

## Source task
2026-11-25, Eric: build velocity and burndown into story-time, with the sprint as an attribute on the story so the MCP can use it. Design: `docs/designs/velocity-burndown.md` (PR #444).

## To plan
- New optional frontmatter field `sprint` (`YYYY-Snn`), accepted by `story set`, `story_update` and the lint schema, plus a `sprint` filter on `story list` / `story_list`.
- Sprint calendar in settings: the existing `team.sprintDays`, a new `team.sprintAnchor` (start date of sprint 1, plus the time zone), and an optional `team.sprints` override list (dates and goal per sprint).
- Derive everything from the changelog, as `metrics.rs` `history()` does for status:
  - the committed set is `set sprint=<id>` on or before the start;
  - adds and drops are dated `set sprint=` changes after the start;
  - points at commitment are the last `set size=` on or before entry.
- Velocity in `story metrics`: completed points per closed sprint, then the mean, minimum and maximum over the last 3 and last 6. It is `unknown` with a reason below 3 closed sprints.
- `story sprint show <id>`: the dates, the committed set, the changes and the done set. Read-only.

## Acceptance Criteria
- [ ] Given three closed sprints whose stories carry sprint attributes and done changelog events, when story metrics runs, then velocity reports completed points for each sprint and their mean, min and max instead of unknown
- [ ] Given a story, when `story set <id> sprint=2026-S23` runs, then the frontmatter has `sprint: 2026-S23` and the changelog gains `- <date> set sprint=2026-S23`; a value that is not `YYYY-Snn` is refused and writes nothing, and `sprint=` removes the field and logs `set sprint=`
- [ ] Given a hand-edited story whose `sprint` is not `YYYY-Snn`, when `story lint` runs, then it reports an error under `sprint.format`, and a valid or absent `sprint` reports nothing
- [ ] Given stories in several sprints, when `story list --sprint 2026-S23 --json` or the local MCP `story_list` with `sprint` runs, then only the stories in that sprint return, and `story_update` with `set: {sprint: ...}` sets it through the same validation as `story set`
- [ ] Given `team.sprintAnchor` `{date, tz}` and optional `team.sprints` `{id, start, end, goal}` entries in settings, when config loads, then a weekday anchor date, a time zone name, `YYYY-Snn` ids, valid ordered dates and unique ids are accepted, and anything else is refused naming the field
- [ ] Given an anchor on 2026-01-05 and `sprintDays` 10 (working days), when a sprint id is resolved, then `2026-S01` is 2026-01-05..2026-01-16 and `2026-S02` is 2026-01-19..2026-01-30, and a `team.sprints` entry replaces the dates of its own id only and adds its goal
- [ ] Given changelogs with `set sprint=`, `set size=` and `set status=done` lines, when a sprint is derived, then the committed set is the stories in the sprint on its start date, an add or drop is a dated change after the start, points at commitment are the last `set size=` on or before the commitment date (the start for the committed set, the add date for an add) so a later re-size changes nothing, and the done date is the `set status=done` event
- [ ] Given fewer than 3 closed sprints with known points, when story metrics runs, then velocity is `unknown` with the count of closed sprints and a reason, and `last_6` stays `unknown` below 6; a sprint with a completed story whose points at commitment are unknown is listed as unknown and left out of the statistics
- [ ] Given a sprint id, when `story sprint show <id>` (with or without `--json`) runs, then it prints the dates and goal, the committed set with points, the dated adds and drops, and the done set with points, and changes no file

## Out of Scope
- Burndown (ST-195), forecast (ST-196), hosted MCP tools and skills (ST-197).
- Tracker sprint fields (GitHub Projects iterations, Jira sprints).
- Holidays in the generated calendar: a `team.sprints` entry covers them.

## Test Plan
1. Unit, `sprint.rs`: sprint id format (`2026-S01` yes; `2026-S1`, `2026-S00`, `26-S01`, `2026-s01` no).
2. Unit, `sprint.rs`: calendar from anchor and `sprintDays` gives S01 and S02 dates above; a year boundary restarts at `S01`; an override replaces one id only; an id outside the calendar is an error.
3. Unit, `sprint.rs`: fixtures with 3 closed sprints, an add after the start, a drop, a re-size after commitment (points must not move), a story done outside the sprint dates, an unknown size, and a story with no sprint events.
4. Contract, `agile_metrics_contract.rs`: 3 closed sprints give per-sprint points, mean, min, max; 2 give `unknown` with count 2; the old no-sprint output carries the new reason.
5. Contract, `set_contract.rs`: `story set sprint=` writes the field and changelog line, refuses a bad id without writing, clears on empty.
6. Contract, `lint_contract.rs`: `sprint.format`.
7. Contract, `list_contract.rs` and MCP: `--sprint` filter, `story_list` `sprint`, `story_update` sets and refuses.
8. Contract, `config_contract.rs`: anchor and `sprints` accepted and refused.
9. Contract, `sprint_show_contract.rs`: `story sprint show` text and JSON, read-only (file bytes unchanged).
10. Docs: `doc_native_lists.rs` still names exactly the dispatch table (`sprint`).
