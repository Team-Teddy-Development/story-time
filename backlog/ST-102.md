## Story
As an agent, I want list, lint, stats, plan, and adopt to use one rule for which backlog files are stories, so that a stray file never passes one command and fails another.

## Acceptance Criteria
- [x] Given a backlog directory with a story, an epic map, and a stray notes.md, when list, lint, stats, and plan --snapshot run, then all of them skip notes.md through one shared rule, as list, lint, and stats already did, because only <PREFIX>-<digits>.md files are stories, and the story and epic map are still read; adopt preview, which inventories a project before adoption, still reports notes.md as a conflict and never omits it silently; and both the rule and the adopt exception are documented in skills/story-time/SKILL.md, verified by a native/story-push test

## Notes
Source: ST-097 (PR #204). Today `list`, `lint`, and `stats` read only `<PREFIX>-<digits>.md` names and skip a stray notes.md, while `plan` and `adopt` read every non-map `.md` as a story and stop with an error. Owner decision was pending for many loop rounds. The coordinator applied the default on 2026-11-14 under the loop's autonomy: skip non-ID names, the rule 3 of 5 commands already use. The owner can reverse it to refuse.

## Evidence
- Red 84ecf41: `tests/story_files_contract.rs` failed: `["plan", "--snapshot"] refused: {"status":"conflict","diagnostic":"malformed_story: backlog/notes.md: Story is missing YAML frontmatter (--- ... ---)",...}`.
- Green 7d51561: one rule, `story_file_id(name)` in `native/story-push/src/lib.rs` (`name.strip_suffix(".md").filter(valid_id)`). `list` (and through it `lint` and `stats`) uses it instead of its private duplicate, and so does the `plan` snapshot enumeration. The inline copies in `metrics.rs` and `next_id.rs` also move to it, with no behavior change. A fixture with a story, an epic map and a stray `notes.md` shows that `list`, `lint`, `stats` and `plan --snapshot` all skip `notes.md` and still read the story and the map. Native runs with PATH=/nonexistent.
- Adopt preview exception (criterion amended): adopt preview inventories a project before adoption. Its documented contract says "Every regular file has a byte digest" and "no source is omitted silently", and five existing tests require that. It still reports `notes.md` as an `unsupported_story` conflict, asserted by `tests/story_map_skill.rs:89-93`. `skills/story-time/SKILL.md` documents the rule and this exception, and `skills/story-map/SKILL.md` step 6 is updated.
- Changed tests: `story_map_skill.rs` now expects `plan` to succeed and omit `notes.md`. In `planning_contract.rs`, the duplicate-id fixture is renamed `work/PAY-002.md` and still expects `duplicate_id`.
- Real backlog (109 stories, 2 maps), before and after: `list`, `lint`, `stats` and `adopt preview` show no output change, and `plan --snapshot` differs only in `captured_at`. Node `list`, `lint` and `stats` are byte-identical to native. Node has no `plan` or `adopt`.
- Follow-up filed: `story adopt` accepts stories in non-ID files, such as `work/old-1.md`, that the other commands then cannot see.
- Checks on main 3f88785: `cargo fmt --check` ok; clippy `-D warnings` ok; `cargo test --locked` 346 passed, 0 failed; `npm test` 457/457; `scripts/story-policy.rs` 12 passed; `test/story-policy-contract.rs` 11 passed.
