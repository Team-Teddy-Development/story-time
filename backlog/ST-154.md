## Story
As a team lead, I want story push to keep existing label colors, so that labels do not change color each time a fresh process (for example a CI job) pushes a story.

## Acceptance Criteria
- [x] Given a GitHub repository where the label size:5 already exists with color 00ff00, when a fresh story push process updates a story with size 5, then the label keeps color 00ff00 and gh label create is not run for it
- [x] Given a label that does not exist, when story push applies it, then it creates the label once with a fixed color for its label family

## Test Plan
- AC1 → `gateway::tests::existing_github_labels_keep_their_color` (red first): stub `gh label list` returns `size:5`; a fresh gateway updates a size-5 story; assert no `label create size:5` call and exactly one `label list` call.
- AC2 → `gateway::tests::missing_github_labels_are_created_once_with_a_family_color`: stub list returns `[]`; two updates; assert one `label create size:5 --color c5def5` and one `label create story --color 0e8a16`.
- Port: `ensure_github_labels` in `native/story-push/src/gateway.rs` (GitHub adapter only). Branch: `fix/st-154-label-colors`.

## Notes
- Cause: `ensure_github_labels` (`native/story-push/src/gateway.rs:886-901`) runs `gh label create <name> --force` with no `--color` for each label on first use in a process. `gh` picks a random color when none is given, and `--force` overwrites an existing label's color. The `known` set lives only for one process, so every fresh process recolors.
- Found by the EGM critic review of `docs/designs/merge-sync-design.md` (design reviewer M9), verified with `gh label create --help` on 2026-11-16. Prerequisite of ST-151, whose CI job runs a fresh process on every merge.
