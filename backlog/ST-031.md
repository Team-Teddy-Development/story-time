## Story
As a story-time maintainer, I want story set depends_on=[] to store an empty list, so that clearing dependencies does not create a dangling dependency on a story named "[]".

## Acceptance Criteria
- [ ] Given a story, when story set <id> 'depends_on=[]' runs, then its frontmatter reads depends_on: [] and story lint reports no dangling dependency
- [ ] Given a story, when story set <id> 'depends_on=[ST-001, ST-002]' runs, then its frontmatter reads depends_on: [ST-001, ST-002]

## Out of Scope
Other list fields. Changing how story set parses scalar values.

## Notes
Source: gap-sweep dry run row 1 (docs/verification/ST-030-dry-run.md). Reproduced on origin/main during ST-030: `story set ST-001 'depends_on=[]'` wrote `depends_on: ["[]"]`. Affected command: `story set`. This story adopts #12; its next push replaces the issue's title and body.

Original issue #12 title: story set depends_on=[] stores the literal string "[]"

Original issue #12 body:

> Reproduced on main (1cbe7d8):
>
> ```
> story new --title x --prefix ZZ
> story set ZZ-001 'depends_on=[]'
> grep depends_on backlog/ZZ-001.md
> # depends_on: ["[]"]
> ```
>
> Expected `depends_on: []`. The list value from `story set` is not parsed with the frontmatter value parser, so an empty inline list becomes a one-item list holding "[]". `story-checks ids` in cartographer then reports a dangling dependency on a story named "[]".
>
> Done when a test sets `depends_on=[]` and `depends_on=[A, B]` through `story set` and reads back `[]` and `[A, B]`.
