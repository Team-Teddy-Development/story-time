## Story
As a maintainer of story sync-merge, I want a contract test for each case that the merge-sync design lists, so that a change to the range or comment logic that breaks one of them fails the test run

## Acceptance Criteria
- [ ] Given the tests in native/story-push/tests/sync_merge_contract.rs, when `cargo test --test sync_merge_contract` runs, then a test asserts that a pull request merged during a skipped run gets its merge comment on the next run
- [ ] Given the same test file, when the tests run, then a test asserts that one push that carries two merged pull requests posts both merge comments
- [ ] Given the same test file, when the tests run, then a test asserts that after a run with a 404 on one issue exits 0, the range of the next run starts after that push
- [ ] Given the same test file, when the tests run, then a test asserts that a rerun posts the merge comment of a named card that a failed run missed, one time
- [ ] Given the same test file, when the tests run, then a test asserts that a run history that cannot be read takes the --all path, reports the reason, and posts no comment

## Notes

- Design: `docs/designs/merge-sync-design.md` lines 955-967 list the tests; lines 371-375 give the unreadable run history case.
- Present state of `native/story-push/tests/sync_merge_contract.rs`: `a_successful_all_run_does_not_move_the_range_start` asserts only the `run list` arguments; `merged_two` is one pull request with two stories, so no test has two pull requests in one push; `a_server_error_exits_1_and_a_missing_issue_exits_0` asserts exit codes and kinds only; `a_rerun_posts_a_missed_state_comment_once` covers the state comment only; `no_history_or_a_non_ancestor_anchor_takes_the_all_path` covers the empty history and the non-ancestor anchor only.
- A test that fails shows a defect. File that defect as its own bug story; do not change the test to pass.
