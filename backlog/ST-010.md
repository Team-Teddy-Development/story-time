## Story
As a story-time operator, I want story-time traces in Tempo and Grafana, so that I can locate slow or failed steps within an operation.

## Acceptance Criteria
- [ ] Given configured tracing, when a story-time operation runs, then Tempo contains a root span and child spans for the storage or tracker calls it actually performs, verified on the live stack from a GitHub Actions run that exports through the Xanthos gateway, recorded in the story Evidence
- [ ] Given a failed operation, when its trace opens in Grafana, then span status and sanitized error attributes identify the failed step, verified on the live stack from a GitHub Actions run that exports through the Xanthos gateway, recorded in the story Evidence
- [ ] Given a trace context, when logs and spans are emitted with logging enabled, then they carry the same trace identifier and Grafana can navigate from the trace to matching Loki logs, verified on the live stack from a GitHub Actions run that exports through the Xanthos gateway, recorded in the story Evidence
- [ ] Given story bodies or credentials, when spans are exported, then neither appears in span names, attributes, or events, verified by a native/story-push test that exports to a local OTLP/HTTP receiver
- [ ] Given disabled tracing or an unavailable backend, when an operation runs, then its result remains correct and sampling, buffering, and export timeouts remain bounded, verified by a native/story-push test that exports to a local OTLP/HTTP receiver
