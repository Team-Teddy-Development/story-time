## Story
As a local agent coordinator, I want `story assignment status` to report ownership or explicitly report that verification is unavailable, so that a slow backlog read does not hide available evidence or block other assignment operations. Cartographer CRT-548 is ready at `23b7958ee1331d1ff545eb2b90a275ca3e1d0494`, but a 35-second status attempt returned no JSON. At 18 seconds the active read descriptor was a backlog file; the child was reaped at the deadline. The physical cause of the slow read and installed source revision are not established. Out of scope: Cartographer admission, WIP-limit changes, legacy ownership resets, and filesystem remediation. Verify in Rust with `cargo test --manifest-path native/story-push/Cargo.toml --test assignment_contract` and a deterministic blocked-reader test, not a live filesystem stall.

## Acceptance Criteria
- [ ] Given a shared repository with a status read blocked on a legacy backlog file, when an independent assignment operation reaches the shared lock, then status does not prevent that operation from acquiring the lock while the backlog read waits.
- [ ] Given unchanged recorded owners, reservations, and legacy stories, when status completes the backlog scan, then the command returns the same ownership, reservation count, WIP limit, and legacy quarantine as an unblocked status read of the same state, without changing assignments.
- [ ] Given a legacy scan that cannot complete or whose inputs change during the read, when status cannot verify a consistent result, then it reports ownership verification as unavailable rather than presenting free capacity, and it does not release claims or change story state.
