## Story
As a story-time operator, I want one hosted server to hold the repositories of several orgs, so that Varsity and Team Teddy use one deployment and each org keeps its own backlog and links.

## Acceptance Criteria
- [x] Given a registry where a [[repo]] table names an org and another takes the top-level org, when the server starts, then story_repos lists every repository with its org, and a registry in the current one-org format loads with no change and gives each repository the top-level org
- [x] Given two repositories of different orgs that declare the same prefix, when the server starts, then it loads and story_show with the repository returns the story of that repository, and two repositories of one org that declare the same prefix are refused by name
- [x] Given a story that depends on an id that only a repository of another org holds, when story_lint and story_graph run for it, then the link does not resolve into the other org, and story_graph returns no node, no edge, and no sync entry of the other org
- [x] Given a registry where one repository key appears in two orgs, or an org name that is not a lowercase key, when the server starts, then it exits non-zero and names the entry

## Out of Scope
- Links between stories of two orgs. A link stays inside one org.
- A second forge type. ST-140 adds Gitea.
- Self-service sign-up. The operator still edits the registry.

## Notes
Source: owner message on 2026-11-16, "maybe not full public but at least we need to support multi org and multi type", after the hosted server went live for one org (ST-136). Refinement decision (2026-11-16): the registry stays flat. Each `[[repo]]` table can name its `org`; the top-level `org` is the default, and `default` is the org when neither is set. The TOML subset parser has no nested table arrays, so `[[org]]` tables with repositories inside are not possible without a parser change. A repository key stays unique in the whole registry, so each tool still takes `repository` and needs no `org` argument. The parser did not read the top-level `org` before this story. Today the registry has one top-level `org` value (`k8s/story-time/25-configmap.yaml` in coffee-apps holds `org = "varsity"`), and the design `docs/designs/hosted-story-mcp.md` says one org for each server. The GitHub App `story-time-mcp` is owned by Team-Teddy-Development and can be installed on more orgs, so the credential side already permits several GitHub orgs. "Multi type" is the forge type: ST-140 covers Gitea. ST-142 limits what a client token can read, and it must land before a second org with other readers goes live. The design document needs an amendment for this story.
