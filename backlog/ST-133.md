## Story
As a hosted story MCP client, I want each story edit to land on one branch and one pull request for that story, so that story changes go through review and never overwrite another writer.

## Acceptance Criteria
- [x] Given a story with no open PR, when story_update runs with the current expected_sha256, then the server pushes one commit to story-time/<ID> with the bot author and a Requested-by trailer, opens one PR, and returns state proposed with pr_url
- [x] Given an open PR for the story, when story_show runs, then the response includes proposed with ref, content_sha256, and pr_url
- [x] Given two clients that hold the same content_sha256, when both call story_update in turn, then the second call returns conflict with ref and current_sha256 and writes nothing
- [x] Given an upstream push to the story branch between fetch and push, when the server pushes, then the lease rejects the push and the call returns conflict
- [x] Given a leftover story-time/<ID> branch with no open PR, when the next write runs, then it starts from the default branch
- [x] Given two concurrent story_create calls, when both finish, then the two stories have different IDs
- [x] Given commit directories and index files left by a crash, when the server starts, then it removes them

## Out of Scope
- Direct commits to a default branch.
- Publishing tracker issues from the server.
- Atomic edits across repositories.
- Rebasing a PR when the default branch moves.

## Notes
Source: ST-128, docs/designs/hosted-story-mcp.md, slice S4 (Component 4; items 9, 12, 21, 28). Owner handoff: add Contents: write, Pull requests: write, and Issues: write to the App, and create `Varsity-Engine/story-time-sandbox`.

As built:
- `native/story-push/src/mcp/propose.rs` runs the local write logic on a private directory of the base commit, then commits, pushes with `--force-with-lease`, and finds or opens the pull request. `src/mcp/forge.rs` holds the GitHub pull request calls.
- A registry server has write tools only with the GitHub App flags. Each write fetches first, under one write lock for each repository.
- A leftover branch with no open PR is replaced by the one leased push of the next write. The design said "deletes"; the design document now says "replaces".
- When GitHub does not open the pull request, the server removes the branch it pushed and returns the retryable error `forge_unavailable`.
- The bot email is `<slug>[bot]@users.noreply.github.com`, without the numeric user id that GitHub uses to link a commit to the bot account.
- Red run: with the new test file on the ST-132 source, 5 of 5 tests failed (`Unknown tool`, index file not removed). The tests were written before the code.
- Not checked here: a push and a pull request against real GitHub. That is ST-137.
