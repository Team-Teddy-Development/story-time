## Question
Which native Rust MCP design should story-time adopt: a dedicated server sharing a Rust application core, or MCP transport within the Rust CLI?

## Exit Criteria
- [ ] Given the current CLI and MCP client requirements, when the spike ends, then a decision under docs/adr/ compares the named designs and records the selected boundary, transport, tool scope, and evidence.
- [ ] Given read and write operations, when the design is reviewed, then typed request and response contracts define repository isolation, authorization, validation, idempotency, concurrency, errors, and redacted audit evidence.
- [ ] Given the selected design, when planning ends, then linked vertical delivery stories identify dependencies, Rust conversion scope, estimates, and criterion-level protocol and real-client verification plans, or document unresolved blockers.

## Research scope
Inventory existing CLI commands, lifecycle rules, tracker adapters, and the Rust preflight MCP before proposing another server. Compare stdio and Streamable HTTP for actual target clients. Define an initial read-only slice and a guarded write slice; decide whether prompts and resources add value.

Record tool names, schemas, pagination, error codes, repository selection, compatibility, secret handling, and synchronization policy. Evaluate shared native Rust application logic against subprocess coupling; a wrapper around the Node CLI does not satisfy the Rust requirement.

## Notes
Requested design and planning only. Proposed timebox: one working day, not a deadline. ST-007 is the blocked delivery placeholder. Preserve current CLI behavior and historical non-Rust evidence. Do not execute the spike as part of this backlog addition.

## Out of Scope
Build or deploy the MCP server, migrate the whole CLI, change tracker policies, or add production access.

## Verification plan
Inspect the decision record and contracts against each exit criterion. Link source and MCP specification evidence. Give follow-up stories testable criteria and Rust protocol, failure-path, and actual MCP client checks. Keep unanswered questions explicit.
