## Story
As a hosted story MCP client, I want story mcp to serve the existing tools over HTTP with my own bearer token and scopes, so that I can call story tools without a stdio process on my machine.

## Acceptance Criteria
- [ ] Given story mcp --http 127.0.0.1:0 --root <fixture> --clients <fixture>, when a request has no bearer token or an unknown token, then the server returns HTTP 401
- [ ] Given a valid read-only token, when the client calls story_show over HTTP, then structuredContent equals the stdio result for the same story
- [ ] Given a valid read-only token, when the client calls story_update, then the result is scope_refused, tools/list omits story_update, and no file changes
- [ ] Given a legacy client and a modern client that interleave requests, when each sends tools/list, then each response uses the protocol era of its own request
- [ ] Given a request whose Mcp-Method or Mcp-Name header does not match its body, when the server handles it, then it returns JSON-RPC error -32020
- [ ] Given a disallowed Origin, a body over 1 MiB, GET /mcp, or a notification, when the server handles each request, then it returns 403, 413, 405, and 202 in that order

## Out of Scope
- Any cluster deploy. S0 is checked in CI only.
- Registry, clones, and GitHub credentials (ST-130).
- Write and comment behavior behind the scopes (ST-133, ST-134).
