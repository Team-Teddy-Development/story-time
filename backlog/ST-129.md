## Story
As a hosted story MCP client, I want story mcp to serve the existing tools over HTTP with my own bearer token and scopes, so that I can call story tools without a stdio process on my machine.

## Acceptance Criteria
- [x] Given story mcp --http 127.0.0.1:0 --root <fixture> --clients <fixture>, when a request has no bearer token or an unknown token, then the server returns HTTP 401
- [x] Given a valid read-only token, when the client calls story_show over HTTP, then structuredContent equals the stdio result for the same story
- [x] Given a valid read-only token, when the client calls story_update, then the result is scope_refused, tools/list omits story_update, and no file changes
- [x] Given a legacy client and a modern client that interleave requests, when each sends tools/list, then each response uses the protocol era of its own request
- [x] Given a request whose Mcp-Method or Mcp-Name header does not match its body, when the server handles it, then it returns JSON-RPC error -32020
- [x] Given a disallowed Origin, a body over 1 MiB, GET /mcp, or a notification, when the server handles each request, then it returns 403, 413, 405, and 202 in that order

## Out of Scope
- Any cluster deploy. S0 is checked in CI only.
- Registry, clones, and GitHub credentials (ST-130).
- Write and comment behavior behind the scopes (ST-133, ST-134).

## Evidence
Source commit `08c6bd7`. Each criterion is verified by a test in `native/story-push/tests/mcp_http.rs`, which starts the real `story` binary with `--http 127.0.0.1:0`.

| Criterion | Test |
|---|---|
| 1: no token or an unknown token gets 401 | `a_request_without_a_known_token_gets_401_on_every_method` |
| 2: `story_show` over HTTP equals stdio | `story_show_over_http_equals_story_show_over_stdio` |
| 3: read-only token, `scope_refused`, hidden tool, no file change | `a_read_only_token_cannot_see_or_run_write_tools` |
| 4: each request uses its own protocol era | `each_request_uses_the_protocol_era_of_its_own_request` |
| 5: header mismatch gets `-32020` | `a_header_that_does_not_match_the_body_gets_minus_32020` |
| 6: 403, 413, 405, 202 | `origin_size_method_and_notification_get_their_status_codes` |

- `cargo test --locked --manifest-path native/story-push/Cargo.toml --test mcp_http`: 7 passed, 0 failed.
- `cargo test --locked` (all binaries): 402 passed, 0 failed. This includes `mcp_protocol` unchanged, 3 unit tests in `src/mcp/caller.rs`, and 3 in `src/mcp/http.rs`.
- `cargo clippy --locked --all-targets -- -D warnings`: clean. `cargo fmt --check`: clean. `npm test`: 457 pass, 0 fail.
- Language audit: every new implementation and test is Rust (`src/mcp/http.rs`, `src/mcp/caller.rs`, `tests/mcp_http.rs`). One new dependency: `tiny_http` 0.12.0.
- Registration commands in the README were checked against `claude mcp add --help` and `codex mcp add --help` (codex-cli 0.157.1). No real agent client was connected to the server.
- Not covered by a test: the request timeout (504), the full-queue reply (503), and the prefix limit through HTTP. The prefix limit has a unit test in `caller.rs`.
- Deviations from the design: `usage.txt` has no `story mcp` entry, so it did not change. `Redactor.values` stays a `Vec`, because this slice holds token hashes only; ST-130 changes it when installation tokens refresh. The tests were written before the code but were not run in a failing state first.
