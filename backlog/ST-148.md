## Story
As an agent with a long-lived MCP session, I want story_repos to keep answering after the hosted server is redeployed with an extra output field, so that I can find the registered repositories without restarting my session.

## Acceptance Criteria
- [ ] Given a client that loaded the story_repos output schema before a deploy, When the server returns a repository entry with a field that schema does not list, Then the client accepts the response, because each output object schema of a hosted tool allows additional properties, and a test in native/story-push fails if an output schema sets additionalProperties to false.

## Notes
Seen 2026-11-16 about 04:20 UTC from a Claude Code session started before the evening deploys (ST-141 merged 2026-11-16T03:00Z, ST-146 at 04:18Z). `story_repos` failed in the client with: `Structured content does not match the tool's output schema: data/repositories/0 must NOT have additional properties` (same for entries 1 to 3). `story_config` in the same session worked.

Cause (supported, not reproduced): `repos_schema()` in `native/story-push/src/mcp.rs` builds each entry with `object()`, which sets `additionalProperties: false`. The current server returns `key, org, prefixes, sha, fetched_at, state, last_error`, and the current schema lists all seven, so server and schema agree today. The client validates against the schema it loaded at session start. ST-141 added `org` to each entry, so a session older than that deploy rejects every response. Any later additive field breaks old sessions the same way.

Kickoff should confirm the cause with an old-schema client test before choosing the fix (allow additional properties on output objects, or version the tool name on a breaking change).
