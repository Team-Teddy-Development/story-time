## Story
As a maintainer, I want one port of JavaScript Number(string), so that every native command coerces numbers the same way.

## Acceptance Criteria
- [x] Given numeric strings such as 0x10, 1e3, -0, .5, whitespace, and Infinity, when native stats, set, and new coerce them, then each calls one shared function and matches Node, verified by a native/story-push unit test table captured from Node

## Notes
Source: ST-050 (PR #174) report. `stats::number` and `new_story::js_number` both port JavaScript Number(string).

## Evidence
- Red 70d08ac: `number_of_a_string_matches_node` ran both old copies (`stats::number`, `new_story::js_number`) against a 99-input table captured from Node 24 and failed with 6 mismatches, for example `0x200000000000011` where Node gives 144115188075855900 and native gave 1.4411518807585587e17 (digit-by-digit rounding past 2^53).
- Green ac3c7e3: `js_number::string_to_number` is the one port; radix literals are read as exact bits and rounded once (ties to even). stats, set, new, rank, judge, lenient_story, toml_subset, and next_id call it; both copies are deleted and no `parse::<f64>` remains outside it.
- The table covers 0x10, 1e3, -0, .5, the JS whitespace set (and U+0085, U+180E, U+200B as NaN), '', Infinity forms, 1_000, partial literals, -0x10, and exponent extremes; `string_to_number_matches_node` passes.
- Real backlog copies: stats, rank, set (4 fields), and new for 37 values, 296 runs compared with Node, 0 differing; the pre-change binary differed on 15 (the long radix literals).
- Checks: `cargo fmt --check` ok; `cargo clippy --locked --all-targets -- -D warnings` ok; `cargo test --locked` 315 passed, 0 failed; `npm test` 461/461; `scripts/story-policy.rs` 12 passed; `test/story-policy-contract.rs` 11 passed.
