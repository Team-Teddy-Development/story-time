## Story
As a story-time maintainer, I want story push to stop a tracker CLI call that hangs, so that a stuck gh or az process does not block push forever.

## Acceptance Criteria
- [x] Given a tracker CLI that never exits, when story push calls it, then push stops it after a bounded timeout and reports a timeout error naming the command, verified by a native/story-push test with a stub CLI

## Out of Scope
Retrying a timed-out call.

## Notes
Source: ST-038 review. native/story-push/src/gateway.rs:67 (Cli::run) calls wait_with_output with no time limit for gh and az. Affected command: story push for GitHub and ADO.

## Test Plan
Red: a stub CLI that sleeps forever; assert push returns a timeout error within the bound. Verify with cargo test --locked in native/story-push.

## Evidence
- Red 467a14d: `gateway::tests::a_tracker_cli_that_never_exits_is_stopped_with_a_timeout_naming_the_command` hung until an outer `timeout 300` killed it (exit 143).
- Green ec79276: `Cli::run` drains stdout and stderr and writes stdin on threads, polls `try_wait` until `Cli.timeout` (120 s in production), then kills and reaps the child. Error: "Tracker CLI `gh label create` timed out after 1s and was stopped." The test passes in 1.44 s and checks that the token is not in the error.
