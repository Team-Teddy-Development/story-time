## Story
As an agent adopting an existing project, I want adopted stories to land in <PREFIX>-<digits>.md files, so that list, lint, stats, and plan see every story that adopt accepted.

## Acceptance Criteria
- [x] Given a project whose stories live in non-ID files such as work/old-1.md, when story adopt previews and applies the adoption, then each adopted story is proposed and written as <PREFIX>-<digits>.md, or adopt refuses with a diagnostic naming the file, and afterwards story list shows every adopted story, verified by a native/story-push test

## Notes
Source: ST-102 (PR #236) agent report, checked by the coordinator. native/story-push/tests/adoption_contract.rs:519 adopts work/old-1.md (id PAY-001); ST-102 made list, lint, stats and plan read only <PREFIX>-<digits>.md, so after such an adoption those commands do not see the story. story adopt apply exists (ST-023). The adopt preview inventory rule from ST-102 stays: preview still reports every file.

Apply, verify and rollback recompute preview, so no plan can approve such a backlog. Preview still lists every file.
- The new test checks the conflict for exactly `["work/PAY-003.md", "work/old-1.md"]`, empty `allowed_writes`, and all 3 files in the inventory. It checks that apply exits 2 and leaves the repository unchanged. - Existing tests: only fixture file names changed, to `PAY-00N.md`, where a test expected success or `already_adopted`. No assertion's meaning changed. One lost case: a non-ASCII story name that sorted as a story. `docs/adoption-preview/README.md` describes the new conflict.
