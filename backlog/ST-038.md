## Story
As a story-time maintainer, I want a push whose create request timed out to find the issue it may have created, so that a retry does not leave a duplicate issue.

## Acceptance Criteria
- [ ] Given a create request that times out after the tracker made the issue, when story push runs again, then it links the story to that issue and creates no second issue, verified by a native/story-push test with a fake tracker
- [ ] Given a create request that timed out before the tracker made the issue, when story push runs again, then it creates exactly one issue

## Out of Scope
Label locking (ST-039). Reconciliation for other operations than create.
