## Story
As a pull request author, I want story check-pr to report each finding of each named story in one run, so that I can correct the pull request in one pass

## Acceptance Criteria
- [ ] Given a pull request body 'Stories: ST-001 (#24)' where ST-001 is in-progress with one unticked criterion and #24 is a pull request, when `story check-pr --mode fail` runs, then the output has the finding '#24: is a pull request' and the finding that ST-001 is in-progress with 1 unticked criteria, and the command exits 1
- [ ] Given the same body where the lookup of #24 fails, when `story check-pr` runs, then the output has the lookup finding and the acceptance finding for ST-001
- [ ] Given a reference whose story ID has no card, when `story check-pr` runs, then the output has one finding for the missing card and no acceptance finding for it

## Notes
- Source: EGM drift report on `docs/designs/merge-sync-design.md`, run 2026-11-16 as the trial for a design-deviation brief. Finding DR-14. A second code read at `f3a9dbd` confirmed it. No test was run; write the failing test first.
- Design: `docs/designs/merge-sync-design.md` line 702: "Every finding is reported. The check does not stop at the first one."
- Code: rules 2 and 3 are skipped for a reference that has a rule 1 finding (`if r.partial || !linked { continue; }`, `native/story-push/src/check_pr.rs:229`). A valid card whose `(#N)` is a pull request, or whose issue lookup failed, gets no acceptance finding until the link is corrected.
- If the owner prefers the present behavior, amend design line 702 to say that link findings suppress rules 2 and 3 for that reference, and close this story with that amendment.
