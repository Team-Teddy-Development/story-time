## Story
As a story-time user, I want story-install to build the release I asked for, so that the installed story binary always matches that release.

## Acceptance Criteria
- [x] Given CARGO_TARGET_DIR names a directory that already holds a build of an older release, when story-install installs a newer release, then cargo builds it in a target directory that did not exist before the install and is removed after it, verified by a native/story-push test with a fake cargo in tests/release_install.rs

## Notes
Cause reproduced on 2026-11-14 with a two-file crate: cargo install --path A (prints 'release A') with CARGO_TARGET_DIR=T, then cargo install --path B (prints 'release B', files touched one hour older) with the same T installed a binary that printed 'release A'; the same install with --target-dir set to a new directory printed 'release B'.
Source: ST-011 acceptance on 2026-11-14. With CARGO_TARGET_DIR=~/.cache/accept65-target set, story-install for release cdb3a1d printed 'Finished release in 0.21s' and installed the stale f4953ba binary (7126416 bytes, no --graph). Cause: cargo install honors an inherited CARGO_TARGET_DIR (and a cargo config target-dir), and the exported release files carry the commit time as mtime (15:26:17), older than the previous build's artifact (15:27:44), so cargo treated the old build as fresh. Fix: pass --target-dir with a new temporary directory per install and remove it afterwards.

## Evidence
- Criterion 1: `tests/release_install.rs` `each_install_builds_in_a_fresh_target_directory_that_is_removed_afterwards` sets `CARGO_TARGET_DIR` to an existing shared directory and records what the fake `cargo` receives. Cargo gets a `--target-dir` that is not the shared directory and did not exist before the call, the directory is gone after the install, and the binary comes from the requested release.
- Red: cargo built in the inherited shared directory (`.../shared-target existed`, commit 7ed9f05). Green: `Step::Build` passes `--target-dir` with a new temporary directory and removes it after cargo exits, also on failure (commit 6a736f9).
