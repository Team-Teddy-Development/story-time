## Story
As a supervised coordinator, I want Story Time to rebind only the recoverable reservation I inspected, so that an absent or changed reservation cannot turn a recovery request into fresh admission. Keep manual next, fresh-only dispatch, tracker settings, and acceptance behavior unchanged. Use a native Rust assignment contract test with the old owner terminated and a separate caller consuming and releasing the reservation before the recovery request.

## Acceptance Criteria
- [ ] Given a recoverable native claim with the expected old owner, story, worktree and branch, when a supervised recovery command names that claim and a live replacement owner, then the native ledger transfers the same reservation without increasing WIP and invalidates the former token.
- [ ] Given that the expected recoverable claim is absent or differs in owner, story, worktree, branch or recovery state, when a supervised recovery command runs, then it returns a typed refusal without admitting a new claim or modifying any recorded reservation.

## Test Plan

Branch: `feat/ST-171-exact-recovery`. The existing native reservation is kickoff authority.

Seams: native assignment CLI, Git worktree and branch identity, Linux process
identity and liveness, and the existing locked assignment ledger. Keep manual
`next`, fresh-only dispatch, tracker settings, and acceptance behavior unchanged.

1. AC1: `exact_recover_rotates_once_under_contention` verifies one transfer, unchanged WIP, and rejection of the former token.
2. AC2: `exact_recover_refuses_changed_or_missing_predecessor_without_writes` verifies typed refusal and identical ledger bytes, including after another caller consumes and releases the reservation.
3. AC2: `exact_recover_preserves_unrelated_dead_claim_and_rechecks_eligibility` verifies that recovery does not reconcile unrelated claims and refuses ineligible recovery.
4. Run `cargo test --locked --manifest-path native/story-push/Cargo.toml --test assignment_contract`. Verify `story assignment recover --help` with the built native binary.
