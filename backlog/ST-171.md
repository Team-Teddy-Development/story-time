## Story
As a supervised coordinator, I want Story Time to rebind only the recoverable reservation I inspected, so that an absent or changed reservation cannot turn a recovery request into fresh admission. Keep manual next, fresh-only dispatch, tracker settings, and acceptance behavior unchanged. Use a native Rust assignment contract test with the old owner terminated and a separate caller consuming and releasing the reservation before the recovery request.

## Acceptance Criteria
- [ ] Given a recoverable native claim with the expected old owner, story, worktree and branch, when a supervised recovery command names that claim and a live replacement owner, then the native ledger transfers the same reservation without increasing WIP and invalidates the former token.
- [ ] Given that the expected recoverable claim is absent or differs in owner, story, worktree, branch or recovery state, when a supervised recovery command runs, then it returns a typed refusal without admitting a new claim or modifying any recorded reservation.
