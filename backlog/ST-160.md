## Story
As the owner, I want the hosted story-time server to start with the token of the Gitea bot user from Vault, so that it reads private Gitea repositories and is prepared for Gitea writes (ST-149) and comments (ST-150).

## Acceptance Criteria
- [x] Given the Vault entry global/infra.story-time.gitea-token and the deployment flag --gitea-token-file, when the pod starts, then story_repos on the live server shows the Gitea repository xanthos as ready, and the token is in no log line of the pod and no tool result
- [x] Given the registry entries cartographer-core and cartographer-web of the org cartographer, when the pod starts with the bot token, then story_repos on the live server shows both as ready, and story_list returns the stories of each

## Out of Scope
- Writes and pull requests on Gitea (ST-149). Comments on Gitea (ST-150).
- A Gitea repository in the registry other than xanthos, cartographer-core, and cartographer-web.

## Notes
Source: owner request on 2026-11-16 ("can you use my gitea token to configure what you need").

Done on the Gitea with the owner token: team `story-time-bot` (id 14) in the org `team-teddy`, write on code, issues, and pulls, with only the repository `xanthos`; the user `story-time-bot` is its member; the bot has a token `story-time-mcp` with the scopes `write:repository` and `write:issue`. The token and the bot password are in mode-600 files under `~/.config/story-time/` on the owner machine.

No private Gitea repository has story-time settings on 2026-11-16 (119 repositories examined). The check thus uses `xanthos`: Gitea refuses a wrong token on a public repository also, so `ready` shows that Gitea accepts the token.

Changes are in coffee-apps: `scripts/provision-story-time-secrets.sh` (a mode that writes only the Gitea token), `k8s/story-time/20-externalsecret.yaml`, `k8s/story-time/30-deployment.yaml`. Order: the script change merges, the owner runs the script, then the ExternalSecret and the deployment change merge. The other order stops the start of the pod, because the token file does not exist.

Scope change on 2026-11-16: the owner said that the bot must also be in the org `cartographer`. Team `story-time-bot` (id 15) of that org has write on `cartographer-core` (prefix CRT, 492 backlog files, 160 MiB) and `cartographer-web` (prefix CRTUI). A local run of image `eae1e7a-amd64` with the bot token returned 24 stories for `cartographer-web` and 60 for `xanthos`; `cartographer-core` gave no answer in 120 seconds on an emulated CPU, so its check is on the live server.

Owner handoff: an agent cannot write to Vault. The owner runs the script.

## Evidence
Verified on 2026-11-16 on `https://storytime.teamteddy.net/mcp`, pod `story-time-6b6bf6f5b9-rd7ll`, image `eae1e7a-amd64`, coffee-apps `d8eb786`.

- Criterion 1: the owner ran the script with `GITEA_ONLY=1`; it printed `1 Vault entry written`. The Secret `story-time-credentials` has the key `gitea-token`. The deployment has `--gitea-token-file`. `story_repos` shows `xanthos` as `gitea`, `ready`, commit `d29f39e`; `story_list` returns 60 stories. The bot token is in 0 of the 10 log lines of the `story` container and in no tool result.
- Criterion 2: `story_repos` shows `cartographer-core` (`ready`, commit `d56b916`) and `cartographer-web` (`ready`, commit `ce288e8`), org `cartographer`. `story_list` returns 492 stories for `cartographer-core` and 24 for `cartographer-web`.
- Script: coffee-apps PR 315; `node --test tests/provision-story-time-secrets.test.mjs` gave 6 passed, 0 failed, and the 2 new tests failed on the test-only commit. Deployment, ExternalSecret, and registry: coffee-apps PR 316.
- The 4 GitHub repositories are `ready` on the same pod. Directly after the start, `varsity-core` showed `unavailable` one time ("GitHub did not answer the installation request"); the next call 40 seconds later showed `ready`.
