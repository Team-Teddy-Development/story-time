## Story
As a team lead, I want a pull request check to fail when a story named on its Stories: line is not done and is not marked partial, so that story-accept runs before merge and merged work does not leave story issues open.

## Acceptance Criteria
- [ ] Given a pull request whose Stories: line names ST-001 and backlog/ST-001.md on the head branch has status done and no unticked acceptance criterion, when the story-link check runs, then it passes for ST-001
- [ ] Given STORY_ACCEPTANCE=fail and a pull request that names ST-002 whose card on the head branch is not done or has an unticked acceptance criterion, and the reference is not marked (partial), when the check runs, then it fails and names ST-002, its status and its unticked criterion count
- [ ] Given a pull request with 'Stories: ST-003 (#14) (partial)', when the check runs, then it passes for ST-003 whatever its status
- [ ] Given a pull request labeled incident, when the check runs, then it passes with the existing reminder to file a bug story
- [ ] Given STORY_ACCEPTANCE=fail and a pull request body with 'Closes #12' (or close, fix, resolve in any tense) where #12 is the issue of a named story or carries the story label, when the check runs, then it fails and names #12; and given the same keyword for an issue that is not a story issue, then it passes
- [ ] Given STORY_ACCEPTANCE is warn or unset, when the acceptance or closing-keyword rule finds a problem, then the check prints a ::warning:: line naming it and exits 0, while the existing link rules still fail

## Notes
- Design: `docs/designs/merge-sync-design.md` (decisions R1, Q3, Q4). The check lives in `scripts/story-policy.rs`; the mode comes from the workflow variable `STORY_ACCEPTANCE`, and the playbook template ships `warn`.
- Scope grew from 4 to 6 criteria after the design; the size 3 estimate is kept as recorded, not re-estimated.
