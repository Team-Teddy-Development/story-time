## Story
As a team lead, I want a pull request check (`story check-pr`, run by the story-link workflow in every repository that adopts the template) to fail when a story named on its Stories: line is not done and is not marked partial, so that story-accept runs before merge and merged work does not leave story issues open.

## Acceptance Criteria
- [ ] Given a pull request whose Stories: line names ST-001 and backlog/ST-001.md on the pull request merge ref has status done and no unticked acceptance criterion, when the story-link check runs, then it passes for ST-001
- [ ] Given STORY_ACCEPTANCE=fail and a pull request that names ST-002 whose card on the pull request merge ref is not done or has an unticked acceptance criterion, and the reference is not marked (partial), when the check runs, then it fails and names ST-002, its status and its unticked criterion count
- [ ] Given a pull request with 'Stories: ST-003 (#14) (partial)', when the check runs, then it passes for ST-003 whatever its status
- [ ] Given a pull request labeled incident, when the check runs, then it passes with the existing reminder to file a bug story
- [ ] Given STORY_ACCEPTANCE=fail and a pull request body with 'Closes #12' (or close, fix, resolve in any tense) where #12 has a story-type label and no reference that passes the acceptance rule covers it, when the check runs, then it fails and names #12; and given the same keyword for an issue covered by a passing reference, or for an issue that is not a story issue, then it passes
- [ ] Given STORY_ACCEPTANCE is warn or unset, when the acceptance or closing-keyword rule finds a problem, then the check prints a ::warning:: line naming it and exits 0, while the existing link rules still fail

## Notes
- Design: `docs/designs/merge-sync-design.md` (revision 3.3, decisions D1, D4, D7, D8, D9, D14, D15; mode source in Terms and Settings). The check is the Rust verb `story check-pr`, which replaces the body of every story-link workflow; `scripts/story-policy.rs` keeps only story-ids. STORY_ACCEPTANCE is the repository variable `vars.STORY_ACCEPTANCE` (a PR cannot change it); unset means warn. AC1, AC2 and AC5 amended by the design: cards are read from the merge ref, and closing keywords are allowed on passing references.
- Scope grew from 4 to 6 criteria after the design; re-estimated from 3 to 5 at Stage 8 (see Changelog).
