## Story
As a team lead reading cycle times, I want the hook that marks a story done at merge to also record the merge timestamp and whether the Dark Factory or a person built it, so that factory work measured in minutes and human work measured in days are calibrated separately and at the right resolution.

## Source task
2026-11-25, ST-193 refinement. Eric: "estimation and actuals are recorded on PR merge". The merge record exists but holds a date, a PR number and a commit only, so this story extends the same hook rather than adding a second recorder.

## To plan
- The hooks: ess-monorepo `.github/scripts/ci/story-delivered.js` (`markDelivered`, lines 139-142, edits the card in JavaScript) and essentials-core `.github/workflows/story-delivered.yml` (lines 125 and 173, `story set ... status=done`). Both have the PR event, so `merged_at` and the head branch are at hand.
- `built_by` is `factory` when the head branch starts with `factory/` (the Dark Factory's branches), else `person`. ST-193 makes `built_by` a valid attribute; this story adds `delivered_at` (UTC, RFC 3339) to `story set` and lint.
- These hooks live in other repositories. Decide whether this story covers both, or files one story in each.
- Backfill: each delivered story's changelog names its PR (`delivered: PR #N`), so a one-off script can read `merged_at` and the head branch from GitHub and set both fields.

## Acceptance Criteria
- [ ] Given a merged pull request whose head branch starts with factory/ and whose merged_at is 2026-11-22T20:47:56Z, when the merge hook marks its story done, then the story frontmatter carries delivered_at 2026-11-22T20:47:56Z and built_by factory
